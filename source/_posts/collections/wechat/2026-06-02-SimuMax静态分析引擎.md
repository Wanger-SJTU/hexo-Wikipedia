## 快速上手、使用

> SimuMax 是纯 Python 包，零编译依赖，只要 `pip` 就能跑。最精简的安装与第一条 `perf` 命令如下：

```bash
# 1. 建议先建一个独立虚拟环境
python -m venv .venv
source .venv/bin/activate

# 2. 克隆并安装
git clone git@github.com:MooreThreads/SimuMax.git
cd SimuMax
pip install -r requirements.txt
pip install -v -e .

# 3. 跑一个内置的 Llama3-8B、TP1/PP2 perf 例子
cd examples
python perf_llama3_8b_tp1_pp2.py
```

如果你只想"点点鼠标"看效果，仓库还提供了 Streamlit App：

```bash
cd app
bash install.sh
python -m streamlit run streamlit_app.py
```

进一步的玩法分五类：跑现有 perf、加自定义机器配置、加自定义模型、生成 simulator trace / memory snapshot、做策略搜索。各路径的入口分别参考 docs/tutorial.md、docs/system.md、docs/model.md、docs/strategy.md 与 examples/search_strategy_llama3_8b.py。需要提醒的是：<strong>只做 OOM 可行性筛查</strong>时，用 shipped 配置即可；但要做 `perf vs real` 的时间比对，请按 simu_tools/efficency_test 的真实测量流程先填好 `system.miss_efficiency`。

## 一、架构总览与设计哲学

### 1.1 三件套：System、Strategy、Model

> SimuMax 把"分布式训练"这件事拆成正交的三份输入：

- <strong>System</strong>：机器画像。每张卡的算力、显存、各级带宽、算子效率因子。
- <strong>Strategy</strong>：策略画像。`tp/pp/ep/cp/sp/zero/recompute/interleaving/...`，外加 micro-batch 与全局 batch 形状。
- <strong>Model</strong>：模型画像。隐藏维、层数、注意力类型（MHA/GQA/MLA）、专家数、SwiGLU 与否……

三者解耦带来一个直接好处：换机器只动 System、换模型只动 Model、调策略只动 Strategy，再交给一个统一的 `PerfLLM` 完成"假训练"。配置类全部继承自 `Config`，自带 `to_dict / to_json_string / init_from_config_file`，保证 JSON 化与可复现：

```python
# 来源：simumax/core/config.py
@dataclass
class Config:
    def to_dict(self) -> Dict[str, Any]:
        # 把 dataclass 字段与所有 @property 都序列化进去
        output = asdict(self)
        for attr_name in dir(self):
            attr_value = getattr(self.__class__, attr_name, None)
            if isinstance(attr_value, property):
                output[attr_name] = _normalize_jsonable(getattr(self, attr_name))
        return _normalize_jsonable(output)

    @classmethod
    def init_from_config_file(cls, config_file: str):
        return cls.init_from_dict(cls.read_json_file(config_file))
```

注意 `to_dict` 主动把 `@property` 也序列化出去，这意味着像 `dp_size`、`global_batch_size`、`recompute_status` 这些<strong>派生量</strong>在落盘时也会被记录，方便事后对账——这是一个看似不起眼但对"科学实验记录"非常友好的设计。

### 1.2 仓库布局

> `simumax/` 下的关键目录可以用一句话概括：

- `core/`：核心引擎。`config.py`（三套配置）、`perf_llm.py`（顶层 `PerfLLM`）、`base_struct.py / model_struct.py / graph.py`（模拟图与基础数据结构）、`simu_memory.py / simu_runner.py / simu_artifacts.py`（显存时间线与产物）、`trace_export.py / generate_tracing.py`（Chrome trace 导出）。
- `core/transformer/`：把 Transformer 拆成 `dense_module.py`（13 万字符，整套 Dense 层）、`moe_module.py`（6 万字符，整套 MoE）、`language_model.py`（语言模型外壳）、`pipeline_schedule.py`（4 万字符，流水线调度建模）、`function.py / simu_ops.py`（算子级 cost 公式）。
- `tuning/strategy_searcher.py`：网格搜索器，串起 `PerfLLM` 自动试遍候选策略。
- `pp_simu/utils.py`：DualPP 等流水重叠的小型独立解析器，主要用于画图与对照。

`app/`、`examples/`、`simu_tools/`、`configs/` 则分别是 UI、示例、机器测量脚本与公开配置库。整个工程没有 C++ 扩展、没有 CUDA 算子——所有"性能数字"都来自纯 Python 的代数式，这正是 SimuMax 能在普通笔记本上几秒钟跑完一个 1024 卡策略的根本原因。

## 二、配置层：把"能不能跑"先算清楚

### 2.1 StrategyConfig：一份配置 = 一次实验

> `StrategyConfig` 是 SimuMax 中最"沉"的一类配置，几乎所有训练里能动的旋钮都在这里。它的核心字段可以概括成几组：

```python
# 来源：simumax/core/config.py
@dataclass
class StrategyConfig(Config):
    # 形状
    seq_len: Optional[int] = None
    micro_batch_size: Optional[int] = None
    micro_batch_num: Optional[int] = None
    dtype: Optional[int] = 'bf16'
    fp8: Optional[bool] = False

    # 并行
    world_size: Optional[int] = 8
    tp_size: int = 1
    cp_size: int = 1
    pp_size: int = 1
    ep_size: int = 1
    etp_size: int = 1
    cp_comm_type: str = "a2a"
    order_of_paralielism: str = "tp-cp-ep-dp-pp"
    interleaving_size: int = 1                 # VPP
    microbatch_group_size_per_vp_stage: Optional[int] = None

    # 显存优化
    enable_recompute: bool = True
    recompute_granularity: Optional[str] = None    # full_block / attn_only / mlp_only / sdp_only / selective_recompute
    recompute_layer_num: int = 0
    megatron_recompute: bool = False               # Megatron-LM 0.14 风格
    megatron_recompute_modules: Optional[List[str]] = None
    zero_state: int = 1
```

派生属性是这套配置的"杀手锏"。例如：

```python
# 来源：simumax/core/config.py
@property
def shard_size(self):
    return self.pp_size * self.tp_size * self.cp_size

@property
def dp_size(self):
    assert self.world_size % self.shard_size == 0
    return self.world_size // self.shard_size

@property
def global_batch_size(self):
    return self.micro_batch_size * self.micro_batch_num * self.dp_size
```

`dp_size` 不是用户填的，而是**从 `world_size / (pp·tp·cp)` 反推**——一句话就把"并行布局是否自洽"卡死。`sanity_check` 进一步把上百条约束写成可读断言：`seq_len % cp_size == 0`、`world_size % (ep·etp·pp) == 0`、`zero_state ∈ {0,1,2,3}`、`megatron_recompute` 要求 `recompute_granularity == "selective_recompute"`、`interleaving_size > 1` 要求 `pp_size > 1` 且 `microbatch_group_size_per_vp_stage >= pp_size`……这些约束在真实训练里往往要靠 OOM 或 NaN 才能暴露，在 SimuMax 里直接是配置时报错。

### 2.2 重计算策略的语义翻译

> 重计算（recompute）是显存与算力之间最经典的 trade-off。SimuMax 把它拆成 `AttentionRecomputeConfig` 与 `MLPRecomputeConfig` 两个细粒度配置，再用 `parse_attention_recompute / parse_mlp_recompute` 把用户层面的"粒度词"翻译成具体的开关。以注意力侧为例：

```python
# 来源：simumax/core/config.py
def parse_attention_recompute(self, layer_idx):
    if self.recompute_granularity is None or layer_idx >= self.recompute_layer_num:
        return AttentionRecomputeConfig()           # 该层不重计算
    conf = AttentionRecomputeConfig()
    if self.is_megatron_selective_recompute:
        modules = self.megatron_recompute_module_set
        conf.megatron_layernorm   = "layernorm" in modules
        conf.megatron_mla_up_proj = "mla_up_proj" in modules
        # 把 Megatron 的"模块清单"映射成 MLA 内部各子模块的重计算开关
        conf.input_layernorm_recompute = conf.megatron_layernorm
        conf.q_down_recompute = conf.megatron_layernorm
        ...
        return conf
    if self.recompute_granularity == "full_block":
        conf.set_all_status(True)
    elif self.recompute_granularity == "sdp_only":
        conf.core_attn_recompute = True
    ...
    return conf
```

这段代码的价值在于：它把"我打开了选择性重计算"这种<strong>抽象意图</strong>，逐层翻译成"q_down 要不要存激活、rope 要不要重算、core_attn 要不要重计算"等<strong>可被显存模型直接消费的事实</strong>。换言之，SimuMax 的重计算建模并不是"乘个系数"，而是细到 MLA 内部 q_down/q_up/kv_down/kv_up/rope/core_attn 一级。

### 2.3 SystemConfig：一台"虚拟加速器"

> 机器侧最有趣的是把算子时间、显存访问时间、网络通信时间分别建成解析函数。先看算子：

```python
# 来源：simumax/core/config.py
def compute_op_accuracy_time(self, op_name: str, flops: int, shape_desc: str, ...):
    op = self.accelerator.op.get(op_name, None) or self.accelerator.op.get("default")
    # 如果有"按 shape 标定"的精确效率，就用它；否则退回默认 efficient_factor
    if op.accurate_efficient_factor is not None \
       and op.accurate_efficient_factor.get(shape_desc) is not None:
        efficient_factor = op.accurate_efficient_factor[shape_desc]
        self.record_hit_efficiency(op_name, flops, shape_desc, efficient_factor)
    else:
        efficient_factor = op.efficient_factor
        self.record_miss_efficiency(op_name, flops, shape_desc, efficient_factor)
    # 时间 = FLOPs / (峰值算力 × 效率)，单位 ms
    return flops / (op.tflops * 1e12 * efficient_factor) * 1e3
```

这里有两个值得记下来的细节：

- <strong>"命中/未命中"是被显式记录的</strong>。任何一次按 shape 找不到精确效率的查询都会落进 `miss_efficiency`，让用户能很清楚地知道"这次模拟有多少不靠谱的部分"。SimuMax 在 README 里反复强调"做时间精度对比前先把 miss_efficiency 填掉"，背后就是这套机制。
- <strong>算子效率是 per-shape 的</strong>。`accurate_efficient_factor` 是一张 `shape → efficiency` 字典，意味着 SimuMax 不假设 "matmul 永远 70% 效率"，而是按 GEMM 形状查表。这是它能拿到 B200/A100 真实对账精度的关键。

通信侧的 `compute_net_op_time` 则把 `all_reduce / all_gather / reduce_scatter / p2p / all2all` 五种集合通信全部建成 `actual_size = size * scale + offset_chunk` + 带宽折减的解析式，并且为不同语义打补丁：

```python
# 来源：simumax/core/config.py（compute_net_op_time 节选）
if net == "inter_node":
    if op_name == "all2all" and "ep" in comm_stage.lower():
        # k 台机器跨 EP：实际跨机量 = (k-1)/k * actual_size，且单 NIC 限速
        k = max(1, math.ceil(comm_num / self.num_per_node))
        actual_size = (k-1)/k * actual_size
        bw /= self.num_per_node
    if op_name in ["all_reduce", "all_gather", "reduce_scatter"] and is_dense_dp_stage:
        # DP/DP+CP 的跨机带宽随 TP/CP 的"组数"分摊 NIC
        dense_group_multiplicity = strategy.tp_size
        if comm_stage == "dp":
            dense_group_multiplicity *= strategy.cp_size
        bw /= min(self.num_per_node, dense_group_multiplicity)
```

短短几行，把 "EP 跨机只算 (k-1)/k 流量、且单组只能用一张 NIC"、"DP/DP+CP 的 NIC 数被 TP（或 TP·CP）瓜分"这些工程现实写成了代数。能不能精准命中真实带宽，往往就取决于这种细节是否被建对。

最后由 `compute_end2end_time` 决定整体口径：

```python
# 来源：simumax/core/config.py
def compute_end2end_time(self, compute_time, mem_time):
    if self.accelerator.mode == "only_compute":
        return compute_time if compute_time else mem_time
    elif self.accelerator.mode == "roofline":
        return max(compute_time, mem_time)
```

`only_compute` 用于"算子主要被算力卡住"的场景；`roofline` 则强制按 Roofline 取 `max(compute, mem)`。两个模式分别覆盖了"训练时 GEMM 占主导"与"小算子被带宽吃掉"两类典型 case。

### 2.4 ModelConfig：参数量与 FLOPs 的"账本"

> 模型侧除了字段，更核心的是把"参数量、激活参数量、每 token FLOPs"做成属性：

```python
# 来源：simumax/core/config.py
@property
def qkv_proj_elements(self):
    kv_head_num = self.head_num if self.kv_head_num is None else self.kv_head_num
    if self.attention_type == 'mla':
        # MLA：考虑 q_lora / kv_lora 与 qk_pos_emb_head_dim 的低秩拆分
        if self.q_lora_rank is None:
            elements = self.hidden_size * self.head_num * (self.qk_head_dim + self.qk_pos_emb_head_dim)
        else:
            elements  = self.hidden_size * self.q_lora_rank
            elements += self.q_lora_rank * self.head_num * (self.qk_head_dim + self.qk_pos_emb_head_dim)
        elements += self.hidden_size * (self.kv_lora_rank + self.qk_pos_emb_head_dim)
        elements += self.kv_lora_rank * self.head_num * (self.qk_head_dim + self.v_head_dim)
        return elements
    else:
        proj_size = self.head_size * self.head_num + 2 * self.head_size * kv_head_num   # GQA/MQA
        return self.hidden_size * proj_size
```

`flops_per_token` 则同时考虑 MoE 的 `topk` 放大、Shared Expert 的额外宽度、MLA 的 q/k/v 头维差异，以及最后 vocab 投影的"3·2·H·V" 项。把"参数量/FLOPs"这些通常散落在 PPT 上的公式实装进配置类，配合 `dp_size`、`global_batch_size`，就让 MFU 这种衍生指标可以<strong>直接由配置层算出</strong>，不需要等到真训练。

## 三、性能引擎：PerfLLM 与算子图

### 3.1 PerfBase / PerfLLM 的角色

> `simumax/core/perf_llm.py` 是整套引擎的"大脑"。它的核心类 `PerfLLM` 继承自 `PerfBase`，承担了五件事：

- 接收 System / Model / Strategy 三件套，做交叉合法性检查（`_cross_sanity_check`）；
- 按 PP/VPP 切分构造一组 `LLMModel` 实例（每个 PP stage、每个 virtual rank 一份"模型块"，记入 `model_chunk_dict` 与 `vpp_chunk_dict`）；
- 触发 `run_estimate` 跑完整套前向/反向/优化器的"假执行"，沉淀 `compute_info / cost_info / all_gemm_cost_info`；
- 通过 `analysis_cost / analysis_mem` 输出顶层指标（MFU、单卡吞吐、breakdown、峰值显存）；
- 借助 `simulate(out_dir)` 导出 `tracing_logs.json` 以及可选的 `simu_memory_*` 产物，让模拟过程能被 Chrome trace 工具直接打开比对。

被它复用的是一组缓存数据类：

```python
# 来源：simumax/core/perf_llm.py
@dataclass(frozen=True)
class CachedLeafActivationProfile:
    full_name: str
    current_full_module_path: str
    enable_recompute: bool
    recompute_status: str
    offload_inputs: bool
    input_mem_bytes: float
    activation_mem_cache: float
    fwd_peak_mem_no_cache: float
    bwd_peak_mem_no_cache: float

class CachedUnitRuntimeProfile:
    @classmethod
    def from_model_chunk(cls, model_chunk: LLMModel):
        leaf_profiles = []
        for leaf in model_chunk.get_all_leaf_modules():
            act_info = leaf.get_act_info()
            leaf_profiles.append(CachedLeafActivationProfile(...))
        return cls(
            compute_info=model_chunk.get_compute_info(),
            cost_info=model_chunk.get_cost_info(),
            all_gemm_cost_info=model_chunk.get_all_gemm_cost_info(),
            leaf_profiles=leaf_profiles,
            miss_efficiency=deepcopy(getattr(model_chunk.system, "miss_efficiency", {})),
        )
```

注意 `CachedLeafActivationProfile` 是 `frozen=True` 的：每个叶子模块（一个 LayerNorm、一段 GEMM、一段 SDP……）的激活峰值、缓存大小、是否 offload，被冻结成只读快照，方便后续按 PP/VPP 反复拼装而不互相污染。这是 SimuMax 能够支持搜索器一次跑成百上千种策略却不爆栈的关键工程手段。

### 3.2 Dense 与 MoE 模块如何被"代数化"

> `simumax/core/transformer/dense_module.py` 与 `moe_module.py` 是项目里最大的两个文件，把 Transformer 的每个子模块（Linear、LayerNorm、RoPE、SDP、SwiGLU、Router、Permutation、GroupGEMM……）都封装成既能算 FLOPs/显存、又能算时间的"对象"。

`language_model.py` 把这些子模块拼成一个完整的 LLM，并暴露 `get_all_leaf_modules / get_act_info / get_compute_info / get_cost_info` 这一组方法供 `PerfLLM` 调用。这种"算子级解析"和真实框架（PyTorch + TE）的好处是几乎一一对应：

- 对每个 GEMM，按形状去 System 表里查 `efficient_factor`，未命中就入 `miss_efficiency`；
- 对每个 LayerNorm / SwiGLU 等小算子，按显存带宽走 `compute_mem_access_time`；
- 对每次 TP/CP/EP 切分引发的集合通信，按 `compute_net_op_time` 计算；
- 对每段"激活缓存"，根据 recompute / offload 策略决定是否落入显存时间线。

这也是为什么 SimuMax 强调它的语义和 Megatron-LM 0.14 的 `megatron_recompute=true + megatron_recompute_modules` 严格对齐：`parse_attention_recompute / parse_mlp_recompute` 与 `dense_module / moe_module` 之间是一一映射的，可以做"端到端对账"。

### 3.3 流水线调度的建模

> `simumax/core/transformer/pipeline_schedule.py` 负责把"逐 micro-batch 的前向 / 反向 / 权重更新"按 `pp_size`、`interleaving_size`、`microbatch_group_size_per_vp_stage`、`pp_comm_async` 等参数排成时间线，进而算出<strong>气泡（bubble）</strong>与<strong>有效计算占比</strong>。仓库当前主推 1F1B 与 sync-VPP（Preview）。

对"前反向重叠"这种更激进的调度，仓库还在 `simumax/pp_simu/utils.py` 提供了一个独立、可读性极高的解析器，专门用来分析 DualPP / FB-overlap：

```python
# 来源：simumax/pp_simu/utils.py
def duration_dualpp(mbn, pp, F_cost, B_cost, W_cost, FandB_cost, opt_time, stage):
    bubble = (pp-2-stage)*FandB_cost - (pp/2-stage-1)*F_cost \
             - (pp*3/2-3)*W_cost + stage*B_cost
    duration = mbn * (F_cost + B_cost) * 2 \
               - (2*mbn - 3/2*pp + stage + 1) * (F_cost + B_cost - FandB_cost) \
               + bubble + opt_time
    return duration

def mfu_dualpp(mbn, pp, F_cost, B_cost, W_cost, FandB_cost, opt_time, stage,
               Flops_perbatch, default_flops=465):
    opt_time = opt_time * 2   # DualPP 下上/下游各算一次 opt，权重梯度规模翻倍
    dur = duration_dualpp(mbn, pp, F_cost, B_cost, W_cost, FandB_cost, opt_time, stage)
    flops = Flops_perbatch * mbn * 2
    return flops / (dur / 1000) / default_flops / 1e12
```

`cal_FandB_multi_layers` 则进一步把"attn 前向、Dispatch、MLP 反向、Combine、attn 反向"等子事件排成两条时间线（compute / comm），在每一步用 `max(...)` 做硬同步，最终得到 `compute_dur` 与 `comm_dur` 并取 `max` 作为 "F&B 重叠后" 的等效成本。这段代码非常适合作为<strong>理解流水重叠机制的入门样本</strong>：它把图形化的 PP 时序图变成了一个可读、可调试、可绘图的 Python 函数。

### 3.4 显存时间线与 trace 导出

`simu_memory.py / simu_artifacts.py / generate_tracing.py / trace_export.py` 这一组文件负责把"假训练"的产物落地。`simulate(out_dir)` 至少会产出 `tracing_logs.json`（Chrome Trace Viewer 直接打开就是流水图）；如果策略和当前显存时间线路径允许，还会产出：

- `simu_memory_result.json`：每 stage 的显存峰值数据；
- `simu_memory_snapshot.json`：每事件级别的显存快照；
- `simu_memory_viz_snapshot.pickle`：可视化用的 pickle。

对工程师来说，这些产物的真正价值在于<strong>对账</strong>：把 SimuMax 的 trace 与真实 Megatron run 的 trace 摆在一起，可以一眼看出"是哪一段被估短了"或"哪一块激活其实可以被回收"。这也是为什么 README 反复强调"simulator 不是替代真实跑，而是给真实跑提供可解释的参照"。

### 4.2 自动推导 PP/EP/ETP

```python
# 来源：simumax/tuning/strategy_searcher.py
def _comp_cand_parallel_size(self, params: dict):
    tp_size = params["tp_size"]; world_size = params["world_size"]
    layer_num = self.model_config.layer_num
    expert_num = self.model_config.expert_num
    num_per_node = self.system_config.num_per_node

    candidate_list = []
    for pp_size in range(1, world_size // tp_size + 1):
        if layer_num % pp_size != 0:                       # 层数能整除
            continue
        if (world_size // tp_size) % pp_size != 0:         # 卡数能整除
            continue
        if expert_num == 1:                                # 稠密模型
            candidate_list.append({"pp_size": pp_size, "ep_size": 1, "etp_size": 1})
            continue
        # MoE：枚举 etp ∈ {1,2,4,...,num_per_node}，ep ∈ {expert_num 的因子}
        etp_size = 1
        while etp_size <= num_per_node:
            for ep_size in range(1, expert_num + 1):
                if expert_num % ep_size != 0: continue
                if (world_size // pp_size) % etp_size != 0: continue
                if world_size % (pp_size * ep_size * etp_size) != 0: continue
                candidate_list.append(
                    {"pp_size": pp_size, "ep_size": ep_size, "etp_size": etp_size}
                )
            etp_size *= 2
    ...
```

简洁但密度极高：用一段嵌套循环把"PP 必须整除层数、ETP 不超过单节点 GPU 数、`world_size` 必须能被 `pp·ep·etp` 整除、ep 必须整除 expert 数"这一串硬约束直接编码成候选剪枝。一行 `if … continue` 都对应着一条工程现实，避免了<strong>笛卡尔积爆炸</strong>。

### 4.3 网络选择与重计算分桶

`_select_net` 把通信组按"网格前缀积是否超过单节点"决定走 `high_intra_node`（NVLink/MTLink）还是 `inter_node`（IB/RoCE）：

```python
# 来源：simumax/tuning/strategy_searcher.py
def select_impl(name, mesh_order, mesh_size):
    index = mesh_order.index(name)
    if reduce(operator.mul, mesh_size[: index + 1]) <= num_per_node:
        return "high_intra_node"
    return "inter_node"
```

而对"重计算层数"，作者用一个"桶 = 4"的近似采样，避免 `recompute_layer_num` 也成为完全网格的一维：

```python
# 来源：simumax/tuning/strategy_searcher.py
layers = self.model_config.layer_num // params_with_full_shard["pp_size"]
stride = -1
bucket_num = 4
if layers // bucket_num > 1:
    stride = -layers // bucket_num
if params["enable_recompute"]:
    recompute_strategy_list = [
        {**deepcopy(params_with_full_shard), "recompute_layer_num": r}
        for r in range(layers, 0, stride)
    ]
```

### 4.4 主循环：搜 batch、估性能、按 MFU 排序

```python
# 来源：simumax/tuning/strategy_searcher.py
for params in tqdm(combinations):
    try:
        cur_candidate_strategy = StrategyConfig(**params)
        self._select_net(cur_candidate_strategy)
        perf_model = PerfLLM()
        perf_model.configure(strategy_config=cur_candidate_strategy,
                             model_config=self.model_config,
                             system_config=self.system_config)
        max_micro_batch_size = perf_model.search_max_micro_batch_size()
        if max_micro_batch_size < 1:
            print(f"Error: memory is not enough, skip {cur_candidate_strategy.to_dict()}")
            continue
        cur_candidate_strategy.micro_batch_size = max_micro_batch_size
        if cur_candidate_strategy.pp_size > 1:
            cur_candidate_strategy.micro_batch_num = 128   # 暂用大值压低气泡，
                                                           # 真实使用需结合 global_batch 约束
        perf_model._set_strategy_config(cur_candidate_strategy)
        perf_model._cross_sanity_check()
        perf_model.run_estimate()
        cost_result   = perf_model.analysis_cost()
        memory_result = perf_model.analysis_mem()
        first_stage_mem_result = memory_result if memory_result.get("first_stage") is None \
                                 else memory_result.get("first_stage")
        self.strategies.append((cur_candidate_strategy,
                                cost_result.get("mfu"),
                                cost_result.get("throughput_per_accelerator"),
                                cost_result.get("breakdown_result"),
                                first_stage_mem_result.get("peak_cached_mem")))
    except AssertionError as err:
        print(f"Error: {err}, skip {cur_candidate_strategy.to_dict()}")
        continue
self.strategies.sort(key=lambda x: x[1], reverse=True)
```

值得说三点：

- <strong>batch 搜索内嵌</strong>：`search_max_micro_batch_size()` 会在当前并行布局下二分/递增地试出能塞下的最大 micro-batch，再把它写回策略——也就是说，外层网格只决定"拓扑"，micro-batch 由 `PerfLLM` 用显存模型自适应决定；
- <strong>AssertionError 主动捕获</strong>：所有 `sanity_check` 失败都被当作"剪枝"而不是 crash，这让搜索过程对"含有非法组合"的候选鲁棒；
- <strong>排序口径是 MFU</strong>：在 throughput / peak_cached_mem / breakdown 一并保留的同时，按 MFU 降序选 topK。这与公开 README 中强调的"先搜 micro-batch / micro-batch-num，再做小范围 tp/pp sweep"的推荐路径一致。

整个搜索器只有 200 行，但它把"配置约束 + 显存预算 + 通信拓扑 + MFU 评估"四件事拼成了一个<strong>离线 AutoTuner</strong>。对工程师来说，它能在你买空 GPU 队列之前，先告诉你"在这台 B200 上，1024 卡跑 Llama3-405B，最优可能是 `tp8.pp16.ep4` 而不是 `tp4.pp8.ep8`"。

### 5.2 何时该相信 SimuMax、何时应先测

> README 给的边界非常清晰：

- <strong>OOM 可行性筛查</strong>：可以容忍 `miss_efficiency` 不空，直接用 shipped 配置即可；
- **`perf vs simulator` / `perf vs real` 时间对账**：必须先把 `miss_efficiency` 中显眼的算子和通信形状测掉。

换句话说，SimuMax 不试图替你"算准每一个 us"，而是把它的不确定性<strong>显式暴露</strong>给你看。这种"诚实"是它区别于很多"一键算 MFU" 小工具的根本之处。

## 六、设计上的几点取舍与价值

> 回过头看，SimuMax 的工程取舍可以总结成几条：

- <strong>纯 Python、解析式、零 CUDA</strong>：以"可读 + 可改 + 可在 CPU 上秒级运行"换"一定的精度损失"。对策略搜索场景，这是完美 trade-off。
- <strong>三件套解耦</strong>：System / Strategy / Model 各自 JSON 化、可复用，社区可以独立贡献"机器画像"、"模型画像"，而不必动核心引擎。
- <strong>细到子模块的重计算与激活建模</strong>：MLA 的 q_down/q_up/kv_down/kv_up/rope/core_attn 一级开关，让它能逼近 Megatron-LM 0.14 的真实行为。
- <strong>per-shape 效率 + miss/hit 记账</strong>：算力与带宽的不确定性被显式登记，模拟报告自带"可信度元数据"。
- <strong>搜索器只有 200 行</strong>：复杂度被压在 `PerfLLM` 与 `StrategyConfig.sanity_check` 里，外层调度器尽量"短小、可读、可改"。
- <strong>流水重叠有独立解析器</strong>：`pp_simu/utils.py` 把 DualPP/FB-overlap 单独建模并配可视化，便于研究者快速验证调度想法。

对一个仍在 v1.x 阶段的开源项目，它的 Roadmap（更多 PP 调度、compute/comm overlap、offloading、更大规模公开 sweep）方向也清晰指向了"把更多真实工程细节代数化"。

## 结语

> 大模型时代，"训练前先模拟"已经从奢侈品变成必需品。

SimuMax 用一套朴素到极致的工具栈——dataclass + 解析公式 + 几千行 Python——把一件原本需要点亮一个机房才能验证的事，压缩到一台笔记本几秒钟。它没有在公式里偷懒：算子按 shape 查效率、通信按 NIC 数和跨机比例修正、重计算按 MLA 子模块开关、流水线按 1F1B/VPP/DualPP 各自建时序。当你下一次准备按下"训练启动"按钮前，不妨先让 `PerfLLM` 跑一遍——它可能不会替你赢得每一个 MFU 百分点，但几乎一定能替你省下几次"开机即烧钱"的代价。这，就是一个静态分析模型在 LLM 时代最朴素也最坚实的价值。
