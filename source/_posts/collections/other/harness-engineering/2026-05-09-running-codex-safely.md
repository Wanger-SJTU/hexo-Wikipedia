随着 AI 系统变得越来越有能力，它们越来越多地代表用户行事。编码 agent 可以自主审查仓库、运行命令并与开发工具交互。这些是以前需要直接人工执行的任务。

通过 Codex，我们设计了这些能力以及组织安全部署所需的管理控制。安全团队需要方法来治理 agent 的操作方式：它们可以访问什么、何时需要人工批准、它们可以与哪些系统交互，以及有什么可用的遥测来解释它们的行为。

在 OpenAI，我们部署 Codex 有几个明确的目标：让 agent 保持在明确的技术边界内，让开发者快速处理低风险操作，并使高风险操作变得明确。我们还保留原生的 agent 遥测，以便我们可以理解和审计 agent 做了什么。在实践中，这意味着托管配置、受约束执行、网络策略和原生 agent 日志。

## 控制 Codex 的运行方式

我们部署 Codex 有一个简单的原则：它应该在有界限的环境中有生产力，低风险日常操作应该无摩擦，高风险操作应该停止等待审查。

批准和沙箱一起工作。沙箱定义了技术执行边界，包括 Codex 可以写入哪里、它是否可以访问网络、以及哪些路径受到保护。批准策略决定 Codex 何时必须请求执行某个操作，例如当它需要做沙箱之外的事情时。用户可以一次性批准该操作，或在该会话中批准该类型的操作。

对于常规批准请求，我们使用 Auto-review 模式，这是一个开启后可以自动批准某些类型请求的功能，以减少用户停止和批准 Codex 操作的频率。Codex 将计划的操作和最近上下文发送给 auto-approval subagent，后者可以自动批准低风险操作，而不是打断用户。这让 Codex 在常规工作上继续前进，同时在高风险或具有意外后果的操作上停下来。

我们不运行开放式出口访问的 Codex。我们的托管网络策略允许预期目的地，阻止我们不希望 Codex 到达的目的地，并对陌生域名要求批准。这让 Codex 完成常见的、已知良好的工作流，而不给予它广泛的网络访问。

我们还管理 Codex 的认证方式。CLI 和 MCP OAuth 凭证存储在安全 OS keyring 中，登录通过 ChatGPT 强制执行，访问被绑定到我们的 ChatGPT 企业工作区。这使 Codex 使用与我们的工作区级控制挂钩，并使 Codex 活动在我们的企业工作区的 ChatGPT 合规日志平台中可用。

我们使用规则让 Codex 不要将每个 shell 命令视为同等安全。工程师在日常开发中使用的常见良性命令允许在沙箱外无批准运行，特定危险命令可以阻止或需要批准。这让 Codex 在普通工程任务中快速前进，同时对我们不希望在沙箱外运行的模式强制审查或阻止。

我们通过云托管要求、macOS 托管首选项和本地要求文件的组合来应用这种姿态。要求是管理员强制执行的控制，用户无法覆盖。macOS 托管首选项和本地要求文件允许我们保持一致的基础，同时按团队、用户组或环境测试不同配置。这些配置适用于本地 Codex 界面，包括桌面应用、CLI 和 IDE 扩展。

## 原生 agent 遥测和审计跟踪

控制只是工作的一半。一旦 agent 部署，安全团队需要了解这些 agent 在做什么以及为什么。传统安全日志在查看 Codex 执行的操作时仍然有用，但它们主要回答发生了什么：进程启动、文件更改、尝试网络连接。防御者仍然需要弄清楚 Codex 为什么做了某件事，或者用户的意图是什么。

Codex 可以为安全团队提供更具 agent 意识的视图。Codex 支持各种 Codex 事件的 OpenTelemetry 日志导出，例如用户 prompts、工具批准决策、工具执行结果、MCP server 使用以及网络代理允许或拒绝事件。Codex 活动日志也可通过 OpenAI 企业和教育客户的合规平台获取。

在 OpenAI，我们将 Codex 日志与我们的 AI 驱动的安全分类 agent 结合使用。当端点警报说 Codex 做了异常操作时，端点安全工具告诉我们发生了可疑事件。Codex 日志帮助解释用户和 agent 周围的上下文。我们的 AI 安全分类 agent 使用 Codex 日志检查原始请求、工具活动、批准决策、工具结果以及任何相关的网络策略决策或阻止。AI 安全分类 agent 将其分析呈现给我们的安全团队进行审查，以区分预期的 agent 行为、无害的错误和真正值得升级的活动。

我们也在操作上使用相同的遥测。我们使用这些日志来了解内部采用如何变化、正在使用哪些工具和 MCP server、网络沙箱阻止或提示的频率，以及推广仍需要在哪里调整。这些 OpenTelemetry 日志可以集中在 SIEM 和合规日志系统中。

## 展望未来

随着 Codex 这样的编码 agent 集成到开发工作流中，安全团队需要专门为管理这一转变而设计的工具。Codex 提供了确保安全采用所需的控制面、配置管理、沙箱和详细的原生 agent 遥测。有了这些能力，安全团队可以更有信心地启用 Codex，平衡开发者生产力与企业安全所需的可见性和控制。
