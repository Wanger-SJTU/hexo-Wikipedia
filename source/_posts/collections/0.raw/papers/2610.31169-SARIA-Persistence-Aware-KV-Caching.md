# SARIA: Persistence-Aware KV Caching with Coordinated DRAM–SSD Reload for LLM Agents

**作者**：Hui Li、Zequn Gong、Qihui Zhou、Xiao Yan、Shumeng Zhang、Zijie Dai、Mingcong Song、Guoping Long、Hongjie Si、James Cheng（香港中文大学、华为、武汉大学、厦门大学）

## 摘要

多轮 LLM agents 通常复用长上下文 prefix，使 key-value（KV）caching 对降低 prefill 延迟至关重要。SSD 为有限的 DRAM 容量提供了低成本扩展，但带来两个关键挑战：急切地（eagerly）持久化所有 KV cache 块会产生大量写入流量并迅速耗尽 SSD 有限的 endurance；而典型 GPU 服务器配备的少量 SSD 限制了聚合重载带宽，使 SSD 上的 KV cache 检索远慢于 DRAM，推高 prefill 延迟。

我们提出 SARIA（Selective Admission and Reload for Inference Acceleration），一个联合管理 DRAM 与 SSD 的 KV caching 系统，通过利用 LLM agents 的会话级时间局部性来减少 SSD 写入并加速 cache 重载。在写路径上，SARIA 利用驱逐与复用历史，选择性地持久化那些复用机会超出 DRAM 驻留期的 KV cache 块，避免对已驻留 DRAM 的 KV cache 做不必要写入。在读路径上，SARIA 在 prefill 之后把选定的 SSD 命中块从 GPU 内存晋升（promote）到 DRAM，使同一会话内的后续复用可从 DRAM 读取，减少 SSD 读流量同时限制 DRAM 争用。一个传输协调器（transfer coordinator）在 SSD 传输活跃时对 DRAM 读取限速，使两条路径都能推进并高效共享 GPU 入口带宽。

我们在 LMCache MP 上实现 SARIA，并使用 TraceLab 和 WEKA 工作负载评估，覆盖 full-attention 与 hybrid-attention 模型。结果表明：相比流行的全量复制缓存（full duplicate caching），SARIA 减少 SSD 写入 57.1–58.9%；相比纯 DRAM 缓存，平均 TTFT 降低 42.3–79.7%。

## 1 引言

Agentic LLM 服务正在把 KV cache 从每请求的临时状态转变为跨越多轮交互的可复用服务状态。系统 prompt、工具 schema、仓库说明和对话历史构成在 agent 会话中反复出现的长 prefix。保留这些 prefix 的 KV cache 可让后续请求避免重复 prefill 计算，降低 TTFT。但 GPU HBM 与主机 DRAM 容量有限且昂贵。SSD 提供更大容量、更低成本的层级：Mooncake、LMCache 等系统已把 KV cache 层级从主机 DRAM 扩展到 SSD；GPUDirect Storage（GDS）等 I/O 技术支持高效的 SSD→GPU 直接传输；近期工作表明 SSD KV caching 可接近 DRAM 性能。但在典型 GPU 服务器上部署 SSD 缓存需解决两个挑战：

**挑战 1：有限的 SSD endurance**。SSD 只能承受有限的累计写入量。现有系统把所有新生成的 KV 块从 DRAM 复制到 SSD（我们称之为 full duplicate caching），写流量随模型 KV 占用与 prefill 吞吐扩展。例如 vLLM 报告 GLM-5.2 在 B300 GPU 上单卡 12,963 prefill tokens/s（8K 输入），相当于每 GPU 约 1,145 MiB/s 的 KV 写入，即 103.7 TB/天——一块 4 TB、1 DWPD 的 SSD 约 70 天即耗尽其五年写入预算。增大 SSD 容量可扩大写入预算，但耐久所需容量远超缓存所需：将缓存从 3M token slots 增至 32M（五年耐久所需）只把命中率从 82.0% 提到 84.8%，按性能收益并不经济。

**挑战 2：有限的 SSD 并行度**。GPU 服务器上的 SSD 数量通常太少，无法匹配 GPU 入口带宽：一块典型 NVMe SSD 用 x4 PCIe 链路，而 GPU 用 x16，同代 PCIe 下至少需要 4 块 x4 SSD 并行才能匹配一块 GPU。AWS p5.48xlarge 配 8 张 H100 + 8 个本地 NVMe，增加盘会占用槽位与 PCIe 资源并提高成本。现有 SSD KV cache 系统采用两条重载路径：一是通过 GDS 直接取入 GPU 内存——绕过 DRAM、不为 SSD 命中创建 DRAM 副本（zero promotion），重复的 SSD 命中始终受 SSD 带宽限制；二是先加载到 DRAM 再传 GPU——保留所有重载块（full promotion），但晋升块与活跃会话争抢 DRAM。

**SARIA**：核心思想是用会话复用历史引导 SSD 持久化与晋升。面对有限 endurance，SARIA 以重复的 DRAM 驱逐作为"该块需要 SSD 持久化"的证据——同一会话内的请求常在块仍在 DRAM 时复用它，但其他会话的争用或长请求间隔可能在复用前将其驱逐，因此被反复驱逐的块在驱逐后仍有高复用潜力。SARIA 还在驱逐前持久化特别热门（按复用计数）的块；用户可通过配置驱逐与复用计数阈值权衡 SSD 写量与缓存覆盖（§4.2）。统一的上下文元数据同时支持 full-attention 与 hybrid-attention 模型，并规划来自 DRAM 与 SSD 的有效 prefix 重载（§4.3）。为应对有限的 SSD 并行度，SARIA 结合直接 GDS 重载与惰性部分晋升：请求经 GDS 重载 SSD 命中块并完成 prefill 后，惰性晋升将部分 SSD 命中块从 HBM 复制到 DRAM，晋升比例的选取使 DRAM 与 SSD 能充分利用 GPU 入口带宽并避免 DRAM 容量竞争（§4.4）。DRAM 与 SSD 并发加载需要仔细协调：DRAM 传输可能耗尽大部分 GPU 入口带宽、留下漫长的仅 SSD 完成尾延迟，SARIA 的协调器在 GDS 活跃时限制 DRAM 传输速率、SSD 传输结束后恢复满速，并利用残余 GPU 入口带宽服务其他请求的 DRAM 重载（§4.5）。

**贡献**：识别出急切持久化导致的 SSD 短寿命与 SSD 并行度不足导致的有限重载带宽两大挑战；设计 Persistence-Aware SSD Admission（利用驱逐与复用历史减少写入）与 GDS 直接重载 + 部分 DRAM 晋升 + 协调多源传输；在 full-attention 与混合模型、不同缓存压力与 SSD 配置下量化其写入-性能权衡。

## 2 背景与挑战

### 2.1 分层 KV Caching

KV caching 允许后续请求恢复缓存 prefix、只 prefill 未匹配的后缀。CachedAttention、Mooncake、LMCache 将 KV cache 从 GPU 内存扩展到主机 DRAM 与 SSD；SSD 重载可经 DRAM 中转或用 SPIN、GDS 等直接 I/O。FlexKV 与 Dynamo KVBM 的 GDS 路径不保留 DRAM 副本（zero promotion）；HiCache 的 DRAM 中转路径支持 full promotion；Tutti 表明在足够 SSD 并行度与优化 I/O 下 SSD 缓存可接近 DRAM 性能。不同模型架构对访问与复用要求不同：full-attention（FA）KV 可在任意匹配的 prefix 边界复用；FA 与循环层（如 linear attention, LA）结合的混合模型也需要该边界的 checkpoint，因为后续状态一般无法回滚——FA 块可服务终止于不同位置的 prefix 命中，而循环 checkpoint 只在计算恢复到其特定边界时被访问。

### 2.2 Endurance 约束的 SSD 供给

NAND flash 反复 program/erase 会磨损，限制写入 endurance，厂商以 TBW 或 DWPD 评级。考虑五年 1 DWPD 的标准耐久 TLC SSD：C TB 的盘有 1,825C TB 的 host 写入预算，持续的 B GB/s 写流将在 1,825C/(86.4B) 天内耗尽它。 sustaining 每 GPU B GB/s 五年需要至少 C_min = 86.4B TB 聚合 SSD 容量。Table 1 估计：GLM-5.2 每 H200 产生 16.4 MiB/s KV 写入，4TB SSD 寿命仅 181 天，五年需 445 TB 容量；Qwen3-235B 为 34.7 MiB/s / 383 天 / 210 TB。Full duplicate caching 因耐久所需的 SSD 容量可远超有效缓存所需。

### 2.3 有限的 SSD 重载带宽

主流 GPU 服务器常配 8 GPU + 8 本地 NVMe；增加盘受槽位与 PCIe 限制，长 prefix 重载可能持续受带宽约束。

## 3 观察与动机

### 3.1 缓存压力下的 KV 复用

会话内请求常在短时间内复用重叠上下文，只要 KV cache 仍驻留 DRAM 就可由 DRAM 服务大部分复用。为量化缓存压力的影响，我们在三种负载设置（会话起始分布在 12h/4h/2h 窗口，对应较低/中等/较高负载）下模拟 full duplicate caching：GLM-5.2 用 100 GB DRAM（约 220 万 token slots，按 FP8 KV 占用），SSD 容量充足不驱逐，SSD 读取不回填 DRAM。分析 350 个重建的 TraceLab 会话（平均每会话 18.4 个请求、每请求 83.7K prompt tokens）。为不扭曲多轮到达模式，保留每会话的请求序列与请求间隔，只变化会话起始时间。

Figure 3(a)：较低负载下 79.3% 的缓存命中请求的全部命中块来自 DRAM，DRAM 供给总缓存读字节的 76.9%；较高负载下降至 52.4% 与 44.2%。Figure 3(b)：较低负载下 82.5% 的 SSD 写入在回放结束前未收到任何后续 SSD 读；4 小时设置降为 65.0%，2 小时设置降为 44.3%。

**观察 1**：会话级时间局部性使较低缓存压力下 DRAM 可服务大部分 KV 复用，许多 SSD 写入未被使用；随缓存压力增大，更多复用超出 DRAM 驻留期、愈发依赖 SSD 持久化。

### 3.2 Full Promotion 下的 DRAM 竞争

SSD 驻留块经 GDS 重载后在 DRAM 保留副本可加速后续复用，但晋升副本消耗 DRAM 容量并与活跃会话竞争。我们比较 zero、half、full promotion（GDS 带宽设为 GPU 入口带宽一半，传输时间在 DRAM/SSD 理想重叠下测量；half promotion 固定 50% DRAM 覆盖目标）。结果（Figure 4）：较低负载下 half 与 full promotion 均值约 78 ms，P5 分别 226/229 ms；负载升高差距拉大——中等负载下 half 将 P5 从 256 降到 244 ms；较高负载下 P10 从 252 降到 231 ms、P5 从 310 降到 277 ms、均值 81→78 ms。副本还加剧 DRAM 替换：2 小时回放中累计 DRAM 块驱逐从 zero 的 59,589 升至 half 的 97,097、full 的 175,314。

**观察 2**：会话级时间局部性使 DRAM 晋升有益，但激进晋升加剧缓存压力下的 DRAM 竞争；降低晋升比例可缓解竞争并改善尾传输延迟。

## 4 SARIA

### 4.1 系统概览

SARIA 管理分层 DRAM–SSD KV cache。新块先放入 DRAM；Persistence-Aware SSD Admission（§4.2）用积累的复用与驱逐历史决定哪些块应持久化到 SSD；统一上下文元数据跨 DRAM 驻留保留历史并跟踪每块位置，查找时构造有序重载计划（§4.3）；prefill 完成后 Lazy Partial DRAM Promotion 将选定 SSD 命中块从 HBM 复制到 DRAM（§4.4）；传输协调器按重载计划对 DRAM 读取与 GDS 传输协同限速（§4.5）。

### 4.2 持久化感知 SSD 准入

正常负载下 DRAM 供给大部分缓存复用，许多急切持久化的副本毫无读取收益（参考回放中 82.5% 的写入无后续 SSD 读）。自然信号是请求热度，但对以会话私有为主的 agent 上下文，累计访问计数主要描述会话内复用，不反映其他会话的 DRAM 竞争；也不区分短突发内集中复用与长间隔分散复用。Figure 6：复用 16–31 次的块中，收到至少一次 SSD 读的比例从较低负载的 29.0% 升到较高负载的 60.2%；即使复用 ≥64 次的块，12 小时设置下仍有 44.5% 从未被 SSD 读。请求热度单独不足以刻画缓存竞争下的持久化需求。

SARIA 用重复 DRAM 驱逐作为持久化需求的实用信号：块的第一次驱逐说明 DRAM 已无法在当前负载下保留它；若它随后被复用并再次到达驱逐边界，其历史包含 DRAM 无法覆盖的复用。这种跨驻留（cross-residency）历史无需显式估计复用间隔或 DRAM 保留时间就融入了竞争因素。另保留请求复用阈值让特别热门块在重复驱逐前即可持久化。对每个逻辑上下文块 b 跨驻留跟踪 DRAM 驱逐计数 E_b 与请求复用计数 R_b，满足下式即有资格持久化：

admit(b) = [E_b ≥ θ_E] ∨ [R_b ≥ θ_R]　（式 1）

两个阈值暴露写量与覆盖的权衡。**写入调度**：合格未持久化块到达 DRAM 驱逐路径时，先写入 SSD 再回收 DRAM（DRAM 副本作为写源直至传输完成）；复用路径也可在 R_b 达到 θ_R 时提前发起异步写——Prewrite 用 E_b + 1 评估候选，让"下次驱逐即合格"的块仍在 DRAM 时就开始写入，把 SSD 流量移出 DRAM 回收的关键路径。

### 4.3 统一元数据与重载规划

对物理块独立做准入可能让混合模型缺少恢复上下文 prefix 所需的 KV cache：位置 c 之前的 FA KV 在后续请求延伸超出 c 时仍然有用，而 c 处的 LA 循环状态只在该特定边界作为 checkpoint 复用；两组件即使代表同一上下文位置也可能积累不同的访问与驱逐历史。独立准入可能只持久化了 FA 块而缺少复用该 prefix 所需的 LA checkpoint。选择性持久化与独立替换还会把可复用块分散在 DRAM 与 SSD，产生 DRAM–SSD–DRAM 交错来源。

SARIA 按 radix tree 组织上下文元数据（沿用 HiCache 与 Unified Radix Cache 的 prefix 组织）：每个节点代表块对齐的上下文 prefix，将其物理 cache 对象与共享的复用/驱逐计数及逐对象存储位置关联。准入在该上下文粒度评估并应用到关联对象，checkpoint 可共享其上下文积累的准入证据；元数据跨驱逐保留，以滑动时间窗口管理。查找时缓存管理器把 DRAM 与 SSD 中可用的 KV cache 合成统一重载计划（Figure 7(b)），识别可复用 prefix 并为每个所需对象选择 DRAM 或 SSD 来源，即使命中在两层间交替也保持块顺序。

### 4.4 惰性部分 DRAM 晋升

请求经 GDS 从 SSD 重载 KV cache 并完成 prefill 后，SARIA 将选定的 SSD 命中块从 HBM 复制到 DRAM（Figure 8），若副本保持驻留，后续请求可从 DRAM 复用。沿两个维度限制晋升带来的 DRAM 竞争：第一，不为容纳晋升副本而驱逐最近复用的块——候选块 b 只有在 t_now − t_b,reuse ≥ P_τ（新近性阈值）时才可被晋升驱逐，符合条件的候选少时晋升量随之减少甚至为零。第二，按 DRAM 与 SSD 相对带宽限定目标晋升量。设重载总字节 V、GDS 持续带宽 B_disk、共享 GPU 入口带宽 B_GPU（B_disk < B_GPU），假设 GDS 活跃期间 DRAM 能供给剩余带宽，DRAM 应服务的目标比例为：

r* = 1 − B_disk / B_GPU　（式 2）

这样两路同时完成并充分利用 GPU 入口，重载时间为 V / B_GPU；超出该比例的晋升只消耗 DRAM 容量而不缩短重载。若请求当前从 DRAM 重载 D_0 块、从 SSD 重载 S_0 块，目标额外晋升的 SSD 块数为：

P_target = max(0, r(D_0 + S_0) − D_0)　（式 3）

已在 DRAM 的块计入目标；实际晋升量还受上述驱逐候选过滤约束。

### 4.5 协调多源重载

简单启用重叠并不能保证并发推进：初始 DRAM 突发期间 SSD 流量很低，DRAM 流量消退后 SSD 才达到持续速率，留下仅 SSD 的完成尾。SARIA 的协调器在 GDS 工作活跃时对 DRAM 流量限速：按每请求的重载计划跟踪剩余 DRAM 与 SSD 工作量，在并发流量间共享每 GPU 入口预算。设独立 DRAM 重载带宽 B_DRAM，SSD 工作可运行时将聚合 DRAM 速率限制为：

pace_B_DRAM = min(B_DRAM, B_GPU − B_disk)　（式 4）

为 GDS 保留足够入口带宽维持 B_disk；协调器通过限制单次 DRAM 提交并按可用预算间隔发送来执行。无 SSD 工作时 DRAM 恢复不限速。Figure 9：请求 A 完成 DRAM 部分后，残余入口推进仅 DRAM 的请求 B，同时 A 继续读 SSD；A 的 SSD 传输完成后 B 用满速 DRAM；请求 C 的 DRAM 与 SSD 传输重叠，SSD 部分完成后剩余 DRAM 工作也全速运行。协调器依赖对 DRAM、GDS、GPU 入口带宽的估计；当 GDS 单独就能饱和 GPU 入口时协调无益且开销可能降低性能。

## 5 评估

### 5.1 实验设置

**工作负载**：TraceLab 的 Claude Code 与 Codex coding-agent trace，以及 SemiAnalysis WekaTrace（WEKA）的 Claude Code trace。两者均不含 prompt 内容，故重建保持记录复用的确定性合成输入。过滤截断后：TraceLab 350 会话 / 6,431 请求 / 538.26M prompt tokens；WEKA 170 会话 / 5,995 请求 / 930.25M prompt tokens；最小 prefill tokens（无限容量缓存下仍需计算的 prompt token）分别为 36.55M 与 26.43M。上下文上限 450K tokens、24 小时截断，会话内平均请求间隔 112.1 / 111.1 s。默认 12 小时会话起始窗口、Gamma 分布间隔（k=1）；默认允许 4 个在途请求；逻辑回放时钟按 6,500 prefill tokens/s 推进，延迟用墙上时间。

**Baselines 与缓存配置**：在 LMCache MP 上实现 SARIA，集成 Phoenix 作为 GDS 后端（含三项优化：GDS 控制操作异步流水线化；HBM 卸载时 DRAM 分配失败则驱逐重试；参照 Tutti 分离 SSD 读写执行）。两个 LMCache-based baseline：GDS-only（KV 仅存 SSD）；LMCache+（full duplicate DRAM–SSD 缓存、逐对象元数据、串行层加载、无晋升）。另有 SARIA 的 DRAM-only 与 Full Duplicate（关闭选择性准入）变体。

**模型与平台**：主平台为 RTX PRO 6000 Blackwell（96 GB GDDR7）+ 双 AMD EPYC 9534 + 256 GB 主存 + 两块 1.92 TB PCIe 5.0 NVMe；评估 Qwen3-8B（36 个 FA 层）与 Qwen3.5-9B（8 FA + 24 GDN 层）的 BF16 checkpoint。准入与元数据实验用 A30（24 GB）+ 单 NVMe 的次平台，构造缩减配置 Qwen3-1.7B（20 FA 层）与 Qwen3.5-5.6B（5 FA + 15 GDN 层），随机初始化 BF16 权重执行真实前向。

**配置**：DRAM 1M tokens、SSD 10M tokens；外部块 512 tokens（dense）/ 1,024 tokens（hybrid）；GDN checkpoint 每 16,384 tokens 保留。默认晋升比例 r=0.4；共享入口/GDS/DRAM 带宽估计 48/20/48 GB/s（A30 为 24/10/24 GB/s）；晋升新近性阈值 P_τ=60 s（回放时钟）。

**指标**：TTFT（提交到首个输出 token 的墙上时间）；cache-transfer time（首次外部缓存查找至 vLLM 观察到加载完成，不含 prefill 计算）；CHAR（实际缓存命中块数与无限容量下可达成之比）；归一化 SSD 读写（累计完成负载字节 ÷ 配置的 SSD 缓存容量）。

### 5.2 主要结果

**端到端性能**（Figure 10）：按 1 DWPD SSD、与缓存容量 C 成比例分配 endurance，12 小时窗口与 24 小时截断对应 0.5C 与 C 写入预算（图中阴影带）。WEKA + Qwen3.5-9B：θ_E=3（E3）保持在一日预算内，相对 Full Duplicate（FD）减少写入 78.2%，平均 TTFT 比 FD 高 78.4%，但相对 DRAM-only 仍降低约 94.9%。TraceLab 需要不同阈值：Qwen3.5-9B 上 E3 相对 FD 减少 78.7% 写入但超一日预算 13.3%，平均/P90 TTFT 比 DRAM-only 低 73.7%/72.2%；提高到 E5 满足 12 小时限制，平均/P90 TTFT 仍降 66.5%/63.7%。Qwen3-8B 上 E3 满足一日预算、写入比 FD 少 80.3%，平均/P90 TTFT 相对 DRAM-only 降 27.8%/45.3%。DRAM 辅助重载还减少 SSD 读：FD 相对 LMCache+ 读字节少 27.2%（TraceLab 两模型）与 18.1%（WEKA Qwen3.5-9B）。

**不同压力下的表现**（Figure 11）：固定 100 会话、起始窗口 10–40 分钟（压力递减），准入阈值不变。基于驱逐的准入随压力下降自动减少持久化：窗口从 10 扩到 40 分钟，Qwen3.5-9B / Qwen3-8B 的 SSD 写入减少 28.3% / 23.5%，P25 bad CHAR 改善，且平均 TTFT 波动范围比复用门控准入更窄。固定阈值下，驱逐历史使持久化随负载自适应：高压力下更多块有资格保留，低负载下 DRAM 覆盖更多复用、节省写入。

**消融**（Figure 12，350 会话、full duplicate、单在途请求）：从逐对象元数据 + 串行层加载（Base）出发，累加统一元数据与混合源查找（+Meta）、部分 DRAM 晋升、层重叠、协调器。完整配置相对 Base 平均 TTFT 降 6.4%（Qwen3.5-9B）/ 5.8%（Qwen3-8B），P25 bad 传输时间相对 +Meta 降 31.9% / 26.7%；协调器再分别降 17.8% / 11.0%。

## 5.3 微观实验

**盘准入权衡**（Figure 13，A30）：驱逐阈值 E∈{2,3,4,6}、纯复用阈值 R∈{4,8,16,32,48}、组合（E=2 且 R∈{2,8,24(,48)}）。TraceLab 上相似 P25 bad CHAR 下 R=4 的写入约为 E2 的 1.9×；组合（E=2 ∨ R=2）以更大写成本进一步改善热门上下文覆盖。

**统一元数据与重载规划**（Figure 14，E2 准入）：启用后 Qwen3.5-5.6B / Qwen3-1.7B 平均 TTFT 降 25.4% / 23.5%，两模型 P25 bad CHAR 改善。禁用时损失部分源于 LMCache 的层-prefix 查找无法在切换到 SSD 后用 DRAM-only 块扩展 prefix——选择性准入可产生 DRAM–SSD–DRAM prefix，漏掉最后一段会强制重算已有 KV 块；统一重载规划恢复这些交错命中。

**惰性部分 DRAM 晋升**（Figure 15，full duplicate + 协调重载，扫 r）：Qwen3.5-9B 上 r=0.6 使 SSD 读减少 43.8%、平均传输时间降 17.9%、平均 TTFT 降 3.5%；Qwen3-8B 上 r=0.8 分别为 61.7%、31.6%、9.0%。r 从 0.6 升到 0.8（Qwen3.5-9B）继续减少 SSD 读但不改善延迟，符合 §4.4 的带宽平衡：DRAM 补足 SSD 带宽即可，无需持有全部重载集。

**协调多源重载**（Figure 16，A30，合成单请求重载 135,168 缓存 token、DRAM/SSD 各 9.28125 GiB）：单 SSD 慢盘/快盘配置下，非协调重叠在初始 DRAM 突发期间 SSD 进展很低，与串行加载相比无改进；协调使两源同时推进，完成时间相对串行分别缩短 18.0% 与 20.7%。但双 SSD 条带下协调反而使完成时间增加 15.8%——盘配额几乎不留 DRAM 带宽，协调器开销又阻止 SSD 流量达到配额。协调在 SSD 带宽受限时有效，但其配额须匹配各路径有效带宽。

## 6 相关工作

**KV cache 管理**：SGLang 用 radix tree 组织可复用 prefix；HiCache 用访问计数过滤 HBM→DRAM 备份；Unified Radix Cache 将 prefix 管理扩展到混合注意力模型；Marconi 为循环状态引入 checkpoint 感知缓存；SAECache 用驱逐反馈估计 token 复用价值。这些技术改善内存层级内的缓存组织与准入，但不显式处理 SSD endurance；SARIA 用跨 DRAM 驻留的复用与驱逐历史决定哪些块值得持久化到 SSD。**SSD KV caching**：Mooncake、LMCache、CachedAttention 用主机 DRAM 与 SSD 扩展 KV 缓存；HiCache 经 DRAM 重载并支持 full promotion，FlexKV 与 Dynamo KVBM 用 GDS 直接重载（无晋升）；Tutti 利用 SSD 并行度与优化 I/O 接近 DRAM 性能；Unified KV Pooling 按设备带宽分区 KV cache；HiFC 结合 GDS 与伪 SLC 区域；Strata 与 Swarm 改进存储 I/O 调度与多 SSD 放置。SARIA 面向 SSD endurance 与并行度受限的部署，用部分 DRAM 晋升与协调多源重载降低对带宽受限 SSD 路径的依赖而不造成过度 DRAM 竞争。**SSD 准入与写入 endurance**：Flashield 基于观测读取与更新准入通用 KV 对象；CacheSack、Baleen 优化 flash cache 准入——面向通用存储负载而非 agent 服务的会话级复用结构；SARIA 区分 DRAM 驻留期内已覆盖的复用与跨驻留的复用，重复驱逐与复用构成同时反映会话复用与缓存竞争的准入信号，辅以热门 prefix 的复用阈值。

## 7 结论

SSD KV caching 面临两个实践挑战：过量写入迅速消耗 SSD endurance，有限的 SSD 并行度约束重载带宽。我们提出 SARIA，通过 Persistence-Aware SSD Admission（用复用与驱逐历史避免不必要的 SSD 写入）、Lazy Partial DRAM Promotion（保留选定的 SSD 命中块于 DRAM 供后续复用并限制 DRAM 竞争）、协调多源重载（调度 DRAM 与 GDS 传输高效共享 GPU 入口带宽）应对这些挑战。在 TraceLab 衍生负载与 full-attention / hybrid-attention 模型上，SARIA 相比 full duplicate caching 减少 SSD 写入 57.1–58.9%，相比 DRAM-only caching 降低平均 TTFT 42.3–79.7%。
