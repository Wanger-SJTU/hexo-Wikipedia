# JevAgentHarness: Benchmarking, Deploying and Training Decision Models That Share Control with LLMs

**作者**：Kunlun Zhu、Tao Feng、Xu Han、Heng Wang、Jiaxuan You、Heng Ji（伊利诺伊大学香槟分校），Ling Yang（普林斯顿大学），Xiangru Tang（Google）

## 摘要

大语言模型（LLM）agent 现在可以修复软件、操作计算机并服务客户，但运行它们的 harness（宿主程序）在每一步都调用一次大型 LLM，使长任务缓慢而昂贵。这些调用大多以一个多选决策告终，例如下一步调用哪个工具。Jev 等决策模型直接回答这类问题，耗时与价格只是 LLM 调用的一小部分。我们研究 harness 如何在这些决策可靠时将其委托给决策模型，使 agentic 任务更快更省、且几乎不损失成功率。为了在 agentic 任务中评估决策模型，我们构建 **AGENT DECISION BENCH**，从孤立问题一直测到对运行中 agent 的控制，覆盖公开基准与我们自建的 DECISION GYM 环境。在孤立问题上最准确的决策模型只解决了 69.5% 的 agent 任务；而若没有拟合好的置信度阈值，委托工具选择会使成功率下降 19.0 分。基于这些发现，我们设计了 **JEVAGENTHARNESS**：它在 agent 自身的轨迹上为每个选择拟合阈值，低于阈值时由 LLM 决定。由于现有决策模型从未见过 agent 在自身犯错之后到达的状态，我们以 Jev 的答案为标签、在这些状态上训练了开源 4B 模型 **AGENT DECISION-4B**。在与其训练数据不同的任务上，用 AGENT DECISION-4B 做工具选择时 agent 解决了 91.5% 的任务，用 Jev 时为 82.0%。在与其训练数据相似的任务上，以此方式训练的 4B 模型使 agent 便宜 81.1–89.0%、最快 2.5 倍提速，且不损失 3 分以上的任务成功率。模型、数据与 harness 将发布于 https://github.com/JevAgentHarness/JevAgentHarness。

## 1 引言

大语言模型已成为有能力的 agent。GPT-6 Astru（OpenAI, 2026c）、Claude Opus 5.5（Anthropic, 2026）等前沿模型报告其在 agentic 工作上取得最大进展：在真实代码仓库中解决 issue（Jimenez et al., 2024）、操作桌面与 Web 应用（Xie et al., 2024）、在终端完成任务（Merrill et al., 2026）、在领域政策下服务客户（Barres et al., 2026）。前沿模型可完成的软件任务长度自 2019 年以来约每七个月翻一番（Kwa et al., 2026）。这些能力通过 Claude Code、Codex、OpenHands 等 agent harness 落地（Anthropic, 2025; OpenAI, 2026a; Wang et al., 2025c）——为模型提供工具、管理上下文与记忆、并决定何时停止（Yao et al., 2023; Yang et al., 2024; Guo et al., 2026a）。

然而 agent 在长任务上仍然缓慢昂贵，因为多数 harness 在每一步都调用大模型（Kapoor et al., 2025; Wang et al., 2025b）。在某个公开排行榜上评估一次 agent 花费约 4 万美元（Kapoor et al., 2026）。但其中大多数调用最终只产生一个多选决策。图 1 中，客服 agent 只需查订单、取消订单或询问客户。

Jev（Almeida, 2026）及其开源同类（InternLM, 2026; StartLuxLabs, 2026; razorback16, 2026）等**决策模型**直接做出此类选择。给定任务、历史和一个多选问题，决策模型为每个列出的选项返回概率而不是生成文本，更像快速直觉的 System 1 而非缓慢审慎的 System 2（Kahneman, 2011）。在一次记录的执行中，一次 Jev 调用耗时为 LLM 调用的 28%、价格为 2.6%。现有系统将决策模型用于游戏动作、记忆、升级与评审（Ma et al., 2026; Jiang et al., 2026; Wu and Lim, 2026b; Li et al., 2026）。由于 harness 在每一步都能列出可选动作，它可以在决策模型有把握时把选择委托给它，否则退回 LLM（图 1）。我们将其称为面向 agent 的决策建模（decision modeling for agents）（Chen et al., 2025）。

然而决策模型是在固定问题上构建和测试的，并不适应其服务的 agent。它能否在 agent 内部工作从未被检验过。路由与级联（Chen et al., 2024; Ong et al., 2025）、小型函数调用模型（Zhang et al., 2025c; Lin et al., 2025）与快慢 agent（Lin et al., 2023; Christakopoulou et al., 2024）同样把工作从大模型移走，但它们也只在固定问题或单一决策类型上被测过，而 agent 基准只给整个任务打分。在 agent 内部，决策模型的错误会传播到后续步骤（Zhu et al., 2025），且一个选择改变下一个选择；它还会遇到跟随 agent 自身错误出现的状态——固定问题集很少包含这些；每次查询还会增加延迟。因此我们问：

**当决策模型可靠时，agent harness 如何把常规选择委托给一个快速便宜的决策模型，使 agentic 任务更快更省且几乎不损失成功率？**

我们的假设是：当决策模型**在 agent 内部被测试选出**、**只在有把握时使用**、并**在 agent 自身到达的状态上训练**时，它对 agent 有帮助。我们为这三个条件各建一个部分（图 2）。**AGENT DECISION BENCH** 在三个层级测试决策模型，每一层都更接近真实使用：在没有 agent 的孤立问题上；在记录的 agent 运行的每一步（答案只评分不执行，步级）；以及对运行中 agent 的控制（每个选择改变后续走向，任务级）。我们使用公开基准与 **DECISION GYM**——我们构建的环境，它知道每个状态下可接受的下一步，从而每个选择都可被评分。**JEVAGENTHARNESS** 让现有 harness 把每个常规选择作为带类型的多选问题交给决策模型，仅当模型置信度超过在 agent 自身轨迹上拟合的阈值时才采用答案。**AGENT DECISION-4B** 是开源 4B 决策模型，从 Jev 在 agent 访问状态上的答案中学习。三者都将发布。AGENT DECISION-4B 在 agent 内部优于 Jev：在与训练数据不同的任务上，它做工具选择时 agent 解决了 91.5% 的任务，Jev 时为 82.0%。JEVAGENTHARNESS 使 agent 更便宜更快：用在每个 agent 状态上训练的 4B 模型，客服与家务 agent 便宜 81.1–89.0%、最快提速 2.5 倍，且不损失 3 分以上成功率。

> **图 1**：JEVAGENTHARNESS 的直觉。Agent 的大多数 LLM 调用最终是多选决策，小决策模型可以用极小的时间和价格完成常规选择；置信度不足时才由 LLM 决定。

## 2 在哪里委托、如何委托

一个选择是否值得交给决策模型，取决于它是哪种选择、以及决策模型的答案如何与 LLM 的结合。我们定义该任务（图 3）并推导委托规则（§2.1）。该设置适用于任何能在某一步列出其选项的 harness。

**决策点**。一次 episode 是 agent 在一个任务上的一次运行，其状态 s 保存 agent 在某一步所知的信息。决策点 d 是跨步骤重复出现、且 harness 能列出其选项 Od(s) 的一类选择。我们研究八个决策点（图 3a）。三个决定 agent 做什么：工具、其参数、以及无工具时的下一个动作。五个控制循环：是否写记忆、失败后是否反思、是否停止、是否把该步路由给更便宜的 LLM、以及读取哪些存储的笔记。

**决策模型**。决策模型把 s 读作文本，带一个问题与选项（App. B.3），为每个选项返回概率 p(o|s)。其答案是最可能的选项，其置信度 c(s) 是该选项的概率（Jev 直接返回该概率）。Intern-Decision、AGENT DECISION-4B 等开源模型一次前向即可为所有选项打分。

**谁决定**。集成模式固定谁提出答案、谁有最终决定权（图 3b）。我们主要使用级联（CASCADE）：决策模型先作答，harness 仅当其置信度超过阈值时采用，c(s) ≥ τd；否则照常由 LLM 决定。其他模式中，决策模型总是决定（REPLACE）、为 LLM 缩短选项名单（ASSIST）、批准或否决 LLM 的选择（GUARD）、或决定一个可选步骤（如反思）是否运行（TRIGGER）。我们实现了全部 40 种"决策点×模式"组合（附录 A）。一个决策点连同其模式与阈值构成一个**委托（delegation）**，例如工具选择级联。我们寻找成功保持在 LLM 单独水平 3 分以内的最便宜委托集合。

**一个决策示例**。考虑被要求取消订单的客服 agent（附录图 6）。每一步 harness 问应调用 69 个工具中的哪一个。第 3 步，Jev 把票分给询问客户（0.63）与取消（0.37），于是 LLM 决定并询问。第 4 步，Jev 对取消很有把握，于是从聊天复制的选项中选出订单、从固定列表中选出原因。两个答案都有把握，因此这次调用无需 LLM。一个没把握的答案或自由文本参数则要花一次 LLM 调用。

### 2.1 决定委托什么

**阈值规则**。把一个选择交给决策模型可省一次 LLM 调用，但可能导致错误选择。若其置信度等于其正确率（附录 A），则恰好当 c(s) ≥ qL − ΔC/V 时移交是值得的，其中 qL 是 LLM 在该选择上的正确率，ΔC 是省下的调用价格，V 是错误选择的代价。此值即最优阈值 τd。因此只要节省覆盖额外风险，决策模型可以略逊于 LLM。

**拟合阈值**。我们先在单独任务上运行 agent（每个 agent LLM 150 个任务），同时决策模型以影子模式（shadow mode）默默回答每个问题。从这些轨迹中，我们按决策点估计 LLM 正确的频率（qL）、一次调用的价格（ΔC）与 V（一次错误选择导致的任务成功下降，按每个已解决任务 1 美元计价）。轨迹还给出决策模型在各置信度上的准确率，因此阈值是"接受值得"的最低置信度，且该置信度不必精确等于其正确概率（附录 A）。若没有合格值，LLM 继续决定。用 Jev 与 Flash 时，拟合阈值为工具 1.00、参数 0.99，因此只有近乎确定的答案被采用。

## 3 AGENT DECISION BENCH

一个决策模型可以在测试中得分很高，却仍在 agent 内部失败。现有测试提出固定答案的单个问题，错误答案从不影响后续。Agent 基准运行整个任务但只报告任务是否成功，不展示哪个选择出错。AGENT DECISION BENCH 在公开数据与 DECISION GYM 上于三个层级测试决策模型，每次调用都被计价与计时（附录 F，表 5）。

**L1：孤立问题**。决策模型在无 agent 的情况下回答单个问题。我们把 BFCL v4（Patil et al., 2025）的 1,114 个工具选择与 1,949 个参数条目、以及 When2Call 的 928 个条目（Ross et al., 2025）转为多选题。

**L2：步级（记录的 agent 运行）**。决策模型在记录的 agent 运行的每一步作答，但答案只评分，运行照记录继续，一个错误不会引起下一个错误——如在记录驾驶上测试驾驶策略。每个答案对照"可接受下一步"的答案键检查。所有模型回答相同的 200 个新 DECISION GYM 任务的 5,314 个状态（公共状态）。

**L3：任务级（控制 agent）**。决策模型现在决定运行中 agent 的每次工具选择（ALFWorld 中的每个动作），无阈值，LLM 写参数，且每个选择都被执行。错误选择改变 agent 接下来看到的内容，错误可能累积。该层级度量任务成功，是最难、最接近部署的层级。我们的 agent 循环运行 τ²-bench（Barres et al., 2026）、ALFWorld（Shridhar et al., 2021）与 DECISION GYM 任务；钩子（hooks）使我们无需修改现有 harness 代码即可测试：SWE-bench Verified 上的 mini-SWE-agent 与 SWE-agent（Jimenez et al., 2024），以及 Terminal-Bench 2.0 与 Terminal-Bench-Science 上的 pi 终端 agent（Merrill et al., 2026; Terminal-Bench-Science Team, 2026）。

第 2、3 层需要一个知道 agent 可到达的每个状态（包括其犯错后的状态）下哪些下一步可接受的环境。公开 agent 基准只检查最终状态或运行进度（Lu et al., 2025; Ma et al., 2024），任务集固定且重跑缓慢昂贵。因此我们构建 **DECISION GYM**：一个小商店的模拟客服台，如 τ-bench（Yao et al., 2025）那样在小数据库上提供带类型的工具，如 TextWorld（Côté et al., 2019）那样从模板生成请求。每个任务提供同样的 68 个工具加 finish，顺序打乱：7 个核心工具、1 个询问客户的工具、31 个核心工具的近似重复、29 个无关工具。由于每个任务来自脚本化计划，DECISION GYM 能在每个"仍可解决任务"的可达状态（包括绕路之后）推导答案键。训练、阈值拟合与测试使用不相交的随机种子。近似重复的干扰工具与"必须询问"状态（正确动作是询问客户）使任务变难。答案键对所有模型隐藏；严格模式下，任何不在计划内对商店数据的修改都会结束 episode（附录 B）。主研究之后追加的两个任务集测试模型超出训练数据的能力：**Shifted tasks**（DECISION GYM-Shift，附录 G.9）重命名工具并改变请求措辞与种类；**Hard tasks**（DECISION GYM-Hard，附录 D.6）每个有 10 或 12 个客户，并加入新的取消/发货规则。

## 4 JEVAGENTHARNESS

JEVAGENTHARNESS 把 harness 的常规选择移交给决策模型。它把每个列出的选择作为多选题提出，仅当模型足够有把握时采用答案，否则照常由 LLM 决定。Harness 有三部分（附录图 8）。

**带类型的决策接口**。每个选择都用 Jev 的输入格式：选项是工具、固定列表或是否型参数值、或从上下文复制的文本片段。一次工具调用被拆为一个工具选择加每个此类参数各一个选择，因此决策模型可两者都选而 LLM 只写自由文本。任何接受该格式的模型都可用（附录 C）。

**在轨迹上拟合的置信度阈值**。每个决策点获得 §2.1 中在影子模式轨迹上拟合的阈值，因此决策模型只接受它可靠作出的选择。低于阈值时 LLM 决定，因此一个没把握的答案只浪费一次便宜的决策模型调用而不危及任务。当 LLM、决策模型或任务规则改变时重新拟合阈值。

**适配器、服务与记账**。适配器通过现有 harness 的钩子提问同一批问题：mini-SWE-agent 的强弱 LLM 路由、pi 的 guard 与 trigger、Codex CLI 与 Claude Code 的命令钩子。若适配器或决策模型失败，harness 照常运行（附录表 9）。

## 5 AGENT DECISION-4B

我们训练自己的决策模型有两个原因。Jev 这类 API 模型按次计费且无法学习 harness 自身的规则；现成模型从固定问题与成功示范中学习，这类数据很少包含 agent 犯错后到达的状态——而决策模型也必须在那里作答（附录 D.2）。因此我们对小型开源模型 Qwen3-4B 做 LoRA 后训练（Yang et al., 2025; Hu et al., 2022），数据是 harness 访问的状态：先监督微调（SFT），再在 agent 循环内做强化学习。

**监督微调**。我们在 587 个训练任务上运行 harness 并记录全部 15,694 个决策状态。为纳入错误后的状态，脚本化策略重演开发中见过的错误（Ross et al., 2011; Laskey et al., 2017），30.9% 的状态跟随一个错误（附录 D）。当教师 Jev 把正确答案 a⋆ 排在首位时，目标分布将 a⋆ 的 one-hot 标签与教师概率混合：ya = α·𝕮[a = a⋆] + (1−α)·pJev(a|s)，α = 0.3；否则目标为纯 one-hot 标签。SFT 用交叉熵加平方误差（Brier）项拟合该目标以保持概率校准：

LSFT = E_s[ Σ_a (−ya log pa) + μ(pa − ya)² ]，(1)

其中 pa = pθ(a|s)，μ = 0.5。使用 LoRA（r=32）、2 个 epoch、学习率 10⁻⁴。

**Agent 循环内的 GRPO**。SFT 模型随后在训练任务上做决策，固定 agent LLM 完成其余部分，从而从自身选择的后果中学习。每个任务运行一组 G=8 个 episode。Episode i 的奖励为成功 Si∈{0,1}，按其使用的 LLM 调用数 Ni 折减，并在做出不可逆错误调用时扣罚（Ei=1）：

Ri = Si(1 − λ·min(1, Ni/N0)) − ηEi，(2)

其中 λ=0.5、N0=10、η=0.2：用了十次以上 LLM 调用的已解决任务只得一半。每 episode 的优势为组内相对奖励 Âi = (Ri − R̄)/σR，episode 内每个决策共享它进入 GRPO 目标（Shao et al., 2024），加上组内重复出现状态的步级项（Feng et al., 2025a）与对 SFT 模型的 KL 惩罚（附录 D）。Agent LLM 为 Flash-Lite，保留第 15 次迭代。

**评估**。Stage 2 用冻结的 AGENT DECISION-4B 替换 Jev 并重新拟合阈值。之后我们还在公开工具使用数据上进一步训练。

## 6 实验协议

Stage 1 单独测试每个委托，保留比 LLM 单独更便宜且不劣于其的委托。"不劣"指在同任务双向运行上的 5% 单侧检验显示任务成功损失小于 3 分（τ²-bench 为 5 分；附录 E）。Stage 2 将通过筛选的委托组合起来在新任务上测试，因为委托之间可能相互作用。我们预注册了模型、任务与测试，并在读取任何 Stage 1 结果之前注册 Stage 2 计划，使组合选择无法偏置其检验。

**Stage 1：每个委托单独**。决策模型为 Jev（三个委托另用 Intern-Decision-4B）。Agent LLM 为 Gemini 3.5 Flash（原生工具调用）。更便宜更弱的 Gemini 3.5 Flash-Lite 接收被路由的步骤、模拟 τ²-bench 用户，并作为 DECISION GYM 上的第二 agent LLM（附录 F）。LLM 单独与无决策模型的简单对照在与每个委托相同的任务上运行（附录 B.5）。十一项注册检验中有些可能偶然通过，因此 Holm 方法（Holm, 1979）使每个检验更严格，把任何错误通过的概率保持在 5%。其余结果为描述性的。

**Stage 2：委托组合**。脚本按预先固定的规则选择组合：每个决策点取通过 Stage 1 且节省最大的委托，若无一通过则保留 LLM（附录 E）。我们在 500 个新 DECISION GYM 任务与 τ²-bench 电信任务上运行该组合。四项 Holm 校正检验检查两件事。前两项检查组合仍然有效：它应在更低成本下不劣于 LLM 单独，且比其最佳单委托更便宜而不损失成功（否则组合不值得）。另两项检查我们训练的模型能否取代 Jev：在公共状态上，AGENT DECISION-4B 应胜过从未见过 agent 状态的同规模模型 Intern-Decision-4B，且不劣于其教师 Jev；组合在 AGENT DECISION-4B 替换 Jev 后也应保持不劣于 LLM 单独。

## 7 结果

LLM 单独解决了 99.4% 的 DECISION GYM 任务，因此表 1 报告更难的设置。表 1、图 4 与 shifted 任务来自 Stage 1 之后追加的实验。

### 7.1 RQ1：孤立分数能预测成功吗？

在孤立问题上（图 4a），Jev 以 1/50 的成本比 Flash 低 1.7 分（附录 G.6）。在一张 L4 GPU 上，AGENT DECISION-4B 与 AGENT DECISION-0.8B 每次决策的成本分别约为 Jev 的 1/4 与 1/9（附录 G.7）。在任务级，排名不同于孤立排名（图 4b）。StartLux-9B 在 BFCL 工具选择上最准（92.2%），却只解决 69.5% 的任务。AGENT DECISION-4B 在 BFCL 上较不准（89.3%）却解决 91.5% 的任务；Jev 解决 82.0%。步级准确率的排名与任务成功几乎一致（Kendall 相关 0.84）。差距在必须询问状态：AGENT DECISION-4B 答对 67.4%，Jev 答对 58.3%。

> **发现 1**：孤立分数会错误排名决策模型。孤立问题上最好的决策模型只解决 69.5% 的 agent 任务，而 AGENT DECISION-4B 解决 91.5%。

### 7.2 RQ2：哪些决策可以委托？

Stage 1 单独测试了每个委托（图 5）。只在阈值之上采用答案的级联在工具与参数选择上节省了成本。以 Flash 为 agent LLM 时，Jev 做了 27.2% 的工具选择与 20.8% 的参数选择，在 500 个任务的结果完全不变的情况下削减 14.2% 成本，并通过注册检验。用 Flash-Lite 时，拟合阈值把所有工具选择都留给 LLM，级联一无所获。无阈值的模式损失成功率：让 Jev 决定每次工具选择损失 19.0 分；Jev 的三工具短名单损失 7.8 分但削减成本 53.7%（虽远胜关键词短名单：92.0% 对 18.8% 的任务解决率）。停止守卫保住了成功但多花 6.2% 成本；让 Jev 把 Flash-Lite 的步骤发给 Flash 比单独 Flash-Lite 贵 36.2% 且无明显成功增益。在 τ²-bench 上重新拟合后，通过筛选的最便宜委托损失 8.1 分，因此无法证明其可迁移。

> **发现 2**：拟合阈值保护成功率。它削减 14.2% 成本而不损失任何一个任务；固定阈值损失 21.5 分。

### 7.5 委托在何处失败

三种失败模式反复出现。**不可逆步骤上的自信错误**会终结任务：Jev 全部 34 个失败任务都始于一次不可逆的错误工具选择，通常是该询问客户时却取消了订单。在 agent 状态上训练的模型没有此类错误（附录 G.7）。**新规则**：在 10 客户的困难任务上，未在该规则上训练的 AGENT DECISION-4B 做出了大多数取消/发货决策但只对 81.6%，agent 只解决 3.0% 的任务（LLM 单独为 88.0%）。用 Jev 重新拟合阈值恢复了成功（表 1），并在该规则上重训 AGENT DECISION-4B 将其保留集准确率从 76.5% 提到 95.3%（附录 D.6）。最后，仍调用 LLM 的模式（如守卫）节省很少。

## 8 相关工作

**决策模型**。Jev 及 Intern-Decision、StartLux-Decision、OpenJev 等开源模型为列出的选项打分（Almeida, 2026; InternLM, 2026; StartLuxLabs, 2026; razorback16, 2026）；DecisionFlow（Chen et al., 2025）结构化 LLM 决策。REFLEX 在置信度低于一个全局阈值时把动作交给 LLM（Wu and Lim, 2026b），而我们为每个决策点拟合一个阈值。

**决策评估**。决策与工具使用基准为固定问题打分（Benchmark Heaven, 2026; Ling et al., 2026; Patil et al., 2025; Ross et al., 2025），agent 环境为整个 episode 打分（Yao et al., 2025; Trivedi et al., 2024; Lu et al., 2025）。分数相同的模型仍可能以不同方式决策（Zhang et al., 2026）。AGENT DECISION BENCH 增加了步级与任务级测试。

**路由、退避与训练**。路由与级联为一次调用选择模型（Chen et al., 2024; Ong et al., 2025; Aggarwal et al., 2024）。学习型路由（LLMRouter 中比较，Feng et al., 2026a）使用 query–LLM 图、多 LLM 日志或多轮 RL（Feng et al., 2025b, 2026b; Zhang et al., 2025a）。决策模型则为列出的选项打分、不确定时退避，类似 learning to defer（Geifman and El-Yaniv, 2017; Mozhannar and Sontag, 2020）。Agentic RL 训练 LLM（Jin et al., 2025; Wang et al., 2025d），而我们训练决策模型（附录 H）。

## 9 结论

我们的结果支持如下假设：当在 agent 内部**被测试**、**被使用**并**被训练**时，决策模型对 agent 有帮助。只有 agent 内部的测试（AGENT DECISION BENCH）显示了哪些决策模型在那里有效。在 agent 状态上训练的 AGENT DECISION-4B 在 agent 内部胜过 Jev；配合在 agent 轨迹上拟合的阈值（JEVAGENTHARNESS），它完成了大多数常规选择。以此方式训练的模型使 agent 便宜 81.1–89.0%、最快 2.5 倍提速，且不损失 3 分以上成功率。

**局限**。所有任务与 prompt 均为英文，多数运行使用 Gemini agent LLM（少数用 DeepSeek 与 OpenAI 模型）。换用其他语言或 agent LLM 时，值得委托的选择类型可能不同。我们的主要检验是非劣性检验：只表明任务成功下降小于固定边际（3 分，τ²-bench 为 5 分），证明相等成功需要等价性检验。阈值与训练出的决策模型拟合于 agent 自身运行，新 agent、新工具或新任务族需重新拟合。决策模型可能被对抗状态操纵（Wu and Lim, 2026a），因此我们的结果仅对良性状态成立。更便宜的 agent 控制也降低了大规模滥用的成本。
