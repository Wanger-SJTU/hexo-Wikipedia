## 1 引言

大语言模型（LLM）向超长上下文窗口的扩展从根本上受限于内存容量。虽然现代稀疏注意力机制成功地将每个解码步骤的计算 FLOPs 降低到接近恒定的水平，但键值（KV）缓存的 GPU 内存占用仍然与序列长度呈线性增长。DeepSeek-V4$^1$ 和 Qwen3.5$^2$ 等最新基础模型通过引入重度压缩注意力（HCA）或线性注意力层 [1, 2] 来减缓这种内存爆炸。然而，为了保留细粒度的事实召回能力，这些模型仍然必须保留相当一部分低压缩率或全注意力层 [1]。因此，它们只是降低了内存增长的速度，而非从根本上消除线性扩展的瓶颈。

本研究源于对推理过程中资源浪费的一个简单而引人注目的观察：传统的 LLM 在 GPU 内存中完整加载并携带整个 KV 缓存，即使当前解码步骤与历史上下文完全无关。我们对真实推理日志的实证分析表明，超过 90% 的上下文超过 64K token 的用户请求，仅使用最后 8K token 就能准确解决。这意味着绝大多数 GPU 内存被浪费在根本不对当前 token 预测做出贡献的非活跃上下文上。反过来，通过标准滑动窗口注意力简单地丢弃历史信息，在真正需要全局上下文综合的剩余任务上则完全失败。这个尖锐的矛盾——既要支持深层的全局推理，又不愿为局部生成步骤支付完整的 GPU 内存代价——是长上下文服务成本居高不下的根本原因。

为解决这一困境，我们提出了前瞻性稀疏注意力（Lookahead Sparse Attention, LSA）。秉承 DeepSeek-V4 [1] 的结构压缩精神，我们的架构保留了所有高度浓缩的 HCA 块（128:1 压缩比）以维持全局上下文感知能力。然而，我们将传统的压缩稀疏注意力（CSA）层从根本上升级为我们的预测性 LSA 范式。LSA 赋予模型不再回忆那么多细粒度上下文的能力；相反，在高效神经记忆索引器的驱动下，系统以固定的解码间隔 $\tau$ 步（例如 $\tau = 64$）周期性地触发，评估当前隐藏状态并主动仅将关键 CSA 块获取到 GPU 内存中。关键的是，我们将索引器形式化为一个独立的双编码器架构。这种解耦设计使我们能够在预计算的隐藏状态和标签上独立训练索引器，完全绕过全模型微调或联合蒸馏的巨大内存和计算开销。

在三个不同的长上下文基准测试上的实验结果证实了 LSA 的鲁棒性和惊人的效率。在需要长期记忆和深层理解的任务中，LSA 充当了一个有效的注意力去噪器。具体而言，在 LongBench-v2、LongMemEval 和 RULER 上的平均结果中，LSA 将 GPU 内存消耗降至基线的仅 13.5%（降低 86.5%），同时以 +0.6% 的绝对精度优势超过了标准 DeepSeek-V4-Flash。在 500K 上下文长度下，内存降低幅度高达 90%。

概括而言，我们的核心贡献有三个方面：

- **前瞻性稀疏注意力（LSA）范式：** 我们提出了 LSA，一种新型推理范式，通过主动预测并按需获取查询关键的 KV 块，消除了长上下文建模能力与硬件效率之间的尖锐矛盾。
- **无骨干解耦训练：** 我们引入了一种超轻量级训练策略，在物理上将索引器与宿主 LLM 隔离。作为在预计算表示上训练的独立双编码器，索引器仅需一块 H20 GPU 的单小时即可完成独立优化，无需加载庞大的骨干模型。
- **效率突破：** 大量评估表明，LSA 将 GPU 内存降至基线的仅 13.5%（在 500K 时降低高达 90%），同时保持了与全注意力基线相当的精度。

## 2 方法论

在本节中，我们介绍前瞻性稀疏注意力（LSA）的技术细节，包括其架构设计、数据构建流水线、优化策略和最优配置。具体而言，第 2.1 节介绍我们如何在 DeepSeek-V4 框架上架构 LSA 以实现预测性上下文选择。第 2.2 节介绍我们的前瞻性数据格式和自动化收集流水线。第 2.3 节详细说明我们的解耦训练策略，在物理上将索引器优化与庞大的 LLM 骨干隔离。最后，第 2.4 节介绍我们对生产模型的最优层配置和训练方案的系统探索。

### 2.1 用于前瞻性选择的记忆索引器

LSA 的核心设计原则是对 DeepSeek-V4 架构的最小化修改，从而最大化保留其已建立的能力。因此，我们的记忆索引器完全镜像了 DeepSeek-V4 中原生闪电索引器的架构，重用压缩索引器键 $K^{I}_{\text{Comp}}$ 作为历史上下文的稠密表示。关键区别在于我们引入了 Sigmoid 函数作为最终激活层，将索引器分数缩放到 $(0, 1)$ 范围内，并用基于阈值的机制替换了刚性的 Top-k 选择器，以召回动态数量的历史条目。

在自回归解码阶段，记忆索引器以固定的解码步间隔 $\tau$（例如 $\tau = 64$）周期性触发，执行前瞻性块预测。如图 2 所示，在解码步骤 $t$（其中 $t \pmod{\tau} = 0$），给定查询 token 的当前输入隐藏状态 $h_t \in \mathbb{R}^d$，我们将其映射为跨 $n_h$ 个索引器头的低秩索引器查询：

$$c^Q_t = h_t \cdot W^{DQ}, \tag{1}$$

$$q^l_t = c^Q_t \cdot W^{IU}_l, \tag{2}$$

其中 $W^{DQ} \in \mathbb{R}^{d \times d_c}$ 和 $W^{IU}_l \in \mathbb{R}^{d_c \times c^l_h}$ 分别表示前瞻查询表示的下投影和上投影矩阵。同时，我们动态投影 $h_t$ 以计算路由头权重 $w^l_t$：

$$w^l_t = h_t \cdot W^w_l, \tag{3}$$

其中 $W^w_l \in \mathbb{R}^{d \times n_h}$ 是一个可学习矩阵，$w^l_{t,h}$ 动态缩放第 $h$ 个索引器头的重要性。

为确定哪些历史压缩 KV 条目对于即将到来的窗口 $[t, t + \tau - 1]$ 是严格关键的，查询 token $t$ 与前驱压缩条目 $s$（$s < \lfloor \frac{t}{m} \rfloor$）之间的前瞻索引分数 $I_{t,s}$ 被构建为带 Sigmoid 激活的头融合门控匹配分数：

$$I_{t,s} = \sigma \left( \sum_{h=1}^{n_h} w^l_{t,h} \cdot \text{ReLU} \left( (q^l_{t,h})^T \cdot K^{I,\text{Comp}}_s \right) \right), \tag{4}$$

其中 $\sigma(\cdot)$ 表示标准 Sigmoid 函数。

这个 Sigmoid 激活是与原生闪电索引器的唯一架构差异。原始索引器对原始注意力分数应用 ReLU 边界，而 LSA 引入 Sigmoid 归一化，将记忆索引器的标量输出与离散二值目标 $y \in \{0, 1\}$ 显式对齐。对于查询 token $t$，与其使用刚性的 Top-k 选择策略，我们获取所有前瞻分数达到或超过特定分类阈值（即 $I_{t,s} \geq 0.5$）的前驱压缩 KV 条目，从 CPU 冷池获取到 GPU 内存中用于后续核心注意力计算：

$$C^{\text{MemComp}}_t = \left\{ C^{\text{Comp}}_s \mid I_{t,s} \geq 0.5 \right\}, \tag{5}$$

其中 $C^{\text{Comp}}$ 表示预计算的压缩 KV 条目。一旦查询关键上下文子集 $C^{\text{MemComp}}_t$ 成功驻留在 GPU 内存中，原生闪电索引器在这个受限的 $C^{\text{MemComp}}_t$ 边界内计算 token 级匹配分数，而非扫描完整上下文。它对获取的子集应用原生的基于 ReLU 的多头查询注意力评分，选择最终的细粒度 Top-k 核心压缩条目：

$$C^{\text{CoreComp}}_i = \left\{ C^{\text{Comp}}_s \in C^{\text{MemComp}}_t \mid \text{Score}_{\text{native}}(i, s) \in \text{Top-}k \right\}. \tag{6}$$

选定的 $C^{\text{CoreComp}}_i$ 条目随后与不可卸载的滑动窗口 KV 缓存拼接，参与最终的核心注意力计算。这种分层选择机制保证了底层 FlashInfer 或 FlashAttention 内核仅在高度浓缩的、硬件驻留的活跃序列足迹上运行。

### 2.2 前瞻性数据集构建

优化记忆索引器的基石是精确定位解码 token 需要前瞻查看哪些历史压缩 KV 条目。一种朴素的方法是将 token $t$ 的正标签集定义为原生闪电索引器在未来窗口 $[t, t + \tau - 1]$ 中召回的所有 Top-k 条目的简单并集。然而，实证分析揭示了这个策略存在严重的膨胀问题，在过滤前每个 token 窗口产生近 10,000 个正样本（经过我们的流水线后减少到约 100–1,000 个）。根本原因是刚性的 Top-k 选择器强制模型召回固定数量的前驱条目，而不管它们的实际相关性，导致来自不同注意力层的低概率噪声条目严重污染了真实标签数据集。

为消除这种噪声，我们提出了一种黄金标签过滤流水线，使用跨层多数投票机制来识别真正的"黄金条目"。数据生成过程在冻结的 DeepSeek-V4-Flash 骨干模型上完全离线运行。对于每个解码 token $i \in [t, t + \tau - 1]$ 和所有 $L$ 个 CSA 层（DeepSeek-V4-Flash 中 $L = 21$ [1]），我们提取每个前驱压缩条目 $s$ 的原始索引器 logit 分数 $S_{i,l,s}$。然后我们通过三步去噪流水线过滤这些分数：

- **第 1 步：Softmax 归一化。** 我们通过 Softmax 操作将原始 logit 分数转换为有效的概率分布：

$$P_{i,l,s} = \frac{\exp(S_{i,l,s})}{\sum_j \exp(S_{i,l,j})}. \tag{7}$$

- **第 2 步：Top-p 阈值化。** 与其使用固定的 Top-k 数量，我们使用核阈值 $p$ 动态保留高置信度条目（经验上设 $p = 0.6$）。如果条目 $s$ 落在累计占前 60% 概率质量的最小条目集合中，则被标记为由层 $l$ 选中：

$$M_{i,l} = \left\{ s \mid \sum_{j \in \text{Sorted}(P_{i,l,:})} P_{i,l,j} \leq p \right\}. \tag{8}$$

- **第 3 步：跨层多数投票。** 我们汇总所有 $L$ 层的选择命中。条目 $s$ 在 token 步骤 $i$ 的投票分数 $V_{i,s}$ 通过计算有多少层独立投票给它来确定：

$$V_{i,s} = \sum_{l=1}^{L} \mathbb{I}(s \in M_{i,l}), \tag{9}$$

其中 $\mathbb{I}(\cdot)$ 是指示函数。仅当条目获得至少 $\theta$ 层的共识支持时，才被正式认定为核心活跃条目 $A^{\text{golden}}_i$（我们设 $\theta = 3$）：

$$A^{\text{golden}}_i = \{ s \mid V_{i,s} \geq 3 \}. \tag{10}$$

最后，对于在解码步骤 $t$ 触发的每个前瞻评估窗口，正标签集 $Y^+_t$ 通过取整个 $\tau$ 步未来时间窗口中去噪黄金条目的并集来建立：

$$Y^+_t = \bigcup_{i=t}^{t+\tau-1} A^{\text{golden}}_i. \tag{11}$$

通过从任意的 Top-k 查找转向共识驱动的密度估计，我们的流水线隔离了长序列的真实上下文骨架，丢弃了不相关的背景噪声。我们的训练集总计包含约 10,000 篇长文档，上下文长度从 16K 到 512K token 不等。

### 2.3 优化与解耦训练

虽然我们的记忆索引器与原生闪电索引器具有相似的结构设置，但它们的底层优化范式根本不同。与依赖繁重的端到端自蒸馏的原生闪电索引器不同，我们将记忆索引器视为标准的检索模型，通过度量学习进行优化。主要训练目标是执行基于距离的对比优化：最大化查询关键历史条目的前瞻匹配分数，同时最小化负样本的分数。

LSA 的一个关键系统洞察是，历史条目的压缩索引器键 $K^{I,\text{Comp}}_s$ 在训练阶段完全预计算并严格冻结。因此，优化过程简化为仅训练标准双编码器检索架构的查询编码器。具体而言，我们只需要优化低秩投影矩阵 $(W^{DQ}, W^{IU}, W^w)$，将当前输入隐藏状态 $h_t$ 映射为与固定历史目标对齐。

为实现这一目标，我们对预测的前瞻分数最小化标准的逐元素二元交叉熵（BCE）损失函数。对于预测概率为 $p$、标签为 $y \in \{0, 1\}$ 的单个样本，逐样本 BCE 定义为：

$$\ell_{\text{BCE}}(p, y) = -\left[ y \log(p) + (1 - y) \log(1 - p) \right], \tag{12}$$

其中当 $s \in Y^+_t$ 时 $y_{t,s} = 1$，否则 $y_{t,s} = 0$。整体批次目标则是批次 $S$ 中所有样本的平均值。

由于历史表示 $K^{I,\text{Comp}}_s$、目标标签 $Y^+_t$ 和特定层的查询隐藏状态 $h_t$ 均已离线预提取和存储，训练流水线实现了与宿主 LLM 的完全物理隔离。千亿参数的骨干模型在整个优化循环中从不加载到 GPU 内存中。由于可训练的投影层仅占全模型参数规模的不到 0.1%，计算工作量非常小。因此，整个记忆索引器在单块 H20 GPU 小时内即可优雅收敛。

这种解耦设计显著加速了我们的研究周期。借助单个 8× NVIDIA H20 GPU 集群，我们在一周内无缝执行了约 500 个不同的训练运行，系统性地绘制出最优架构和训练策略，这在传统联合端到端蒸馏下是计算上不可行的。

### 2.4 架构最优配置

设计 LSA 的一个基本前提是，并非每个 Transformer 层都适合上下文前瞻预测。我们早期探索发现，在 LLM 初始浅层部署记忆索引器会产生极差的前瞻性能，因为这些早期表示主要捕获低级 token 统计信息，而非长距离语义依赖关系。因此，高效的系统路由范式必须仅在具备成熟全局上下文感知的层上选择性部署索引器。

然而，扩展联合训练层数会引入性能与服务效率之间的严格权衡。单层检索器缺乏处理多样化长上下文工作负载的表示能力，但激进地扩展到 8 层联合配置（跨越第 6 到 20 层）则会引入严重的硬件端效率退化。正如我们在全系统基准测试中所验证的，8 层集成触发了过于宽松的上下文召回掩码，将高达 30%–49% 的历史压缩 KV 条目获取到 GPU 内存中，这违背了我们最小化内存代价的首要目标。

通过大量的帕累托前沿优化，我们确定在恰好三个战略性中间层——第 10、12 和 20 层——部署独立记忆索引器是最佳平衡点。在推理期间，我们的运行时系统使用并集操作策略（OR 模式路由）汇总这三层的评分预测。具体而言，如果三个层索引器中至少一个预测其分类分数 $I^{(l)}_{t,s} \geq 0.5$，则前驱压缩 KV 条目将被主动获取到 GPU 内存中：

$$C^{\text{MemComp}}_t = \bigcup_{l \in \{10,12,20\}} \left\{ C^{\text{Comp}}_s \mid I^{(l)}_{t,s} \geq 0.5 \right\}. \tag{13}$$

这种 3 层共识框架提供了异常鲁棒的回退保护边界。

我们的最终生产模型实例建立在这个最优 3 层几何结构之上，并通过精心策划的有效训练策略组合进行优化：

- **随机初始化：** 与其从宿主检查点加载带有对齐偏差的权重，我们随机初始化索引器的投影矩阵，强制双编码器从头学习统一表示。
- **查询低秩调节：** 我们利用 DeepSeek-V4 架构原生的低秩查询投影几何结构。在 DeepSeek 的 MLA/MQA 设计中，查询向量通过内部低秩瓶颈进行投影（在 DeepSeek-V3 代码库中正式命名为 `q_lora_rank`，默认值为 1536）。在我们的实现中，我们将 R 系列配置的内部投影维度设为 $r = 2048$。这不是 PEFT 风格的 LoRA 微调（通常使用 8–64 的秩来学习冻结权重上的小扰动），而是模型注意力骨干的固定架构维度，决定查询编码器的表示能力。增加这个秩直接扩展前瞻索引器的空间投影能力，而不引入任何适配器开销。
- **Focal Loss 去噪：** 为防止简单负样本主导梯度，我们用样本加权 Focal Loss 替换标准 BCE。令 $p_{t,s} \in [0, 1]$ 表示 Sigmoid 激活的索引器分数，$y_{t,s} \in \{0, 1\}$ 为二值标签。我们首先计算正确类上的预测置信度：

$$p^{(\text{correct})}_{t,s} = p_{t,s} \cdot y_{t,s} + (1 - p_{t,s}) \cdot (1 - y_{t,s}). \tag{14}$$

逐样本 Focal Loss 定义为：

$$\mathcal{L}_{\text{FL}} = \frac{1}{|S|} \sum_{s \in S} w_{t,s} \left(1 - p^{(\text{correct})}_{t,s}\right)^\gamma \ell_{\text{BCE}}(I_{t,s}, y_{t,s}), \tag{15}$$

其中 $\ell_{\text{BCE}}$ 是标准二元交叉熵，$\gamma = 2$ 是聚焦参数，用于降低已正确分类样本的权重，$w_{t,s}$ 是逐样本权重。值得注意的是，我们不使用单独的类平衡系数 $\alpha$；相反，类别不平衡由以下方式联合处理：(i) 3:1 的负采样比（每个正样本对应三个负样本），以及 (ii) 由 `--weighted-loss` 调度器计算的逐样本权重 $w_{t,s}$。这种设计迫使优化器专注于困难边界 token，同时保持超参数表面最小。

反过来，多个流行的检索和对比学习技巧在我们 500 次运行的扫描中被证明是多余的甚至是有害的，被系统性地排除在我们的最终流水线之外：

- **逐对到逐点链式训练：** 将优化从逐对排序阶段（BPR/Margin Loss）过渡到逐点校准阶段，相比纯逐点训练循环没有产生统计上的召回增益。
- **强负样本挖掘：** 利用 LLM 标注的语义块作为硬负样本池，在对比格式中引入了严重的次级标签噪声；在非投票历史仓库中的随机负采样被证明更加鲁棒。
- **加权损失函数：** 根据原生层匹配计数缩放损失略微提高了原始精度，但通过丢弃边界上下文降低了绝对召回上限，使模型偏离了其安全网目标。

**关于超参数选择的说明。** 由于项目的意外暂停，我们无法对若干关键超参数进行系统的消融研究。具体而言，解码间隔 $\tau = 64$ 和分类阈值 0.5 是基于初始探索性运行选择的，但在替代值上尚未经过测试。3 层配置（第 10、12、20 层）是通过第 2.4 节中描述的 500 次帕累托扫描确定的；然而，更细粒度的逐层消融是未来工作所期望的。

## 3 实验

### 3.1 实验设置

为确保对 FlashMemory 范式的严格且受控的评估，我们将模型与三种结构变体进行了基准对比。关键的是，为保持架构一致性，所有评估配置统一保留了完整的重度压缩注意力（HCA）层（128:1 压缩比），以及对应原始提示最后 8K token 和局部窗口内所有活跃解码 token 的精确 CSA 块。剩余历史长上下文 CSA 块的不同处理方式区分了各方法：

- **DS-V4-Flash：** 标准的、未修改的 DeepSeek-V4-Flash 模型。
- **FM-DS-V4（我们的方法）：** 增加了记忆索引器的 DS-V4-Flash 骨干。前瞻选择机制每 $\tau = 64$ 个解码步骤周期性触发，动态评估并将查询关键的历史 CSA 块从 CPU 冷池获取到活跃的 GPU HBM 中。
- **Recency Only（仅近因）：** 滑动窗口回退控制。虽然共享相同的基础 HCA 层和局部 8K/解码 CSA 窗口以匹配静态局部内存分配预算，但完全丢弃所有先前的长上下文历史 CSA 块，执行零预测性前瞻检索。
- **Random 10%（随机 10%）：** 朴素的稀疏路由控制。在基础 HCA 层和局部 8K/解码 CSA 窗口之上，随机选择并保留恰好 10% 的全局历史上下文 CSA 块在活跃 KV 缓存中，提供非预测性的随机基线。

### 3.2 主要结果：突破容量墙

实证结果为 FlashMemory 范式带来了令人瞩目的胜利。在所有任务上的平均结果中，FM-DS-V4 仅消耗基线 GPU 内存占用的 13.5%——代表 KV 缓存存储平均降低 86.5%——同时实际上将整体性能提升到了 77.5%（相比 DS-V4-Flash +0.6% 的绝对优势）。当平均上下文长度达到 500K 时，这个降低比率进一步攀升到惊人的 90%。

这种反直觉的"少即是多"现象在超长 LongBench-v2-L（493K）设置中尤为突出，我们的模型在仅 10.0% 的内存预算下运行，却以 +1.9% 的优势击败 DS-V4-Flash。这有力地证明了我们的核心假设：LSA 充当了一个专家级的注意力去噪器，过滤掉数千个无关的历史块，否则这些块会干扰注意力点积运算并导致事实幻觉。在相同的内存限制下，原生启发式控制（Recency Only 和 Random 10%）完全崩溃，无法综合全局上下文，证实了我们的索引器已经掌握了复杂的预测性时间路由。

人们可能自然会问为什么 Recency Only 和 Random 10% 在 LongBench-v2 等特定数据集上仍能保持合理的性能基线。必须重申，在 DeepSeek-V4 的混合设计中，稀疏 CSA 机制与完整的重度压缩注意力（HCA）层（128:1 压缩比）并行运行。对于主要需要全局语义主题或粗粒度综合而非有损的超细粒度 token 检索的评估场景，利用全局压缩 HCA 基础配合局部 8K 缓存就足以导航基本的上下文结构。

### 3.3 局限性与诊断

虽然 FlashMemory 在三个标准长上下文基准测试上实现了前所未有的效率提升，但我们的压力测试揭示了当前范式的关键边界。由于最近的组织架构调整，主动开发已暂停。我们展示这些诊断发现和具体失败案例，以为开源社区提供透明的洞察。

#### 3.3.1 上下文无关开销

我们最初假设，对于历史长上下文完全无关的上下文无关查询，逐点 Sigmoid 门控自然会坍缩到接近零的检索，产生严格的 $O(1)$ 恒定 KV 缓存占用。为测试这一对抗性边界，我们在 LongMemEval-S 和 LongMemEval-M 中显式添加了严格上下文无关或紧密绑定在局部 8K 窗口内的查询。

**表 2.** 在对抗性上下文无关任务（No-Context）下的系统评估。

| 上下文无关数据集 | DS-V4-Flash | FM-DS-V4（我们的方法） |
|---|---|---|
| LongMemEval-S (No-Context) | 96.7 (0.46 GB) | 95.0 (0.06 GB) |
| LongMemEval-M (No-Context) | 91.2 (1.82 GB) | 92.5 (0.16 GB) |

如表 2 所示，虽然下游精度优雅地匹配了基础基线，但模型未能保持恒定的内存开销。从 125K 上下文移动到 500K 上下文，前瞻内存分配比率确实降低到了 8.4%，但物理上的绝对块保留量膨胀了约 2.5 倍。这表明逐点 Sigmoid 门控器在超大序列长度上仍然泄漏边缘背景概率，在面对大规模干扰池时积累假阳性检索。

#### 3.3.2 稠密全局内存崩溃（MRCR 失败案例）

我们的模型在多范围上下文检索（MRCR）[6] 基准测试上经历了严重的崩溃，精度从基线的 76.0% 骤降至可怜的 48.0%。为隔离这个严重性能回归的根本原因，我们进行了严格的预言机模拟：我们为每个样本预计算了 DS-V4-Flash 在完整解码路径上的全局黄金注意力权重，按累积注意力密度排序历史块，并选择性地仅将 Top 50%、25% 或 10% 最高权重的块加载到核心 MQA 层。

我们的诊断预言机扫描揭示了基准测试之间的根本属性差异：对于 LongBench-v2、LongMemEval 和 RULER，仅保留 10% 或 25% 的黄金 CSA 块配合全局 HCA 层就完全确保了 100% 的基线精度。然而，MRCR 展现了激进的全局稠密内存依赖性——即使为索引器提供 50% 的绝对真实黄金块，精度相比完整上下文缓存执行仍然下降约 2%。

这两个实证发现坚定地隔离了我们当前记忆索引器的架构局限性。理想情况下，我们设想的理想索引器能够执行确定性的、上下文自适应的检索：在上下文无关任务上实现接近零的召回以维持恒定内存底线，同时在内存密集型任务上实现近乎完美的召回以保障最大的上下文感知。

不幸的是，由于依赖高度压缩的独立双编码器框架，模型从根本上缺乏平衡这种极端精确率和召回率操作边界的能力。因此，以下三个关键因素限制了其性能：

1. **冻结的键表示：** 由于计算预算限制，我们从未调整或优化原生 DeepSeek-V4 压缩索引器键（$K^{I}_{\text{Comp}}$），仅微调了查询投影编码器。
2. **浅层交叉交互：** 纯粹通过 64 步粗粒度点积相似度操作，索引器缺乏多轮交互能力。引入后期交互架构（例如 ColBERT 风格的 token 级交叉匹配）对于理清复杂的稠密检索模式至关重要。
3. **解耦训练隔离：** 缺乏与主骨干的端到端联合优化限制了索引器只能使用静态伪标签，忽略了实时自回归偏移动态。

解决这些问题仍然是我们的正式未来路线图。

#### 3.3.3 长度泛化天花板

我们的初始设计意图假设，由于我们的前瞻索引器通过逐点块匹配运行，我们可以在相对较短的上下文窗口（例如 128K）上训练双编码器，并无缝地将零样本推理扩展到 1M+ 上下文域，因为候选池扩展理论上不应该扭曲逐点评分。

我们的实证评估完全推翻了这一假设。索引器可以安全泛化到恰好其训练上下文长度的 2 倍。尝试超越这个硬边界执行推理会导致精度急剧下降，前瞻块选择退化为近乎随机采样。

我们将这个性能瓶颈归因于分布外位置编码的影响，这也是自注意力机制与通用文本检索系统之间的主要架构差异。因此，我们最终发布的记忆索引器明确在最长 512K 的上下文长度上训练。虽然在更大规模上的实证验证仍未测试，但我们假设当部署在超过 1M token 的序列上时，其检索判别力将不可逆地衰减。

## 4 结论

在本报告中，我们提出了 FlashMemory-DeepSeek-V4，一个增加了前瞻性稀疏注意力（LSA）的 LLM。通过将神经记忆索引器引入 DeepSeek-V4-Flash 架构，我们使模型能够主动预测并仅将查询关键的 KV 块获取到 GPU 内存中。与 DeepSeek-V4-Flash 相比，我们的模型在大多数基准测试上实现了相当甚至更优越的性能，同时仅消耗约 13.5% 的 GPU 内存。

我们强调，FlashMemory-DeepSeek-V4 的架构、训练流水线和超参数严重受限于计算资源和项目的意外暂停。索引器在冻结的键表示、浅层点积交互以及与骨干无端到端联合优化的条件下训练——这些设计选择是由资源可用性而非最优性决定的。尽管如此，在这些约束下取得的结果使我们对仍然存在的巨大改进潜力充满信心：FlashMemory-DeepSeek-V4 的当前形式仅仅是 LSA 在超长上下文智能方面所能实现的一个初步瞥见。
