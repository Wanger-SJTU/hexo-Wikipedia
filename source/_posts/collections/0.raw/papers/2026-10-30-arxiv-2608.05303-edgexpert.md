# EdgeXpert: An Edge Device for Memory-Efficient LLM Inference with Mixture-of-Experts and Speculative Decoding

**作者**：Sangwoo Ha、Hyunwoo Seo、Yurim Jo、Youngjin Moon、Hoi-Jun Yoo（韩国科学技术院 KAIST，韩国大田）

## 摘要

大语言模型（LLM）的端侧部署对个性化边缘应用已变得至关重要。主要瓶颈是前馈网络（FFN）层中的外部内存访问（EMA）。投机解码（speculative decoding）与混合专家（MoE）是两条有希望的路线：投机解码通过每个解码阶段生成多个 token 来减少解码阶段数，MoE 通过稀疏专家激活降低单阶段成本。然而这两种技术组合时存在不兼容性。我们提出 EdgeXpert，一个软硬件协同设计的 LLM 加速器来解决这一不兼容。**在 prefill 阶段**，**prompt 级专家复用（prompt-wise expert reuse）** 将路由从独立的逐 token 专家选择重构为 prompt 级的专家集合复用：它用轻量编码器识别重要 token，据此构建共享专家集，并用缩减的专家预算路由不重要 token，从而降低专家 EMA。**在 decode 阶段**，**深度感知专家合并（depth-aware expert coalescing）** 利用同深度候选 token 的上下文相似性与互斥性：不同于加载所有所需通道的并集，EdgeXpert 只加载显著通道并施加计算校准（computational calibration）来在不增加内存访问的情况下恢复精度。采用三星 28nm 工艺、800 MHz 综合，相比先前工作 [1]–[3]，EdgeXpert 实现最高 56.3% 的延迟降低与 44.1% 的能耗降低，同时保持接近基线的精度。

**关键词**：边缘设备、大语言模型、混合专家、投机解码

## I. 引言

大语言模型（LLM）[4]–[6] 正被广泛采用，人们对将其直接部署到边缘设备以获得个性化、低延迟体验的兴趣日益增长。然而端侧推理受限于内存带宽与容量。边缘 LLM 通常以单批次自回归方式推理，需要为每个输出 token 从外部内存加载全部模型参数，带来大量外部内存访问（EMA）延迟与能耗，成为系统瓶颈。如图 1 所示，权重参数的 EMA 构成最大开销，其中 FFN 层的权重 EMA 最为主导，且该开销随解码阶段数线性增长。近期工作集中于缓解长上下文场景的 KV cache 开销 [7], [8]，但端侧上下文通常较短（几十到一千 token）[9], [10]，KV cache 并非显著瓶颈。因此**权重 EMA 成为端侧 LLM 的主要开销**。对常规自回归解码 LLM，每 token 权重 EMA 定义为必须从外部内存访问的权重参数总数 Ptotal：

EMA_W, Conventional = Ptotal  (1)

先前工作 [9], [11], [12] 通过量化、剪枝、张量分解等模型压缩技术减少 Ptotal。

FFN 层的巨大计算开销推动了更高效模型的探索。MoE 模型 [13]–[18] 是缓解该挑战的有希望方案：用一个由多个较小专家网络构成的 MoE 层替换单个大 FFN 层；推理时路由器只为每个输入 token 选择少数相关专家执行。这种选择性激活在降低计算成本的同时取得更优性能。将 MoE 应用于边缘设备 [2] 直接转化为 EMA 成本与整体计算的降低。MoE 模型每 token 的权重 EMA 显著低于常规 LLM，如式 (2)，其中 S 为未激活专家数，Pexpert 为单个专家的权重参数。如 EdgeMoE [2] 与 SMoLPU [3] 所示，MoE 模型大幅降低 FFN 层推理成本，非常适合边缘设备。

EMA_W, MoE = Ptotal − S × Pexpert  (2)

近期 LLM 采用投机解码（SD）[19]–[26] 减少模型参数的重复加载：通常用一个更小、低成本的 draft 模型生成多个候选 token，再由更大的目标 LLM 单次验证；目标模型只接受通过验证的 token（accepted tokens）。SD 为每个阶段产出多个 token，从而加速解码。投机解码对边缘 LLM 设备尤其有益 [3], [27], [28]：通过减少大目标模型参数的频繁加载显著降低 EMA。带投机解码时每 token 权重 EMA 见式 (3)，NA 为每阶段平均接受 token 数（接受长度）。EAGLE-3 [25] 在 DeepSeek-R1 8B [29] 上平均每阶段生成 5 个 token，从而将模型参数加载约减少 5 倍。因此将投机解码与 MoE 结合是边缘 LLM 的 compelling 策略，具备双重优势：投机解码减少解码阶段总数，MoE 减少每阶段 FFN 层的 EMA 开销。

EMA_W, SD ≈ Ptotal / NA  (3)

然而将两者直接简单应用于边缘设备会增加 MoE 层的 EMA 开销。将 EAGLE-3 [25] 附加到 Qwen3 [14] 平均每阶段 4.3 个 token，但如图 2(a) 所示，每阶段激活 52.1 个专家，使 EMA 与计算成本增加 6.5×。两技术组合时每 token 权重 EMA 近似为式 (4)。虽然增大 NA 与 S 都有利于减小 EMA，但二者存在显著权衡：投机解码中生成更多候选 token 增加接受机会（NA↑）从而加速推理；而 MoE 模型中更多候选 token 激活更多专家（S↓）降低推理速度。因此如 [30], [31] 所指出，**投机解码与 MoE 不兼容**。

EMA_W, MoE & SD ≈ (Ptotal − S × Pexpert) / NA  (4)

图 2(b) 给出对 MoE 模型应用投机解码时的系统能耗分解。理想情形（ideal SD）下投机解码将目标模型能量摊销到多个接受 token 上，应降低总能量；但实际结果（actual SD）相反：注意力层 EMA 下降，而 MoE 层 EMA 因不兼容而上升；draft 模型还带来额外 EMA 与计算开销，使总能耗比自回归解码（AU）增加 24.3%。由于 draft 模型只有单层，目标模型主导整体开销。投机解码同时处理多个候选 token 使计算增加，但接受长度 NA 随候选数增长而饱和——任意增加候选 token 并不改善整体效率。因此在最优候选数下，MoE 层的 EMA 能耗仍是主导瓶颈（最优候选数见 II-B 节）。能量分解显示 MoE 层在两个阶段都是主要瓶颈：prefill 阶段大量 prompt token 一起处理，激活大量专家；decode 阶段 MoE 与投机解码的不兼容增加专家激活。这一结果并不意味着 MoE 与投机解码应分开使用，而是表明**必须显式解决其内存不兼容**。若解决之，二者收益互补：MoE 减少每 decode 阶段的活跃 FFN 权重，投机解码减少 decode 阶段数。

为解决 MoE 层的上述 EMA 开销，我们提出 EdgeXpert，结合软件与硬件优化实现边缘设备内存高效的 LLM 推理。在多种基准上对投机解码 [25] 与 MoE 模型 [13], [14], [32], [33] 的实验显示，相比先前工作 [1]–[3]，EdgeXpert 实现最高 56.3% 延迟降低与 44.1% 能耗降低。

**主要贡献**：
- **Prefill 阶段优化**：提出 prompt 级专家复用，将 prefill 路由视为 prompt 级专家集合构建而非独立逐 token 选择，用共享专家集在保持路由质量的同时降低 EMA。EdgeXpert 先用轻量编码器识别重要 token、从其构建共享专家集，再对不重要 token 施加预算化专家路由；分区网络还支持变长输入且延迟开销可忽略。这些技术大幅降低 prefill 阶段 MoE 层的 EMA。
- **Decode 阶段优化**：提出深度感知专家合并，降低 decode 阶段 EMA。不同于现有专家剪枝，我们的方法利用候选 token 固有的深度维互斥性，只加载必要的专家通道，实现现有剪枝策略难以达到的 EMA 降低。

## II. 背景

### A. 混合专家（MoE）

MoE 模型通过把每个输入 token 路由到一小组专门化专家（而非执行全部专家）以最小计算实现高容量。典型 MoE 层（图 3）：路由器计算各专家的选择概率；输入选 top-k 专家并对所选专家做 GEMV；每个专家输出按其路由分数缩放后聚合为最终结果。

先前 MoE 工作聚焦于降低专家加载延迟。[34], [35] 优化路由策略以提高专家命中率从而降低加载延迟，但受限于严苛的片上内存容量 [9], [11], [12]（通常只有几 MB），在边缘设备不可行。例如 DeepSeek-V2-Lite [32] 单个专家 4-bit 占 4 MB，多专家缓存与调度不现实。因此每个专家必须顺序加载，所有被路由 token 必须在加载下一专家前并行计算完成。

若干 MoE 硬件研究 [36], [37] 改善不均衡路由下的专家执行效率：Duplex [36] 用异构 xPU-PIM 架构加速内存受限 MoE 操作，通过 PIM 卸载降低内存访问成本；Space-Mate [37] 同时执行高复用与低复用专家提升 PE 利用率。这些方案改进已激活专家的服务方式，但不减少每请求激活的专家数。

### B. 投机解码

投机解码为克服自回归解码局限而生：用小 draft 模型推测未来 token 并与目标模型并行验证，在保持输出质量的同时降低整体解码延迟。

近期投机解码分三类。**第一，大小模型（big-little）[24]**：小 draft 模型低成本生成多个候选，候选并行送入更大目标模型验证。C-Transformer [11] 在边缘设备上应用此方案改善能效，但要维持高接受长度（推测精度）draft 模型必须足够大（高于某参数量），在边缘不现实。**第二，量化式投机解码 [26]**：用低比特量化模型作 draft、高精度模型验证。但在资源受限边缘设备上目标模型本就以低精度部署 [3], [9], [11]，draft 需比已量化的目标更低精度，难以实现：若目标为 4-bit，激进量化的 2-bit draft 仍占目标一半的体积，draft 自身仍产生大量 EMA，限制边缘收益。**第三，自投机解码（self-speculative）[19], [25], [30]**：在目标模型尾部附加轻量 transformer 块作 draft（图 4a）。输入先过目标模型，随后 draft 迭代生成多个候选并组织为 token 树，树作为下一轮目标模型验证的输入。由于只用一个 transformer 块迭代推测，即使边缘设备成本也很低；且推测块经微调与目标对齐，接受长度高。因此自投机解码最适合边缘设备。

图 4(b) 在相同验证模型下比较三种方法的接受长度与 EMA 能耗（每接受 token 的归一化 EMA 能耗，包含生成所有候选的 draft 模型重复 EMA 与一次验证的目标模型 EMA）。为公平起见各方法用相同 draft 大小。量化方法的 draft 无法继续压缩因此需更大 draft；大小模型方法因 draft 小接受长度低；量化方法因 2-bit 量化接受长度极短（3-bit draft 虽能提高接受长度但体积过大，2-bit draft 的 EMA 已超其他方法目标+draft 之和，总 EMA 比最高）。自投机解码以低 EMA 取得有竞争力的接受长度，最适合边缘。基于此分析，最优候选 token 数设为 **64**。

投机解码专用硬件也已出现：SpecInfer [38] 引入树注意力并行验证；EdgeLLM [27] 动态构建 token 树并在验证期间继续推测。但它们聚焦于提升接受长度或降低验证延迟，忽视了边缘场景的 EMA 开销。

### C. 相关工作

**MoE + 投机解码**。将投机解码应用于 MoE 模型收益欠佳，为此可借剪枝方案减少冗余参数。

**候选 token 剪枝**。投机解码中被错误推测的候选在验证后被丢弃，花在其上的计算完全冗余。候选 token 剪枝 [39], [40] 在验证前移除低置信度候选，但随投机解码更准其收益递减：在我们的 Qwen3 评估中，Medusa [19] 等早期框架可在 NA 退化 20% 时剪掉 74.6% 候选，而 EAGLE-3 [25], [41] 等新框架在同退化点只能剪 13.5%。因此候选 token 剪枝收益递减，已非降低推理开销的有效策略。

**专家剪枝**。近期工作 [1], [42]–[44] 表明并非所有激活专家都对输出有实质贡献，可剪除不重要专家或专家内通道。SMoLPU [3] 提出面向 MoE 投机解码的最先进剪枝框架，是本文的天然基线：其一，预测并剪除只被"预期验证后被丢弃的 token"独占激活的专家；其二，用基于输入 token 通道重要性的动态策略在每个激活专家内做细粒度通道剪枝。这种粗到细剪枝以极小精度损失移除大量参数。因 SMoLPU 已在 MoE+投机解码系统上展示有效剪枝，我们采用其为基线剪枝方案。但 SMoLPU 有两个未能解决主瓶颈的根本局限：其剪枝主要减少计算而非 EMA；只关注 decode 阶段而不考虑 prefill 阶段（用户 prompt 多个输入 token 会同时激活大量专家）。EdgeXpert 以 SMoLPU 的粗到细剪枝为基线，在两个阶段引入 EMA 感知优化解决这些未解决的瓶颈。

**MoE 与投机解码结合**。近期工作 [3], [31], [45], [46] 研究 MoE 的投机解码，表 I 总结其优化覆盖。MoESD [31] 分析 GPU 上 MoE 与投机解码的交互、通过调整批次大小与候选配置搜索高效工作点，不直接降低候选 token 引入的专家 EMA。SS-MoE [45] 用同一目标 MoE 模型、只激活 top-1 专家构建 draft 路径而非独立 draft 模型，但该自 draft 路径对边缘仍昂贵：DeepSeek-V2-Lite 的 top-1 路由仍激活约 1.3B 参数，而 EdgeXpert 使用的 EAGLE-3 draft 块只有 351M 参数 [25]；且 SS-MoE 主要减少 CPU-GPU 专家传输而非专家 EMA。MoE-Spec [46] 采用 EAGLE-3 并通过专家预算限制降低验证开销，有效限制 decode 时的专家级 EMA，但其预算路由仍未解决专家内 EMA。SMoLPU [3] 在 decode 阶段应用粗到细剪枝，但其细粒度剪枝主要减少计算，未完全转化为 EMA 降低。相比之下，EdgeXpert 同时解决 prefill 专家 EMA 与 decode 专家内 EMA，覆盖更全面的边缘部署。

## III. 动机

### A. CLS token 作为全局上下文摘要器

CLS token 是 BERT [47] 等编码器 transformer 附加在输入序列上的特殊 token，被训练为将整个输入摘要为单一表示。在视觉 transformer [48] 中 CLS 捕捉语义重要区域；在 RAG [49] 中 CLS 嵌入代表整个文档用于相似度检索。这使 CLS token 成为 token 重要性的有效轻量估计器。近期 VLM 工作如 FasterVLM [50]、HiPrune [51]、ATP-LLaVA [52] 也利用 CLS token 或注意力分数识别重要视觉 token 做剪枝。与它们不同，EdgeXpert 用 CLS token 估计输入 token 重要性，决定哪些 token 应创建或复用专家以降低专家 EMA。

### B. 候选 token 的特性

**深度维上下文相似性**。图 5 展示同一深度生成的候选 token 间的上下文相似性。候选 token 通常表示为 token 树；同深度 token 有很高概率共享语法或上下文特征。通过检查激活专家的重叠率可验证该相似性：同深度 token 中，8 个专家里有 3 个及以上共同激活的比例最高达 88.4%，与图 2(b) 一致。投机解码通过验证多个候选增加激活专家总数，但许多激活在同一深度组内重叠。因此 MoE 投机解码在增加整体专家激活的同时也创造了深度维的专家复用机会。EdgeXpert 利用这种重叠减少验证时的冗余专家 EMA。

**深度维互斥性**。除相似性外，同深度候选 token 还表现出互斥性：单个深度内验证只接受一个 token，其余被丢弃。这为硬件高效计算提供机会：对最可能被接受的 token 用精确计算，对其余候选用近似计算。

## IV. EdgeXpert：LLM 推理边缘设备

先前工作 [3] 已证明 decode 阶段可通过粗到细策略有效剪除冗余专家，我们采用该剪枝为基线。但边缘设备的主导瓶颈是 EMA 而非计算：剪枝引入稀疏性、减少计算，但不按比例减少 EMA。而且若无硬件级支持，稀疏不会直接转化为 EMA 降低——EdgeXpert 在运行时从输入 token 动态决定所需专家与通道，内存系统必须在取回不必要数据之前支持细粒度专家/通道的即时加载。这在 decode 阶段尤为重要（待加载通道集由同深度候选动态构造）。因此 EdgeXpert 采用 SW-HW 协同设计，在 EMA 发生前跳过不必要的专家/通道数据，性能超过在推理前用验证集离线决定剪枝掩码或位宽的先前软件方案 [1], [2]。

### A. 总体架构

图 6 展示总体架构：EdgeXpert 由指令译码器、顶层控制器、512 KB 全局 SRAM、SIMD 单元与八个 cluster 组成。PE 阵列含 8K MAC，与近期边缘 LLM 加速器相当 [3], [9], [11]；512 KB SRAM 足以为所提数据流缓存输入激活、路由元数据、掩码与流式权重块。由于边缘加速器通常只有几 MB 片上 SRAM 而 MoE 专家需数 MB，片上缓存复用多专家不现实，故 EdgeXpert 用 512 KB——增大 SRAM 只增加面积与功耗仍不足以常驻多专家。每个专家从外部内存取一次，片上保留至所有被路由 token 处理完毕，再被下一专家替换。数据通路适配 prefill 与 decode 的不同特性：prefill 阶段每个专家被多 token 复用，操作强度高，EdgeXpert 用广播 NoC 将同一权重同时分发到所有 cluster；decode 阶段不同输出通道分配到不同 cluster，专家沿输出通道维度从外部内存加载——由于通道剪枝沿输入通道维度进行，此加载顺序保持连续内存访问、避免碎片化 DRAM 事务。

顶层控制器协调 prompt 级专家复用与专家通道合并。Prompt 级专家复用单元（PRU）管理 prefill 路由，含分区网络、组 FIFO、并集单元与共享专家集寄存器：分区网络用三值比较器与 token 重排单元基于 CLS 注意力将输入 token 分类为重要性组；组 FIFO 与并集单元构建并更新共享专家集、为每个 token 组生成路由决策。深度感知合并单元（DCU）在 decode 阶段减少剪枝专家加载的 EMA：通道合并单元评估逐通道重要性并掩码通道；计算掩码更新单元调整通道掩码以恢复合并造成的精度损失。

Cluster 由量化/反量化单元、工作负载分配器、12KB 输入内存（IAMEM）与四个核组成。工作负载分配器通过把输入通道分配给各核，改善不均衡数据复用下的利用率。每个核含输入缓冲、12KB 权重内存（WMEM）、4KB 权重缩放因子内存（SFW_MEM）、八条 PE 线、聚合单元与非零通道索引寄存器（支持高效输入通道跳过）。每条 PE 线含 32 个 PE，通过通道跳过支持稀疏计算。PE 线沿输出通道（OCH）维度映射：权重单播到各 PE、单个输入在行内 32 个 PE 上广播；跨 PE 线沿输入通道（ICH）维度映射：只把非零输入送到对应 PE 线，有效跳过被剪通道的计算。每条 PE 线的 32 个部分积送入加法树，加法树输出在聚合单元中累加。

### B. Prompt 级专家复用

Prefill 阶段对每个 token 独立路由会激活过多专家、增加专家 EMA。为此我们提出 **prompt 级专家复用**：一种 prefill 路由策略，允许不重要 token 复用重要 token 已激活的专家，以降低 EMA。图 7(a) 展示关键直觉：重要 token（major）建立共享专家集，不重要 token（minor/trivial）优先复用该集合而非激活新专家。

EdgeXpert 先用轻量编码器 [53] 识别重要 token，其开销可忽略而显著降低专家 EMA。如图 7(b) 所示，EdgeXpert 用轻量编码器产生的 CLS 注意力权重将 token 划分为 major/minor/trivial 组，再对各组施加不同的路由预算。

**算法 1（Prompt 级专家复用策略）**：输入为 major/minor/trivial token 集（T_maj、T_min、T_tri）、各组 top-k 专家索引（I）与路由专家数 n。流程：(1) Major token 用原始预算路由 R_t^maj = I_t^maj[1:n_maj]，其专家并入共享集 E；(2) Minor token 保留 top-1 专家以维持主导路由路径，其余 n_min−1 槽位先用 reuse_route（取 I∩E 中按分数最高的专家）从 E 复用，不足时用 top_k_route（取 I\R 中分数最高的专家）补齐，所选 minor 专家并入 E；(3) Trivial token 用更新后的 E 与更激进预算 (k_tri, n_tri) 重复相同规则。约束：k_tri > k_min > k_maj = n_maj > n_min > n_tri，以增大复用、减少新激活专家。

**确定 (k, n)**：我们在 MoE 层误差（MSE）与激活专家数（R_EMA）之间搜索 Pareto 点。对每个 (k, n)，比较所提路由与原始路由的最终 MoE 层输出：

MSE(k,n) = E_{ℓ,t}[ ‖h^ori_{ℓ,t} − h^{k,n}_{ℓ,t}‖₂ / ‖h^ori_{ℓ,t}‖₂ ]，(5)

R_EMA(k,n) = Σ_ℓ |E^{k,n}_ℓ| / Σ_ℓ |E^ori_ℓ|

其中 ℓ、t 为层与 token 索引，h 为 MoE 层输出，E 为每层激活专家集大小。搜索中迭代调整：增大 k 扩大可复用专家候选，减小 n 降低激活专家数；每步选 MSE–R_EMA 的拐点（elbow）。如图 7(c)，对 trivial token 允许更激进复用：选 MSE 在 minor token 拐点 MSE 3 倍以内、R_EMA 最低的点。

**与先前路由方法的对比**。先前 MoE 路由方法 [34], [54] 把路由视为逐 token 专家选择问题、主要优化局部性与延迟；EdgeXpert 把路由视为 prompt 级专家集合构建问题，直接降低 prefill EMA，同时改善能耗与延迟。如图 7(d)，重要 token 向共享集添加新专家，不重要 token 主要复用共享集专家。我们还比较了用目标模型注意力权重估计 token 重要性的替代方案：由于因果注意力掩码本质上限制每个 token 只注意前序 token，其跨完整上下文评估重要性的能力受限；而我们的轻量编码器用双向注意力在目标模型执行前计算 token 重要性，从 prefill 一开始就抑制专家 EMA。

**分区网络硬件**（图 8a）：用并行比较器阵列将每个 token 的 CLS 注意力权重与两个阈值比较，生成三值标签；再经蝶形重排单元把输入划分为 major/minor/trivial 组。硬件每周期处理 128 个输入 token，实现为三级流水线，低延迟 token 分组。直接替代方案是按注意力权重全局排序再按秩分组，但排序设计对变长 prompt 低效：prompt 超过硬件输入宽度时需分块排序加跨块合并，延迟随输入长度快速增长；所提基于阈值的分区网络避免全局排序、独立处理每个 128-token 块，适合变长 prefill 输入。

图 8(b) 显示该方法及其硬件支持的有效性：允许不重要 token 复用共享专家集后，EdgeXpert 在 prefill 阶段降低专家 EMA 55.7%；用于重要性估计的轻量编码器引入的额外 EMA 可忽略——专家 EMA 的降低远超编码器开销。且随输入长度增加，基于阈值的设计延迟近线性扩展，而排序设计因重复排序与跨块合并延迟快速增长。

### C. 深度感知专家合并

通道级专家剪枝 [1], [3], [43] 对 MoE 压缩有效，但在投机解码下其 EMA 降低受限：多个候选 token 送入目标 MoE 模型，按各候选通道需求剪枝时，不同 token 往往选择不同通道子集（图 9a）。每个 token 只在自己的通道子集上计算，计算减少可跟随剪枝比例；但硬件必须加载服务多个 token 所需全部通道的**并集**，即使各 token 只用稀疏子集，EMA 降低也很有限。由于权重 EMA 是相对计算的主要瓶颈，需要优化。我们提出**深度感知专家合并**，把通道级稀疏转化为实际 EMA 降低。

EdgeXpert 利用候选 token 的两个关键特性降低专家加载 EMA：深度维上下文相似性（同深度 token 语义相似、倾向路由到相同专家）与互斥性（验证时每深度只接受一个 token，其余被丢弃）。如图 9(b) 所示，多个同深度 token 路由到同一专家时硬件必须加载全部所需通道的并集；验证丢弃每深度除一个外的全部 token，因此大多数被加载的通道服务于被丢弃的 token，造成冗余 EMA。因此不必保留并集全集——EdgeXpert 可在每个深度内做通道合并，只带来轻微精度损失。

图 9(c) 展示深度感知专家合并：对同深度 token 的通道，不加载并集，而是基于两个指标选择性加载显著通道：显著分数（Ss）与通道分数（Sc）。通道分数聚合所有被路由 token 的 |IA|×At（输入通道幅值 × 注意力权重）；显著分数只考虑（按通道剪枝掩码）需要在该通道上计算的 token。当通道显著分数超过 sr×Sc（sr 为选择比率，0<sr<1）时加载该通道，否则跳过以减少 EMA。

虽然通道合并大幅降低 EMA，但可能排除对特定 token 语义重要的通道，造成语义损失、降低精度与接受长度，进而限制整体 EMA 降低。为此我们在每次通道合并时执行**计算校准**：允许所有被路由 token 在合并已加载的全部通道上重计算，而非限制各 token 只用自己的剪枝子集。这样加载的显著通道更充分地跨 token 共享，降低合并引入的近似误差：即使对某 token 重要的通道被跳过，该 token 仍可从同深度其他 token 加载的显著通道获益。这会增加计算，但权衡仍然有利——因为它不需要额外内存访问。EMA 是边缘设备的主导瓶颈，额外计算既恢复精度与接受长度又维持降低的 EMA。因此深度感知专家合并降低整体系统能耗与延迟。

如图 9(d)，我们用验证后接受 token 的通道覆盖率确定 sr：对每个深度组，比较合并通道集与接受 token 原始剪枝通道集，选择使平均通道覆盖率保持 75% 以上的最大 sr，确保合并保留接受 token 所需通道。

图 10(a) 展示用于计算通道与显著分数的双可重构加法树（RAT）。候选 token 数随深度变化，常规固定加法树利用率严重不足；RAT [55] 可在单一单元内累加同深度输入、旁路其他，同时处理多个深度组，降低合并延迟。图 10(b) 显示双 RAT 相比常规双加法树将合并单元延迟降低 76.7%。RAT 相比固定加法树的额外面积与功耗影响很小，因为顶层控制器只占总面积与功耗的一小部分。图 10(b) 还显示深度感知专家合并对专家 EMA 的影响：基线只应用粗到细剪枝 [3]；通道合并减少加载专家数据量，但也降低接受长度、限制 EMA 降低；每次合并后施加计算校准则恢复接受长度，减少解码阶段数、进一步降低专家 EMA。这表明 EdgeXpert 在保持投机解码有效性的同时把通道稀疏转化为实际 EMA 降低，使 MoE 与投机解码更适合边缘部署。

> **图 9**：(a) 剪枝对 EMA 降低的局限：各 token 通道子集不同，硬件需加载并集。(b) 深度维冗余：每深度只接受一个 token，多数加载通道服务被丢弃 token。(c) 深度感知专家合并：按深度加载显著通道并集。(d) sr 对通道 EMA 与通道覆盖率的敏感性。

## V. 评估

### A. 实验设置

EdgeXpert 用 Synopsys Design Compiler 综合，目标三星 28nm FDSOI 工艺（TT, 25°C, 1.0V 典型角）。设计流程含 RTL 设计、综合、逻辑优化、综合后时序检查与 Synopsys PrimeTime 功耗分析。综合后逻辑面积按 60% 单元利用率（数字设计典型值，预留布线拥塞与时序收敛余量）折算 PnR 后面积；SRAM 宏用目标工艺的商业内存编译器建模；总芯片面积为折算逻辑面积（综合面积 ÷ 0.6）加 SRAM 宏面积。

EdgeXpert 运行于 800 MHz、1.0V，支持 8-bit 输入激活与 4-bit 权重（A8W4），峰值吞吐 13.1 TOPS（8K MAC × 800 MHz × 2 op/MAC）。硬件功耗来自综合后功耗分析，无 EMA 功耗时峰值功率 1.52 W，不利用稀疏性时峰值能效 8.6 TOPS/W。外部内存为 16 GB/s 带宽的 LPDDR4X DRAM；按 LPDDR4X 电源轨 IDD 电流与供电电压估计读写能耗为 4.5 pJ/bit 与 2.9 pJ/bit [56]。物理设计指标：综合逻辑面积 3.8 mm²，按 60% 利用率折算 6.3 mm²；SRAM 宏占 3.0 mm²；逻辑+SRAM 总面积 9.3 mm²。

EdgeXpert 用指令级自定义模拟器评估：实现所提硬件模块（路由重构、通道合并、计算校准）的行为模型；给定含专家路由信息与 token 树的原始模型 trace，行为模型仿真硬件模块行为得到最终专家/通道访问模式；随后生成运行时指令序列与内存请求，按每指令成本累计延迟与能耗。逻辑与 SRAM 的每指令成本来自综合后结果，EMA 成本由读写流量计算。片外内存由最终访问模式生成读写请求，按 16 GB/s 带宽计算延迟，能耗按数据手册参数累计。

**软件基线**：现有 MoE 硬件加速器有限，我们额外与 MoE-Pruner [1] 比较——最先进的软件剪枝方案，在每个专家内施加细粒度非结构化稀疏。我们把 MoE-Pruner 映射到支持任意跳过 [37] 的硬件加速器，使其非结构化稀疏直接降低延迟与能耗；因其面向自回归解码，同样在两种设置下评估（MoE-Pruner_AU / _SD）。MoE-Pruner 支持剪枝后可选微调，为保持一致我们禁用它。

表 I 总结的相关工作中，MoESD [31] 与 SS-MoE [45] 与我们的边缘加速器设置不可直接比较（MoESD 聚焦 GPU 级工作点分析；SS-MoE 用大型自 draft 模型，不适合边缘）；MoE-Spec [46] 验证时只做粗粒度专家预算。因此支持粗到细剪枝的 SMoLPU 是更强的剪枝基线。我们的定量比较覆盖三类代表：MoE 细粒度剪枝（MoE-Pruner）、MoE 混合精度量化（EdgeMoE）、MoE 投机解码粗到细剪枝（SMoLPU）。

所有基线归一化到与 EdgeXpert 相同的工艺（28nm CMOS）、频率（800 MHz）与外部 DRAM 带宽（16 GB/s）。SMoLPU 从原 200 MHz 缩放到 800 MHz，以把架构效率与时钟频率差异分离。EdgeMoE 原以 Jetson 板级功耗报告，我们将其混合精度执行映射到 EdgeXpert 后端（4-bit 稠密 INT MAC），保留混合精度收益、排除板级系统功耗。

### B. 实验结果

**精度与接受长度**。表 IV 展示各技术的精度与接受长度。我们逐个启用技术评估四种配置：Baseline 组合 MoE 与投机解码加先前工作 [3] 的剪枝；EdgeXpert_PR 在其上加 prompt 级专家复用；EdgeXpert_DC 进一步引入深度感知通道合并；EdgeXpert_ALL 加入包括计算校准的全部技术。Prompt 级专家复用带来可忽略的精度损失且接受长度不变；其在 MMLU、HellaSwag、ARC-Challenge、WinoGrande、PIQA 上（prefill 阶段效果可观察处）最大退化仅 1.0–3.1%，表明 major token 有效建立了共享专家集、其余 token 可主要经复用服务而无显著质量损失。深度感知通道合并降低 EMA 但显著退化精度与接受长度；加入计算校准后两指标恢复到近基线水平。最终 MT-Bench 分数下降保持在 0.1 以内，GSM8K 退化 3–4% 较大——主要因 GSM8K 在非思考推理下敏感：非思考设置中间推理步骤少，通道合并近似错误缺少恢复机会；思考模式下更长的推理链缓解该敏感性、消除额外精度下降。Qwen3 思考模式（表 IV **）下所提技术在 GSM8K 上无精度损失。

**延迟分析**。图 12(a) 显示 EdgeXpert 在多基准上的归一化端到端延迟：Baseline 为未优化的 MoE+投机解码；Pruning 应用先前工作 [3] 的粗到细专家剪枝；EdgeXpert_PR 通过 prompt 级专家复用降低 prefill 延迟——token 长度越短收益越大（prefill 占比越高）；EdgeXpert_DC 在其上加深度感知通道合并进一步降低 EMA，但通道合并也降低接受长度、限制延迟改善；计算校准恢复接受长度后（EdgeXpert_ALL）转化为大幅整体延迟降低。DeepSeek 延迟降低最大（其专家大于其他模型）。EdgeXpert 实现 10.7–61.1% 延迟降低。图 12(b) 与先前工作比较端到端延迟：Baseline 将 MoE+投机解码映射到稠密 MAC [57] 无优化；MoE-Pruner [1] 静态剪枝专家权重，可在自回归与投机解码下降延迟但静态剪枝比例有限、整体降低温和；EdgeMoE [2] 离线按重要性给专家分配混合精度，在运行时降低专家 EMA，且同时适用于自回归与投机解码，但混合精度量化只降低专家 EMA 30–35%，延迟改善有限；SMoLPU [3] 在 MoE+投机解码系统中运行时剪枝冗余专家，在三者中剪枝比例最高、延迟降低最大；EdgeXpert 在剪枝之上引入 EMA 感知路由与加载进一步降低 EMA，在所有模型上延迟最低，相比先前工作端到端延迟最高降低 56.3%。

图 12(c) 给出详细 TTFT 与 TPOT。实用边缘部署要求 TTFT < 450 ms、TPOT < 50 ms [66]。Prompt 级专家复用有效降低 TTFT（降低 prefill 专家 EMA）；深度感知专家合并降低 TPOT（选择性通道加载降低专家 EMA）。因此 EdgeXpert 是唯一在全部评估基准上同时满足两个阈值的设计。

**能耗分析**。图 13(a) 显示 EdgeXpert 归一化能耗。与延迟趋势类似，EdgeXpert_PR 在较短 token 长度下节能更多；EdgeXpert_ALL 凭借 EMA 感知路由与加载取得最大整体节能（9.5–56.6%）。图 13(b) 与先前工作比较：虽然各模型节能比例随其剪枝比例不同，EdgeXpert 在所有模型上能耗最低，相比先前工作最高节能 44.1%。图 13(c) 给出各设计能耗分解：在 MoE-Pruner 与 EdgeMoE 上，应用投机解码相比自回归解码增加 draft 开销与 MoE 层开销，但由于 MoE 层 EMA 占系统总能量更多，专家剪枝与量化在投机解码下的节能更大；投机解码还降低注意力层与其他组件（如 LM head 与 KV cache）的能耗；EdgeXpert 进一步降低 MoE 层的 EMA 与计算开销，总能耗最低。

**面积与功耗开销**。表 V 给出 EdgeXpert 面积与平均功耗。由 PRU 与 DCU 组成的顶层控制器只占总面积 14.1%、总功耗 8.6%，原因有二：一是 prompt 级专家复用每层执行一次、深度感知专家合并每专家执行一次，而 cluster 持续做 MAC；二是控制器执行与长延迟的 cluster MAC 操作重叠，功耗被摊销到长时间计算周期，延迟开销也被 MAC 摊销。PRU 中专家并集单元构建共享专家集，仅占总功耗 0.2%；其余路由决策逻辑（表中 Etc.）基于共享集选专家，只加 0.1% 功耗。DCU 中计算掩码更新单元通过把已加载通道的掩码从 0 更新为 1 支持计算校准，主要由简单多路选择器与控制逻辑组成，仅占 0.5% 总功耗。剪枝逻辑与地址生成器共占总功耗 4.6%，其中大部分来自剪枝逻辑；地址生成器为所选输入通道生成地址——虽所选输入通道可能碎片化，EdgeXpert 沿输出通道维度为每个所选输入通道取权重，避免不规则 DRAM 访问。

## VI. 讨论

**向其他框架与模型扩展**。EdgeXpert 优化的是验证阶段的目标模型而非 draft 模型，因此兼容多种投机解码框架；也适用于所有 MoE 模型，对专家粒度更细的模型、以及剪枝产生更大通道稀疏性的更大模型收益更大。

**边缘 LLM 加速器**。先前边缘 LLM 加速器主要通过量化 [9], [11]、剪枝 [67], [68] 与张量分解 [9] 做模型压缩；MECLA [12] 引入 SSMP 矩阵划分与微调方法降低内存足迹与计算。相比之下，EdgeXpert 通过 MoE+投机解码系统中的 EMA 感知专家路由与加载，同时降低 EMA 与计算。

## VII. 结论

我们提出 EdgeXpert，一个软硬件协同设计、解决投机解码与 MoE 组合造成的 EMA 瓶颈的边缘设备。我们展示了简单集成会在 prefill 与 decode 两阶段增加专家 EMA、限制 MoE 与投机解码在边缘的收益。EdgeXpert 以 prefill 阶段的 prompt 级专家复用、decode 阶段带计算校准的深度感知专家合并解决该问题。以三星 28nm 工艺 800 MHz 综合，相比先前工作 [1]–[3] 实现最高 56.3% 延迟降低与 44.1% 能耗降低，展示了面向边缘设备的 SW-HW 协同设计。

## 附录 A：工件（Artifact）说明

我们提供论文五种优化技术的软件实现：粗粒度专家剪枝、细粒度通道剪枝、prompt 级专家复用、深度感知专家合并与计算校准。全部技术实现为 PyTorch 模块，构建在四个 MoE 模型（Granite-1B-A400M、OLMoE-1B-7B、DeepSeek-V2-Lite、Qwen3-30B-A3B）的 HuggingFace 实现与 EAGLE-3 投机解码之上。单一命令行入口（run.py）运行每个模型，允许评估者逐项启用或禁用各技术。

**工件清单**：算法为粗到细剪枝、prompt 级专家复用、带计算校准的深度感知专家合并；程序为 Python；模型为四个 MoE 基模型及其 EAGLE-3 draft；环境为 Linux + conda + Python 3.13（版本固定于 requirements.txt）；硬件为 NVIDIA GPU（RTX A6000 48GB 上评估；Granite/OLMoE 1 卡，DeepSeek/Qwen 2 卡）；执行为交互式命令行，各技术用 True/False 开关切换；输出为生成的文本打印到 stdout；磁盘约需 110 GB（四个模型的权重）；工作流准备约 10 分钟（不含模型下载）；权重下载后每模型实验数分钟。公开可用，已存档于 https://doi.org/10.5281/zenodo.21481269。

**安装**：conda create -n edgexpert python=3.13 -y && conda activate edgexpert && pip install -r requirements.txt

**实验流程**：运行 `python run.py --model olmoe --coarse_pruning True --fine_pruning True --prompt_wise_expert_reuse True` 等；模型加载后打印 "write prompt:"，输入任意 prompt 生成文本。峰值 GPU 内存可用 measure_vram.py 在相同开关下测量。生成参数（--max_new_tokens、--temperature、--top_k、--top_p、--max_length、--total_token、--depth）与 GPU 选择（--gpus）可命令行覆盖。

**注意**：该工件以全精度（bf16）运行；论文报告的结果以 LLM Compressor（GPTQ，group size 32）量化的 8-bit 输入 4-bit 权重模拟。
