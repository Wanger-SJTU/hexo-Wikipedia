# Gandalf: Flash Shall Not Die! Increasing Flash Storage Lifetime for KV Cache Offloading in LLM Serving

**作者**：Maharani A. P. Irawan、Kuntai Du、Jiayi Yao、Dongjoo Seo、Yuyang Huang、Haryadi S. Gunawi、Junchen Jiang（芝加哥大学、TensorMesh Inc.、三星半导体）

## 摘要

KV caching 降低了大语言模型（LLM）的服务成本，但不断增长的 KV cache 占用已经超出 GPU 和主机内存的容量。因此，人们用 SSD 来以高 I/O 带宽扩展 KV cache 的存储容量。然而，在生产级 LLM 工作负载（如多轮对话和 LLM agents）中，KV cache 的总写入量显著超过 SSD 容量，使 SSD 寿命从数年缩短到数月。为提升 SSD 寿命，一个自然的方案是借助历史访问模式来门控（gate）KV cache 写入、减少写量。但这会显著降低 KV cache 命中率（并增加 LLM 服务成本），因为不同 attention 类型的 KV cache 可能具有相同的历史访问模式却有截然不同的未来访问模式。我们的洞见是：要在不损失 KV cache 命中率的前提下减少 KV cache 写入，不仅要考虑访问模式，还要利用应用级信息（例如 KV cache 的 attention 类型）。基于此，我们提出 Gandalf——首个具备 SSD 寿命感知的 SSD KV cache 卸载系统。Gandalf 优先将 full-attention 的 KV cache 写入 SSD，而非其他 attention 类型生成的 cache，从而在不牺牲命中率的情况下大幅延长 SSD 寿命。评估表明，Gandalf 平均将 SSD 寿命延长 7.3×，且在多种工作负载 trace 和宽泛的硬件容量范围内对 cache 命中率影响可忽略。Gandalf 的设计还可推广到其他闪存存储，如 High Bandwidth Flash（HBF）。

## 1 引言

LLM 在多轮对话和 agentic 工作流中展现出强大能力并被广泛采用。这类工作负载不断累积对话历史、工具输出和中间状态，产生越来越长且频繁复用的上下文。但每轮都重算这些上下文的 attention key-value（KV）状态会大幅增加推理延迟和成本。因此，人们将所有 KV cache 存储在系统中以避免重算、提高命中率。生产负载每天产生 TB 级 KV cache，超出 GPU 和主机内存容量，促使人们使用更大容量的存储层。基于 Flash 的存储（如 NVMe SSD）为存储这些 cache 提供了可扩展且相对廉价的层级。

但额外的容量伴随耐久性（endurance）挑战：SSD 只能承受有限的写入量。生产负载下，激进的 KV cache 准入（admission）提高命中率却产生巨大写量，使 SSD 在数天到数月内耗尽寿命。因此现有生产系统采用简单的过滤技术门控 SSD 准入，用潜在命中换取更少写入。例如基于频率（frequency-based）的方案只有在 KV cache 被复用 N 次后才卸载到 SSD。然而即使有这种过滤，累计写入量对实际 SSD 耐久性而言仍然过大。这引出核心问题：**如何在不牺牲 KV cache 性能收益的情况下延长 SSD 寿命？**

关键挑战在于预测 KV cache 的未来复用。未来难以预测，但我们发现了与应用强相关、与复用模式高度相关的属性。两个观察：（1）近期 LLM 越来越多地采用混合架构，将 full-attention 层与 linear-/sparse-attention 层结合；（2）在新兴主流负载（多轮对话与 agentic 工作流）下，不同 attention 层类型的 KV cache 复用模式差异巨大——linear- 和 sparse-attention 层的状态复用频率远低于 full-attention 层的 KV cache。

以多轮对话为例（Table 1）：每一新轮开始时，需要此前全部上下文的 full-attention KV 条目，该模式在每轮重复，因此这些 KV 条目在所有未来轮次中都被复用。相比之下，linear-attention 层的状态和滑动窗口 cache 只用于生成紧随的下一轮回复，随后即被丢弃，每个状态只被复用一次。

这种复用模式的异质性启发了 attention 类型感知的 cache 放置：把一次性的、大的 linear-attention 状态写入 SSD 带来很少的命中收益，却同时消耗写入耐久性和 cache 容量。层类型可以作为实用的放置信号。我们提出 attention 层感知放置策略：将短命的 linear-attention 状态缓存在主机内存，将长命的 full-attention KV cache 保留在 SSD。

该放置策略面临两个实践挑战。第一，策略过于刚性：CPU DRAM 与 SSD 容量固定，而负载会生成不同数量的不同 attention 状态——高并发会话可能产生超出 DRAM 容量的可复用 linear-attention 状态；长上下文负载可能产生超出 SSD 容量的可复用 full-attention KV cache。我们称之为"硬件-使用不均衡"（hardware-to-utilization imbalance）。这会迫使饱和层频繁驱逐，降低命中率；若过载发生在 SSD，写入搅动还会更快耗尽其耐久预算。因此我们设计了容量感知放置策略，基于各层利用率和压力过滤 SSD 准入，在命中率与 SSD 耐久性间取得平衡。第二，刚性放置会把命中从 DRAM 转移到 SSD，而 SSD 带宽远低于 DRAM，从 SSD 传输大的 full-attention KV cache 可能损害 TTFT。

我们用一个离线 oracle 联合优化 SSD 准入与 cache 驱逐（偏向我们的分层放置），探索 attention 类型感知放置的潜力。Oracle 揭示了两条互补的设计原则：（1）放置必须适应各层容量，有选择地将 KV cache 持久化到 SSD 以保住 prefix-hit 边界；（2）准入与驱逐必须联合优化：准入一个 cache 有成本也有收益——收益是未来复用，成本是写入成本和替换成本（替换其他条目的代价）。只有当预期复用价值超过写入成本与被驱逐条目价值之和时，SSD 准入才是有益的。

**贡献**：（1）首次揭示在生产规模的 SSD KV cache 卸载中，SSD 实际寿命显著低于出厂保证；（2）证明利用应用级信息（每个 KV cache 对象对应的 attention 类型）可以大幅减少写量、延长 SSD 寿命，而对命中率影响可忽略；（3）提出 Gandalf，平均可将 SSD 寿命延长 7.3×，且在宽泛的 LLM 和硬件容量范围内保持命中率。虽然本文只在 SSD 上演示，但该技术可推广到 HBF 等其他闪存设备。

## 2 动机

### 2.1 KV Cache 超出内存容量

多轮对话与 agentic 工作负载持续累积对话历史、中间推理、工具输出与 subagent 结果。与单轮请求不同，它们反复扩展并复用已有 prefix，使每个会话的 KV cache 占用持续增长。长上下文也让 cache miss 代价更高：可复用 prefix 未命中时必须 prefill 全部前序 token 重算 KV 状态，反复消耗稀缺 GPU 算力，推高 TTFT 与服务成本。

对两份 SemiAnalysis Claude Code 一日 trace 的分析估计，代表性混合模型每天产生 81–240 TB 的 KV cache 状态（Table 2）。峰值时并发活跃 KV cache 工作集达 8.6 TB，超出实际主机内存容量，配置足够 DRAM 代价过高，因此 cache 容量必须扩展到更大容量的本地存储。

### 2.2 为什么不用 HDD 集群？

SSD 通过 NAND flash 单元中的电荷存储数据，只能承受有限的 program/erase（写入）周期。厂商用 TBW（Terabytes Written）或保修期内 DWPD（Drive Writes Per Day）量化耐久性：容量为 C、额定 D DWPD、保修 Y 年的盘，host 写入耐久预算为 E_TBW = C × D × 365 × Y。Garbage collection 会放大写入，写放大因子 WAF = W_NAND / W_host。SSD 寿命为：

T_SSD = E_TBW / (WAF × E_workload)　（式 1）

HDD 通过磁化盘片存储数据，厂商规定年读写总量上限 RW_limit TB/年，Y 年的累计传输包络为 E_HDD = RW_limit × Y。超过 E_HDD 会导致 AFR 上升、MTBF 下降。对写入 W_host 字节、每字节平均被读 h 次的 KV cache 负载，HDD 总负载为 E_workload = (1 + h)·W_host，寿命为：

T_HDD = E_HDD / E_workload　（式 2）

与 SSD 不同，HDD 的读也算寿命。**结论**：虽然 HDD 没有 flash 磨损，但读写都消耗机械部件寿命；KV cache 负载双向流量都大，HDD 不适合。在同等聚合 I/O 带宽和 $20k TCO 预算下，只要每个写入的 KV cache 条目被复用至少 3 次，SSD 的预期寿命就超过 HDD。由于多轮对话与 agentic 负载复用频繁，同等 TCO 下 SSD 更具性价比。

### 2.3 KV Cache 正在快速杀死 SSD

在前沿模型与 agentic 负载下，即使 30 TB 企业级 SSD 也会在不到一年内耗尽额定 TBW；2 TB 盘甚至数天内耗尽（Table 2：如 Qwen3.5-27B 在 cc-traces-062126 上写入 98 TB KV cache，SSD 寿命仅 0.4 年）。我们通过减少发往 SSD 的 KV cache 写入来延长寿命。分层 KV cache 通常采用 write-through 或 write-back 卸载：write-through 立即把每个准入状态复制到 SSD，最大化多层可用性但写量大；write-back 在上层驱逐时无条件持久化，同样写入每个 DRAM 驱逐项。选择性 write-through 用固定复用阈值（如 NVIDIA Dynamo 访问频率达 2 才卸载），但仅凭频率的过滤忽略状态大小、层特定复用、层占用和剩余写入预算。

### 2.4 先前工作如何应对 SSD 耐久性？

三类方案：（1）**提高物理写耐久**：硬件供给分散写入；retention relaxation 以降低保持要求换取更多 program/erase 周期；FlashAccel 利用 KV cache 短寿命以保持换耐久。但它们都是增大写预算而非减少写入，且未利用 KV cache "可以选择不缓存、需要时重算"的独特属性。（2）**选择性 KV cache 准入与驱逐**：LRU-K 在被访问 K 次后才准入；DeepSeek-V4.1 在持久存储中为其他 KV cache 保证至少 72 小时可用性；HotPrefix、PrefixShield 用 prefix 策略驱逐冷数据；Workload-Aware 考虑复用概率、块位置与生命周期；LPC、SAECache 用学习方法预测复用；RR-evict 用轮转驱逐保证会话公平；Bidaw 从会话先前回复预测复用距离；MeritKV 在节省的 prefill 时间减去查找、传输和历史 miss 重算成本后小于阈值时才准入。但它们都不显式优化 SSD 耐久性。

### 2.5 SSD 寿命与命中率的权衡

硬件配置固定而负载需求随时间大幅变化。由于 cache 条目被同质地对待，现有方案只能在 SSD 寿命与命中率之间取舍：在 SSD 存更多条目提高命中率却快速消耗耐久预算；存更少条目延长寿命却丢失可复用状态。打破这一权衡需要识别那些消耗耐久但对未来复用贡献很小的写入。

### 2.6 关键观察：混合模型具有异质复用模式

Dense 模型所有层都是 full attention：恢复缓存上下文时 prefix 的每个 token 的 KV 条目都被复用，SSD 写入与命中率近似一一对应。混合模型打破了这一权衡：full-attention 层与 sparse attention（linear、sliding-window）层结合。如 Table 1 所示，不同层类型的缓存状态复用模式极不均匀——多轮对话等 append-only 负载下，所有 prefix token 的 full-attention KV cache 在每一后续轮都被复用，复用计数随对话增长；而每个 sparse-attention 状态通常只用一次就被更新的状态取代。把这些短命状态一律写入 SSD 是低效的：当最新 linear-attention 状态可留在 DRAM 到下一轮时，其 SSD 副本不带来额外命中，却消耗耐久与容量，还可能驱逐更可复用的 full-attention 条目。

## 3 系统概览

Gandalf 采用 DRAM（L1）+ SSD（L2）的两层存储。§3.1 介绍基于 attention 类型感知的放置策略；§3.2 用 oracle 最优近似评估该放置的潜力；§3.3 给出容量感知 cache 管理策略；§3.4 介绍降低打分开销的优化。

### 3.1 Attention 类型感知放置

混合模型产生的缓存状态大小与复用模式差异巨大：full-attention 层保留每 token 的 KV 条目（随 prefix 增长）；linear-attention 层维护固定大小的循环状态；sliding-window 层只保留最近 W 个 token，可用与 linear 相同的放置策略。在评估的模型中，单个 linear-attention 状态的占用相当于 2k–16k token 的 full-attention KV 条目。而复用只在所有类型状态在同一 prefix 边界可用时才有意义。由此产生两个决策：准入（哪些状态值得保留）与放置（放在哪一层）。我们保留 linear 状态于 DRAM、full-attention KV cache 于 SSD；某层满时驱逐该层最久未用的 cache。

### 3.2 理解潜力

建立一个独立于驱逐策略的数学模型，估计 attention 类型感知放置相对 write-back 的 SSD 寿命提升。设负载含 s 个会话，平均缓存 n 个 token、r 轮对话，full-attention 每 token 大小为 f，单个 linear 状态大小为 ℓ，则每会话 F = nf、L = rℓ。Write-back 下 SSD host 写入量为 W_write-back = s(F + L) − C（C 为 DRAM 容量）。类型感知下只有比例 p ∈ [0,1] 的 linear 状态溢出到 SSD：W_type-aware = s(F + pL)。近似寿命提升为：

I_type-aware = W_write-back / W_type-aware = s(F + L) − C / s(F + pL)　（式 3）

提升随 linear 状态相对大小增长，随溢出比例 p 增大而减小。达到上界（p=0）需要足够 DRAM 保存所有活跃 linear 状态。随会话变长，达到最大寿命提升所需的 CPU/SSD 容量比下降（Figure 5）。因此严格按类型放置并不总能高效利用两层，需要容量感知的准入门作为放置偏好（attention 类型作为复用模式代理），综合大小、类型特定预期复用、层占用与 SSD 写入成本做决策。

**Oracle 近似**。成本模型：收益——提升一个被命中 H 次的对象节省 C_r·H 的重算开销（C_r 为重算一个 KV chunk 的 GPU 租金份额）；成本——提升 s 字节的对象消耗 C_w·s（C_w 为 SSD 每字节写入对应的购买成本份额）；若准入导致驱逐剩余 H_left 次命中的对象，还需加上替换成本。目标等价于最大化命中减去写量：

max C_r·H − C_w·W ⇔ max H − H_left − λ·W，其中 λ = C_w / C_r　（式 4）

λ 表示每写入字节需要换来多少次命中才值得。**SSD 准入规则**：oracle 知道对象 i 的未来命中数 H_i，写入总成本 C_i(x_i) = (1−x_i)·H_i·C_r + x_i·C_w·s_i（式 5），取更便宜的选项。**SSD 满时驱逐**：只有当新对象收益 H_i·C_r − C_w·s_i 超过被驱逐候选的剩余命中重算成本（即 H_i − λ·s_i > H_left，H_left 为被驱逐候选的剩余命中之和）时才写入，否则丢弃新对象。

### 3.3 容量感知 KV Cache 管理

Gandalf 保持 oracle 目标（式 4），在线近似其决策。每个准入的 KV cache 先放入 DRAM（零耐久成本）。DRAM 满时，Gandalf 在"移到 SSD"与"丢弃"之间按式 6 决策：

α·move_cost_j < drop_cost_j ⇔ drop_cost_j / move_cost_j > α　（式 6）

α 为可调超参：α 越大写入越保守（更省 SSD 但更多 miss），反之亦然。

**3.3.1 丢弃 DRAM 候选的成本**：丢弃损失下次命中，成本为命中数 H_d × 需重算 chunk 数 v_d × 每 chunk GPU 成本 C_r。三个观察简化在线估计：第一，只有下一次读取重要（之后再复用会重新准入、重新决策）；linear 状态大多只读一次（Figure 6：Claude Code WEKA trace 中多数 linear 状态复用 0–1 次），因此只需预测 full-attention KV chunk 的下次复用概率。第二，回报可从历史预测：设该 chunk 的会话已空闲 a_d 个请求，回顾历史上同样空闲时长的会话中有多少"回来了"，该比例即 H_d。第三，近期需要的对象价值高：按每字节 DRAM 每请求的成本计价（式 7）：

drop_cost = H_d·v_d·C_r → h_d = H_d·v_d·C_r / (s_d·a_d)　（式 7）

**3.3.2 移到 SSD 的成本**：包含 SSD 写入成本（C_w = P_SSD / E_TBW；为达到 T_target 年目标寿命，写价按乘数 t_L 缩放——超出预算时升高、落后时降低；无目标则 t_L=1）加上替换成本（被驱逐 SSD 对象损失的剩余命中）。总 move_cost（式 8）：

move_cost = C_w·s_j + Σ_{e∈E_j} H_e·v_e·C_r / (t_L·C_w) + min_e h_e / a_j

Gandalf 驱逐 SSD 中 h_e 最低的叶节点并按最便宜者计价；SSD 有空间时不计替换成本。

### 3.4 优化

对每个驱逐都给所有 chunk 重新打分代价高昂。三个观察避免此开销：只有叶节点可被丢弃、只有根侧 DRAM 节点可移入 SSD，因此只增量维护这两个集合；式 7 的分数在请求内不变，故每层叶候选维护按概率加权丢弃分数排序的 min-heap，每个请求首次查询时重建、随后复用，新叶即时插入、过期条目从堆顶惰性丢弃；根侧 DRAM 候选按类型（linear/full）划分，每类内剩余寿命最长者 SSD 写费最低，用按剩余寿命排序的惰性堆识别。默认只比较每类一个最长命候选（评估显示不损失性能）。另一个针对 SSD 叶的惰性 min-heap 用于识别最低价值 SSD 受害者以计算替换成本。

## 4 实现

**模拟器验证**：先用 vLLM + LMCache（RawBlock 模式）跑 Claude Code trace，用 eBPF logger 采集面向存储的 trace（时间戳、读写类型、LBA、大小、页数），在 FEMU 上以 1TB @ 0.3 DWPD（5 年）SSD 配置回放，观察到 KV cache 正在杀死 SSD 的现象；再构建基于 TBW 的 trace 模拟器并与 FEMU 结果对照确认。确认技术有效后迁移到真实生产系统（vLLM 推理引擎后端部署 LMCache）。SSD 寿命估计：回放得到总写量，按日写量折算寿命。层间传输经由 CPU 作为中转（SSD→DRAM 遵循 SSD 读带宽；DRAM→GPU 遵循 PCIe 带宽）。默认假设 1 DWPD / 5 年的企业级 SSD 规格，SSD 读写带宽经 FIO 测量。**已知局限**：模拟器假设 WAF=1，可能高估所有技术（含 baseline）的寿命；但降低写量仍可降低 WAF、进一步改善寿命。

## 5 评估

### 5.1 实验设置

**Baselines**：LRU、Marconi、Workload-aware、MeritKV、HotPrefix、LRU-K。为公平，将各 baseline 扩展为 GPU HBM 之外的 DRAM+SSD 两层（保留其原准入与受害者选择规则）；有超参者做空间扫描取各 trace 最优配置。

**负载 trace**：（1）Qwen Bailian Trace A（阿里云百炼推理服务，46.4% 多轮对话）；（2）Claude Code WEKA SemiAnalysis trace（多 agent、subagent、压缩 trace）；（3）AIPerf trace（40 万请求，每会话 100 轮）。所需 DWPD 远超 SSD 额定值（Table 3：如 qwen_traceA 上 Kimi-K3 在 1TB 下需要 274 DWPD）。

**模型与容量**：主实验用 Kimi-K3（72% linear attention 层，混合 LLM 的典型比例）；DRAM cache 100 GB（低于多数 trace 峰值活跃 KV 的 1%），SSD 取 1 TB / 4 TB。

**指标**：SSD 寿命（年）、cache miss ratio、cache load latency（秒）。

### 5.2 端到端性能

在最低 miss ratio（α=0）时，Gandalf 相对最低-miss baseline 将 SSD 寿命延长：TraceA 2×、ClaudeCode 3.3×、AIPerf 6.5×（写入字节减少 2.0–6.5×）。ClaudeCode 上，miss ratio ≤ 0.47 的所有 baseline 点寿命比同等或更低 miss 的 Gandalf 短 2.9–10.3×；只有 Marconi（α≥1）和 HotPrefix（F≥7）寿命超过 Gandalf 最长点，但 miss 多 4.5–6.1×。AIPerf 上除 Marconi（α≥0.5）外所有 baseline 点短 1.0–23.8×；Marconi 长 1.3× 但 miss 多 2.2×。TraceA 上 Gandalf 在 0.839 miss ratio 下达 57.7 个月，是最长命 baseline（HotPrefix F=10，12.7 个月）的 4.1×。Cache miss ratio：Gandalf 在 TraceA 和 AIPerf 上全部策略中最低；ClaudeCode 上 Marconi（α=0）与 LRU 略低（0.045 / 0.047 vs. 0.052）但写入多 3.3×。总结：100GB DRAM + 1TB SSD 下，Gandalf 平均提升 SSD 寿命 7.3×，同时保持甚至降低 miss ratio。

### 5.3 容量比例敏感性

固定 DRAM+SSD 总容量 4TB，DRAM 从 200GB 到 1000GB 变化：Gandalf 利用额外 DRAM 将 miss ratio 从 0.75 降到 0.6，SSD 寿命稳定在 29–35 个月；baseline 几乎不受益（LRU-K miss 保持 0.785–0.791；HotPrefix 寿命虽达 33–122 个月但 miss 0.852–0.856 不可部署）。Gandalf 只写入约 0.5TB（LRU-K 约 60TB），把大部分工作集留在零磨损的 DRAM。各容量比例下 Gandalf 相对最优 baseline 改善 miss ratio 5–25%，各种场景下寿命最高延长 120×。

### 5.4 权衡超参敏感性

α 从 1 增至 64：SSD 寿命增长 TraceA 6.5×、ClaudeCode 2.3×、AIPerf 2.7×（0.4→1.2 个月），miss ratio 分别上升 0.016、0.071、0.172。α=0 时 Gandalf 在 TraceA 和 AIPerf 上同时胜过最低-miss baseline；ClaudeCode 上与 Marconi miss 差 0.007 且寿命长 3.3×。默认 α=1。

### 5.5 模型 linear-to-full 敏感性

四个混合模型（linear 状态相对 full-attention KV chunk 大小比从 Qwen3.5-27B 的 147× 到 Kimi-K3 的 1,016×）上，Gandalf 相对 LRU-K 延长寿命 3.6–6.6×，相对 HotPrefix 延长 3.6–7.1×；四个模型中三个的 miss ratio 降低 0.006–0.034（vs. LRU-K）与 0.089–0.419（vs. HotPrefix）。比值越大，写入永不复用的 linear 状态的惩罚越高，Gandalf 的过滤收益越大。

### 5.6 提升来自哪里？

- **避免写入不复用的 linear 状态**：LRU-K（K=1）写入 120.6k 个 linear 状态，仅 21% 在 SSD 被命中（43% 不再被请求，45% 在写入前已在 DRAM 完成唯一命中）。K=2 时写入减少 1.9×（62.6k），但 90% 写入前已命中、58% 不再被请求、仅 13% 在 SSD 命中，且 miss 从 0.1 升到 0.14。Gandalf 按"将来是否复用"决策：linear 状态写入减少 8.8×，57% 在 SSD 命中。
- **避免写入少复用的 full-attention KV**：Gandalf 写入的 full-attention chunk 比 LRU-K（K=1）少 33%（21.5M vs. 32.1M），SSD 命中率 61% vs. 50%；"永不复用"chunk 少写 2.7×（1.1M vs. 3.1M）；每 chunk 命中 12.3 次 vs. 7.0；总写入 92TB vs. 153TB，寿命延长 1.7×（98 vs. 59 天），miss 相近（0.099 vs. 0.098）。
- **Attention 类型感知放置**：Gandalf 87% 的 full-attention 命中来自 SSD、90% 的 linear 命中来自 DRAM；LRU-K 分别为 74% 与 67%，且为从 SSD 服务 33% 的 linear 命中需要每命中 4.5 次写入（Gandalf 1.7 次）。

### 5.7 与各 baseline 的对比（TraceA 2 小时片段）

- **Write-back 类（LRU、Workload-aware、Marconi）**：linear 状态占其写入字节 96%，但仅 1.6–8.5% 在 SSD 被命中。Gandalf 写 25 个 linear 状态（LRU 为 90k），full-attention 字节少 3.2×（0.53 vs. 1.70TB），总写入少 73×（0.58 vs. 42.2TB），寿命长 73×（253 vs. 3.5 天）。α=0 时 Gandalf miss 最低（0.603）且寿命仍比 LRU 长 1.4×。
- **MeritKV**：无条件准入每个对象的前 3 次请求以学习复用，97% 写入的 linear 状态写入前从未命中；写入 36.1TB（4.0 天）。
- **HotPrefix**：F=1 时写入 4.4TB、寿命 33 天，但 miss 0.802；Gandalf（α=1）寿命长 7.6×、miss 仅高 0.016。F=10 时寿命 388 天但 miss 0.839。
- **LRU-K**：K=3 时写入 6.8TB、寿命 21.5 天、miss 0.750；Gandalf（α=1）寿命长 11.8×、miss 高 0.068。
- **放弃的命中**：α=1 时 Gandalf 在 TraceA 的 miss（0.818）高于 LRU（0.697），换取 SSD 寿命 73×；更小的 α 可换回命中（§5.4）。

### 5.8 Cache load latency 影响

以传输时间与重算时间的最大值近似请求的 cache load latency（SSD→DRAM 10GB/s，→GPU 50GB/s，重算 60k tokens/s）。ClaudeCode + Kimi-K3：最低延迟 baseline（Marconi α=0、LRU）0.66s、寿命 4 个月；Gandalf（α=1）寿命长 4.2×（17.0 个月）而延迟仅高 0.12s（0.78s）。相近延迟下 Gandalf 比 LRU-K（K=2）寿命长 3.7×；α=64 时比 LRU-K（K=3）寿命长 5.3× 且加载更快。计入 SSD 磨损成本后（重算 GPU 成本 + SSD 价格份额）：LRU、Marconi、LRU-K 的成本 66–86% 来自 SSD 磨损；最便宜 baseline（LRU-K K=2）为 $0.74/千请求；Gandalf（α=1）仅 $0.30/千请求（2.5× 更省）——重算略多（$0.13 vs. $0.11）但磨损低 3.0×（$0.16 vs. $0.49–0.73）。

### 5.9 优化不带来负面影响

Move door（§3.4）每 slot 大小只检查最长命 DRAM 条目。允许每 slot 大小检查至多 64 个候选（Kimi-K3，100GB DRAM，1TB SSD，α=1）：miss ratio 不变（TraceA 0.823、AIPerf 0.036）；TraceA 上 SSD 写入仅增 1.4%（501→508 GiB）、寿命 271→268 天；AIPerf 结果完全相同。单候选检查不损失命中。

## 6 相关工作

**分层 KV cache 系统**：CachedAttention、FlashGen、LMCache、Mooncake 用主机 DRAM/SSD/分布式存储扩展 GPU 内存；TENURE 等研究跨层放置；InfiniGen、Tutti 降低下层访问开销。这些系统主要优化容量、延迟或吞吐，而非 SSD 耐久。**KV 准入、驱逐与压缩**：前述策略从 prefix 结构、新近性、频率、语义、排队需求或负载历史预测复用；MeritKV、Bidaw、LRU-K、NVIDIA KVBM 引入复用效用、存储成本或写感知；正交技术通过 token 驱逐、量化或 KV 压缩减小占用。多数未用 attention 类型复用异质性与显式耐久成本联合管理 DRAM 放置、SSD 准入与驱逐。**Flash 感知缓存与存储**：Flashield 等通用 flash cache 通过准入过滤与写速控制磨损；FlashAccel、HiFC、HBFlex 优化 flash 数据路径——它们与 Gandalf 互补，因为不使用 attention 语义为单个 KV 状态估值。**寿命感知 KV 放置**：最接近的 Lachesis 依据 agent harness 推断的寿命在 HBM 与高带宽 flash 间放置 agent KV 段；Gandalf 面向主机 DRAM 与 SSD、从混合 attention 语义导出复用差异（无需 harness 信息），并联合考虑容量、重算收益与 SSD 写入成本。

## 7 结论

本文提出 Gandalf——一个基于 SSD 的 KV cache 卸载系统，利用每个 KV cache 对象关联的 attention 类型预测其未来复用可能性。Gandalf 将短命的 linear-attention 状态保留在 DRAM，把高复用潜力的 full-attention KV cache 卸载到 SSD，其放置策略权衡每次 SSD 写入的预期命中与设备磨损。通过基于复用潜力与磨损成本的写入过滤，Gandalf 在延长 SSD 寿命的同时保持命中率。在多种混合模型与硬件容量下，Gandalf 相对最优 baseline 将 SSD 寿命延长 2–7.3×。我们希望 Gandalf 能促使未来的 KV cache 系统不仅考虑 SSD 卸载的性能收益，也考虑每次写入造成的磨损。
