## 摘要（全文翻译）

混合专家（Mixture-of-Experts, MoE）模型通过稀疏专家激活在保持单 token 计算量有界的同时大幅扩展模型容量，从而获得强大质量。然而低延迟 MoE 服务正变得越来越困难，因为它横跨两个瓶颈本质不同的推理阶段：**prefill 由逐 token 的专家计算主导，decode 则受限于按批（batch-wise）激活专家集合带来的内存流量**。但现有免训练加速方法只优化单一资源代理——要么优化每个 token 执行的专家，要么优化整个 batch 激活的专家——而且对被排除专家的贡献要么直接丢弃、要么只做隐式近似。

本文提出 ExFold，一个统一的免训练专家折叠（expert folding）框架，用于联合加速 MoE 的 prefill 与 decode。ExFold 把 prefill 和 decode 统一建模为**同一个带预算约束的输出逼近问题**：只执行阶段特定的受约束专家集合，同时用校准的标量投影器（scalar projector）把预算外专家的贡献投影到保留专家上。基于"许多专家输出方向对齐、只是幅度不同"这一观察，ExFold 在无标注数据上校准一个成对（pairwise）标量投影矩阵，并在推理时用它把被排除专家的贡献折叠进保留专家。在这一视角下，prefill 加速成为**token 级 Top-K 折叠**，decode 加速成为**batch 级专家池折叠**。两个阶段只在保留专家的选取方式上不同，被排除的贡献由同一个共享折叠机制恢复。

我们把 ExFold 实现为 vLLM 中的即插即用插件，配套轻量级 expert-folding CUDA kernel，实现最高 **1.41× TTFT** 与 **2.45× TPOT** 加速，同时保留原模型约 **99%** 的平均质量。

## 一、引言

MoE 通过每个 token 只激活稀疏参数子集，在计算预算有界的前提下把模型参数扩大数个量级。这一特性使 MoE 成为近期许多大模型追求更高能力的主流选择（Mixtral、Qwen3、GLM 等）。与此同时，它对生产环境的低延迟服务提出了苛刻要求：prefill 延迟（首 token 时间，TTFT）与 decode 延迟（每输出 token 时间，TPOT）都重要，且二者呈现截然不同的计算特性。如图 1 所示，**prefill 由 token 级专家计算主导，decode 由 batch 级专家内存流量主导**。

现有免训练 MoE 加速方法按所优化的预算分为两族：

- **Token 级专家稀疏化**：减少每个 token 执行的专家数，包括 Dynamic-MoE、MoDES、NAEE、MC-MoE 等；
- **专家集合整合**：缩小活跃专家集合，包括静态剪枝与合并（REAP、HC-SMoE、Sub-MoE），以及动态 batch 级限制（Lynx、SERE）。

然而两族方法都把加速框定为"资源削减"问题：它们只回答**执行哪些专家**，而未回答更难的问题——**被砍掉的专家怎么办**。它们对被排除贡献的处理至多是顺带的：剪枝与跳过直接丢弃；静态合并把贡献固化进一个永久压缩、无法再适配推理时实际面对的逐 token/逐 batch 预算的模型；基于相似度的重路由只是换一个近邻专家，从不校准替代者的输出偏离原贡献多远。被排除的专家质量"丢失、冻结或仅被隐式近似"，从不被显式重建——因此当预算最紧、这些方法被压榨得最狠时，逼近误差最大。

我们提出**专家折叠（Expert Folding）**：把每一个预算外专家的贡献投影到一个实际执行的专家上，而非丢弃，并围绕它构建 ExFold。该设计基于两个经验观察（图 3）：许多源专家至少存在一个输出方向对齐的目标专家；而各专家的输出幅度差异巨大。前者使专家替换成为可能，后者解释了为什么直接重路由不够，并促使我们引入一个**有向标量投影器**来纠正源-目标间的尺度失配。具体而言，只需在无标注文本上做一次冻结前向传播，即可校准两个逐层矩阵——**标量投影矩阵**与**投影损失矩阵**：推理时，损失矩阵把每个被排除专家路由到其最小损失目标，标量矩阵把每个被排除贡献折叠进该目标专家的路由权重。

由于折叠定义在单个被排除专家的粒度上，它在两个阶段中完全通用：prefill 为每个 token 选 K_pre 个主导专家，decode 为每个 batch 选 D 个主导专家——两者复用同一个标量矩阵、损失矩阵和折叠算子来恢复保留集之外的贡献。**两个阶段只在保留专家的选取方式上不同，被排除的贡献由一个共享机制恢复**——这是 ExFold 的核心设计。

我们在 vLLM 中将 ExFold 实现为即插即用插件，配套轻量 expert-folding CUDA kernel，实现最高 1.41× TTFT、2.45× TPOT 加速，保留约 99% 原始平均质量。贡献如下：

1. **阶段感知的问题形式化**：刻画 prefill 与 decode 各自不同的专家预算，并把二者统一为阶段特定选择约束下的单一输出逼近问题；
2. **专家折叠**：提出免训练折叠机制，用方向投影器 + 重建损失矩阵把预算外专家贡献投影到保留专家，其标量形式可直接吸收进路由器权重；
3. **评测**：在真实 vLLM 服务负载上，跨多个 MoE 架构验证近无损的 prefill、decode 及联合加速。

图 2 展示了 ExFold prefill（ExFold-P4 相对 Baseline 最高 1.41× TTFT、质量保留约 100%，显著优于 TopK=4、MC-MoE-K4、MoDES-K4）与 decode（ExFold-D64/D32 相对 Baseline 最高约 2.45× TPOT，优于 Top-K、REAP-D32、SERE-K2）的质量-速度权衡曲线。

## 二、背景与动机

### 2.1 MoE 推理

**稀疏 MoE 层**。稀疏 MoE 层把 Transformer 块的稠密 FFN 替换为 N 个门控 FFN 专家和一个路由器。对维度为 d 的隐状态 x，专家 e 计算：

$$E^{(e)}(x) = W_{\text{down}}^{(e)}\,\varphi\!\left(W_{\text{gate}}^{(e)} x\right) \odot \left(W_{\text{up}}^{(e)} x\right) \tag{1}$$

其中 φ 通常为 SiLU，⊙ 为逐元素乘。路由器产生 logits $r(x) = W_r x$，选出 Top-K 集合 $S_K(x)$，并在其内部归一化门控权重：

$$\alpha_e(x) = \frac{\exp(r_e(x))}{\sum_{j\in S_K(x)}\exp(r_j(x))},\quad e\in S_K(x) \tag{2}$$

MoE 输出为：

$$\text{MoE}(x) = \sum_{e\in S_K(x)} \alpha_e(x) E^{(e)}(x) \tag{3}$$

可能还带有额外的共享专家。这一计算使 FFN 路径对每个 token 稀疏，但也引入了动态路由、专家分发与专家输出聚合的开销。

**阶段特定预算**。虽然同一个 MoE 层（式 3）在两个阶段都运行，但其瓶颈随 token batch 的形状而转移（图 1）。Prefill 一次处理 T 个 token 的 prompt，每个 token 独立激活自己的支持集 $S_K(x)$，因此该层执行 O(TK) 次专家 FFN 计算。当 T 很大时，每个被加载的专家被许多 token 复用，权重加载成本被摊销，该阶段是**算力受限**的，成本由逐 token 专家 FLOPs 主导——减小 K 直接削减成本。Decode 每步为 B 个 batch 内请求各推进一个 token，只发出 B 个 token，但它们的支持集之并 $\bigcup_x S_K(x)$ 通常覆盖大部分 N 个专家。该层因此必须为极少量 token 加载这一 batch 级专家并集，算术强度低，阶段是**访存受限**的，成本与激活的不同专家数量而非 FLOPs 成正比。因此高效服务由两种不同预算支配：**prefill 的每 token 专家数**与 **decode 的每 batch 专家数**。

### 2.2 MoE 加速方法

按优化的预算划分，现有免训练 MoE 加速方法分两族：

**Token 级专家稀疏化**。减少每个 token 执行的专家数。Dynamic-MoE 让累计路由概率超过 p 的最小专家集来服务 token，越容易的 token 用越少专家；MoDES 按校准估计的重要性逐 token 跳过专家；NAEE 依据路由或激活统计剪掉低重要性执行；MC-MoE 合并校准中发现的共激活专家。这些方法缓解 prefill 计算预算，但**放任 decode 时的专家并集不受控**。

**专家集合整合**。缩小活跃专家集合。静态方法从校准信号给每个专家打分并永久缩减全局池：REAP 按路由权重与激活范数剪掉最不重要的专家；HC-SMoE、REAM、Sub-MoE 合并相似专家。动态方法限制一个 decode batch 内的专家并集：Lynx 把次要请求重路由到已激活专家；SERE 离线校准成对专家相似度，decode 时用相似的保留专家替换被排除专家。这些方法缓解 decode 侧流量，但**其静态变换不匹配逐 token 的 prefill 预算**。

**缺口**。两族方法都决定执行哪些专家，但都不保留被排除专家的贡献：剪枝丢弃它，静态合并把它固化进永久压缩的模型，相似度重路由改变专家去向却不校准替代者偏离多远。随预算收紧，误差在每个阶段内增长，并在 prefill 与 decode 之间复合——因为二者是相对两个不同目标而非一个共享目标做逼近。

## 三、设计洞察

> **关键问题**：如何设计一个统一框架，以最小损失加速 MoE 模型的 prefill 与 decode？

这一缺口使得恢复看起来两面都难——prefill 与 decode 拉向互相冲突的预算，而忠实恢复每个被排除专家似乎要么需要重算、要么需要盲目替换。然而两个观察化解了这两个困难。

### 观察一：被排除的贡献共享同一个恢复目标

Prefill 与 decode 受不同预算约束——每 token 专家数 vs 每 batch 专家数——但无论预算排除了哪些专家，留下的残差在 MoE 输出（式 3）中的形式完全相同：$\alpha_e(x)E^{(e)}(x)$。因此两个阶段提出的是**同一个问题**——从保留专家重建被排除贡献——差异只在选择保留集的约束，而不在需要恢复什么。

### 观察二：专家冗余在幅度上可分

图 3 显示专家间冗余集中在一个可以廉价纠正的自由度——**输出尺度**。在两分量 PCA 投影（a）中，原始专家输出形成弥散云团，但把每个输出归一化到单位尺度后，它们塌缩到一条细窄的共享轴上：去掉尺度后，专家方向几乎一致。成对相似度证实了这一点——归一化把第 5 层的平均专家间相似度从 0.335 提升到 0.529，第 17 层从 0.251 提升到 0.471（b），且同样的差距贯穿全部 48 层（c），说明这种对齐是结构性的而非个别层的偶然现象。但被丢弃的尺度很大：一层内原始输出范数跨度超过 3×（图中两层 max/min 分别为 3.04× 与 3.27×，d）。因此被排除专家与保留专家之间的失配几乎纯是径向的——方向已经兼容，只是幅度不对。一个逐对的标量去缩放保留专家的输出——而非重建向量或盲目替换——即可约束替代者的偏离程度，使忠实恢复在原理上是廉价的。（全层可视化见附录 D。）

两者结合，对关键问题给出肯定回答：一个共享的恢复目标，通过廉价的逐对标量纠正即可到达，并跨两个阶段复用；每个阶段只改变保留集的选取方式。ExFold 在下一节把它变成具体机制。

## 四、方法

图 4 给出 ExFold 总览：(1) 离线校准——在冻结 MoE 模型上用 32 条序列 × 4096 token 的校准集，对每个共路由的有序源-目标对收集输出 $v_i = E_t(x_i)$、$u_i = E_s(x_i)$，按 $w_i = \|u_i\|^2$ 加权，闭式求解有向标量 $s^*_{s\to t}$ 与投影损失 $L^*_{s\to t}$；(2) Prefill：token 级折叠——按 $w_i \cdot h_i$ 选 Top-K′ 主导专家，剪掉其余并把权重折叠进目标；(3) Decode：batch 级折叠——把整批专家并集压缩到 D′ ≤ D 个专家后送入 FusedMoE kernel。

### 4.1 统一专家折叠

ExFold 把 MoE 加速视为**受约束的输出逼近**，而非阶段特定的专家丢弃。设 $x_i$ 为第 i 个输入 token，$S_K(x_i)$ 为其原始 Top-K 支持集。把路由权重扩展为 $\alpha_e(x_i) = 0\ (\forall e\notin S_K(x_i))$。在阶段 $\phi\in\{\text{pre},\text{dec}\}$ 下，$B_\phi(x_i)$ 表示保留目标集，$O_\phi(x_i) = S_K(x_i)\setminus B_\phi(x_i)$ 表示被省略的源专家。用 $E_s$ 表示被省略的源专家，$E_t$ 表示其保留目标，$t = \pi_\phi(s, x_i)\in B_\phi(x_i)$。

设 $s^\star_{s\to t}$ 为有向标量投影器，使 $E_s(x_i) \approx s^\star_{s\to t} E_t(x_i)$，记 $t_s = \pi_\phi(s,x_i)$ 为源 s 被指派的目标。逼近后的 MoE 输出把保留贡献与被省略专家的投影贡献分开：

$$\hat{y}_\phi(x_i) = \underbrace{\sum_{t\in S_K(x_i)\cap B_\phi(x_i)} \alpha_t(x_i) E_t(x_i)}_{\text{retained（保留）}} + \underbrace{\sum_{s\in O_\phi(x_i)} \alpha_s(x_i)\, s^\star_{s\to t_s}\, E_{t_s}(x_i)}_{\text{folded（折叠）}} \tag{4}$$

如此，被省略专家不被执行，但其校准后的贡献仍留在 MoE 输出中。折叠进同一目标的路由在专家计算前合并，因此每个保留目标只计算一次。与静态专家合并不同，折叠既不改动专家参数、也不改动原始路由器。

对在同一层一起处理的 token 集 $X_\phi$，两个阶段共享同一目标：

$$\min_{B_\phi,\,\pi_\phi,\,S}\ \sum_{x_i\in X_\phi} \|\text{MoE}(x_i) - \hat{y}_\phi(x_i)\|_2^2 \quad \text{s.t. } c_\phi(B_\phi)\le\tau_\phi \tag{5}$$

其中 $S = [s^\star_{s\to t}]$ 是标量投影表。Prefill 成本按每 token 保留专家计数，decode 成本按 batch 内保留的不同专家计数。我们接下来一次性校准 S，然后用同一条折叠规则求解两个预算约束。

### 4.2 免训练投影器校准

图 4 上半部分总结离线校准。对每个有序的共路由源-目标对 (s, t)，收集其在 m 个校准 token 上的输出：

$$u_i = E_s(x_i),\quad v_i = E_t(x_i),\quad i=1,\dots,m \tag{6}$$

其中 $u_i, v_i\in\mathbb{R}^d$，主方法中每个 token 按 $w_i=\|u_i\|^2$ 加权。给定投影器族 $\mathcal{P}$，校准求解加权输出重建问题：

$$P^\star_{s\to t} = \arg\min_{P\in\mathcal{P}} \sum_{i=1}^m w_i\|u_i - v_i P\|_2^2 + \lambda\,\Omega(P) \tag{7}$$

其中 Ω 正则化所选投影器族的参数。对标量参数化 $P = sI$，闭式解为：

$$s^\star_{s\to t} = \frac{\sum_{i=1}^m w_i\langle v_i, u_i\rangle}{\sum_{i=1}^m w_i\|v_i\|_2^2 + \lambda} \tag{8}$$

除标量形式外，我们还在消融（表 3）中评估了对角投影器和"标量+低秩"投影器。部署方法采用标量解，因为它可以折叠进路由器权重而不需要在线向量变换。（这些替代方案的参数化与闭式校准详见附录 B。）

最后，把标量迁移误差存为：

$$\ell_{s\to t} = \frac{\sum_{i=1}^m w_i\|u_i - s^\star_{s\to t} v_i\|_2^2}{\sum_{i=1}^m w_i\|u_i\|_2^2} \tag{9}$$

校准因此为每个 MoE 层返回一张有向标量表 $S^{(l)} = [s^\star_{s\to t}]$ 和一张损失表 $L^{(l)} = [\ell_{s\to t}]$——全程无标签、无梯度、无模型更新。详细设置、矩阵与收集结果见附录 A 与 D。

### 4.3 阶段特定选择与统一折叠

推理时，prefill 与 decode 使用阶段特定的保留专家选择器，但共享同一迁移准则与折叠算子（由校准的标量表 $S^{(l)}$ 与损失表 $L^{(l)}$ 参数化）。下面省略层索引，记路由权重 $w_{i,e} = \alpha_e(x_i)$，用 $h_e$ 表示专家 e 缓存的输出范数估计。

**第 1 步：选择阶段特定的主导专家。** Prefill 为每个 token 独立选 K_pre 个主导专家；decode 为当前 batch $X_q$ 选一个至多 D 个专家的共享集合：

$$B_{\text{pre}}(x_i) = \operatorname{TopK}_{e\in S_K(x_i)}\left(w_{i,e}\, h_e,\ K_{\text{pre}}\right) \tag{10}$$

$$B_{\text{dec}}(X_q) = \operatorname{TopK}_{e\in\bigcup_i S_K(x_i)}\left(\sum_{x_i\in X_q} w_{i,e}\, h_e,\ D\right) \tag{11}$$

分数 $w_{i,e} h_e$ 估计每条路由贡献的幅度。Prefill 在局部应用它以减少 token 级计算；decode 跨 token 聚合以减少 batch 级专家并集。

**第 2 步：选择最小损失迁移。** 任一阶段中，每个被省略的源专家 $E_s$ 选校准重建损失最小的保留目标：

$$\pi_\phi(s) = \arg\min_{t\in B_\phi}\ \ell_{s\to t} \tag{12}$$

其中 $B_\phi$ 是 token 级集合 $B_{\text{pre}}(x_i)$ 或 batch 级集合 $B_{\text{dec}}(X_q)$。两个阶段因此共享同一损失查找表，差别只在候选目标集。

**第 3 步：折叠路由器元数据。** 记 $S_{s\to t} = s^\star_{s\to t}$ 为标量表查找。Prefill 中，映射到同一目标的被省略路由通过更新目标权重合并：

$$\tilde{w}_{i,t} = w_{i,t} + \sum_{\substack{s\in S_K(x_i)\setminus B_{\text{pre}}(x_i)\\ \pi_{\text{pre}}(s)=t}} w_{i,s}\, S_{s\to t},\quad t\in B_{\text{pre}}(x_i) \tag{13}$$

FusedMoE kernel 因此只需执行 K_pre 条路由。Decode 中，每条被省略路由就地重映射：

$$(E_s,\ w_{i,s}) \longmapsto \left(E_{\pi_{\text{dec}}(s)},\ w_{i,s}\, S_{s\to\pi_{\text{dec}}(s)}\right) \tag{14}$$

保留路由不变，而每条重映射专家都属于 $B_{\text{dec}}(X_q)$；因此 batch 至多触及 D 个不同专家，且不改变常规 Top-K 路由布局。两种变换都只修改现有 FusedMoE kernel 之前的路由器元数据。

## 五、实验

### 5.1 实验设置

**模型**。以 Qwen3-30B-A3B（48 层、128 路由专家、Top-8）为主模型，并在 GLM-4.5-Air（45 个 MoE 层、128 专家、Top-8、1 共享专家）、DeepSeek-V2-Lite-Chat（26 MoE 层、64 专家、Top-6、2 共享专家）与 Qwen3.5-35B-A3B（40 层、256 专家、Top-8）上验证跨架构泛化。附录 C 给出完整结果。

**基准**。数学推理用 MATH500、AIME24；代码生成用 LiveCodeBenchV5（LCB）、HumanEval+（Eval+）；指令遵循用 IFEval、IFBench；知识推理用 GPQA-Diamond、MMLU-Pro。效率方面，报告 prefill 主导服务下的 TTFT、生成主导服务下的 TPOT，以及 vLLM 离线吞吐。

**基线**。Prefill 对比相同 token 级专家预算下的直接 Top-K 削减、MC-MoE、MoDES；decode 对比静态专家剪枝（REAP）与动态专家跳过（SERE）。分别报告仅 prefill、仅 decode 与联合加速，以区分单阶段质量损失与跨相位误差累积。

**超参数**。在 32 条至多 4096 token 的无标注序列上校准，使用源输出范数加权，岭系数 λ=10⁻³。PX 表示 prefill 每 token 保留 X 个专家，DX 表示 decode 每 batch 至多 X 个活跃专家。ExFold 以自定义 Triton 算子实现在 vLLM 中，效率实验在 NVIDIA H800 GPU 上以 BF16 运行（完整校准、硬件与服务配置见附录 A）。

### 5.2 主质量结果

**表 1（Qwen3-30B-A3B 质量）**关键数字：

| 方法 | Prefill | Decode | 平均分 |
|---|---|---|---|
| Original TopK=8 | 100% | 100% | 69.04 |
| Prefill TopK=4 | 50% | 100% | 66.64 |
| MC-MoE-P4 | 50% | 100% | 65.44 |
| MoDES-P4 | 50% | 100% | 66.59 |
| **ExFold-P4** | 50% | 100% | **69.26** |
| REAP-D64 | 100% | 50% | 61.50 |
| REAP-D32 | 100% | 25% | 22.25 |
| SERE-K4 | 100% | 动态S=4 | 64.15 |
| **ExFold-D64** | 100% | 50% | **68.75** |
| **ExFold-D32** | 100% | 25% | **68.97** |
| All TopK=4 | 50% | 50% | 56.17 |
| **ExFold P4+D64** | 50% | 50% | **68.50** |
| ExFold P4+D32 | 50% | 25% | 67.10 |

**仅 prefill 加速**。在 P4 预算下，ExFold 保留原始 Qwen3 平均分并超越所有算力对齐基线（69.26 对 Direct Top-4 的 66.64）。增益在指令遵循与代码生成上最明显——硬丢弃会损失重要的被路由贡献。因此折叠可以在不产生直接稀疏化质量损失的前提下，把 prefill 专家计算砍半。

**仅 decode 加速**。ExFold 的优势随 batch 级专家预算收紧而扩大。在 D32 下它与原模型差距仅 0.07 分；SERE-K2 部分恢复静态剪枝损失的质量但仍显著更低。这一趋势表明，当活跃专家池被激进约束时，恢复被省略专家贡献变得更加重要。

**Prefill+decode 联合加速**。对两个阶段都施加 Direct Top-4 会使逼近误差复合，平均分降到 56.17；而 ExFold P4+D64 仍保留 68.50。ExFold 在两阶段都加速时也强于 MoDES。共享投影器因此避免了两个独立丢弃误差的叠加，并在同一个逼近目标下同时支持两种阶段预算。

**跨架构泛化**。GLM-4.5-Air 上（表 2），ExFold 在仅 prefill P4 与仅 decode D64 下分别保留原平均分的 97.2% 与 98.4%；两阶段同时压缩时 P4+D32 仍保留 96.7%。DeepSeek-V2-Lite 与 Qwen3.5 的额外结果见附录 C，确认 ExFold 在主模型之外也保持质量。

### 5.3 校准与选择消融

**校准语料（表 4）**。仅改变校准域：MATH / GPQA / CODE / PRETRAIN / MIXED。MIXED 平均最佳（73.00），但所有域差距不超过 1.9 分，且任务匹配数据并不总最优。这说明校准捕获的是专家几何结构而非基准特定行为——**不需要任务特定校准**。

**保留专家选择准则（表 5）**。在固定预算下比较路由分数 $S_i$、输出幅度 $H_i$ 及其乘积。路由分数忽略输出规模，幅度单独忽略路由相关性；乘积近似贡献幅度，在两个阶段都给出最佳平均分。因此按 $S_i\times H_i$ 排序保留专家。

**投影器族（表 3）**。同一 Top-4 预算下比较：成对标量（仅 6 MiB 状态、可用 FusedMoE 融合 kernel）在 7 项指标中 6 项优于全局标量（4 B）、层标量（192 B）；对角投影器（316.7 MiB、需 unfused）虽降低困惑度但下游表现不稳；低秩 R8/R16 额外需要 2.44–4.87 GiB 状态且无一致收益。**成对标量是最佳权衡**。

### 5.4 效率评估

**在线 prefill 延迟（图 5a）**。减少 token 级专家计算直接转化为更低 TTFT：ExFold 在 8 QPS 下达到 1.41× 加速，与算力对齐的 Top-4 方法几乎重合——标量折叠开销极小。不同之处在于它在获得计算收益的同时保住了模型质量。

**在线 decode 延迟（图 5b）**。decode 呈现不同的扩展趋势：逐 token 的 Top-4/Top-6 随 QPS 增大失去收益，因为 batch 激活了更广的专家并集。通过约束 batch 级专家并集，ExFold 在 8 QPS 达到 2.45× TPOT 加速，并在 12 QPS 内维持约 2.4×。这证实：**减少 batch 级权重流量（而不仅是逐 token FLOPs）才是高效 decode 的关键**。

**离线吞吐（图 5c）**。在线收益转化为面向吞吐的服务：ExFold 离线吞吐提升 1.20×，超过 Direct Top-4（K=8/K=6/K=4 分别为 2.07/2.15/2.29 req/s vs ExFold 2.48 req/s）。Triton 折叠算子在大 batch 下运行时开销很小。

### 5.5 扩展到 DeepSeek-V4-Flash

DeepSeek-V4-Flash 是 284B 参数 MoE、256 路由专家、Top-6 路由，专家空间大得多，用于检验折叠在候选专家数与 batch 级专家并集都更大时是否依然有效。使用 P3（prefill 每 token 保留 3 个专家）与 D128/D64（decode 专家池上限为路由专家的 50%/25%）。

**表 6（质量）**：

| 方法 | Prefill | Decode | 平均分 | 相对基线 |
|---|---|---|---|---|
| Original TopK=6 | 100% | 100% | 72.68 | 100% |
| All TopK=3（直接削减） | 50% | 50% | 64.08 | 88.17% |
| ExFold P3+D128 | 50% | 50% | 72.18 | 99.32% |
| ExFold P3+D64 | 50% | 25% | 70.99 | 97.68% |
| ExFold-D128（仅 decode） | 100% | 50% | 72.72 | ≈无损 |
| ExFold-D64（仅 decode） | 100% | 25% | 72.54 | ≈无损 |

直接的全阶段 K=3 削减只保留原平均分的 88.17%（AIME25/26 损失最大）；ExFold P3+D64 保留 97.68%，在同样 3 专家 prefill 预算下带来 9.51 个百分点的保留增益；P3+D128 保留 99.32%。仅 decode 的 D64/D128 与原模型平均分差距在 0.2 分以内。结果支持一条**质量前沿**而非单一通用预算：D128 是近无损档位，D64 用 1.64 个百分点的额外质量损失换取更紧的专家池。

**图 7（H800 上的加速）**：(a) 8K prefill——P3 在 QPS 1–8 间改善 8K 平均 TTFT，QPS 8 达 1.32×；(b) 256-token decode——batch 饱和后 D64 稳定在约 1.15× TPOT 加速，D128 保持质量优先档位（1.00×）；(c) 饱和吞吐负载下 D64 把输出吞吐从 5.22k 提升到 6.72k tokens/s（1.29×），领先 Direct K=3（1.22×）、REAP（1.16×）与 D128（1.20×）。代码发布暴露两种预算作为服务参数，并包含这些运行使用的校准矩阵。

### 5.6 为什么专家折叠能保住质量？

图 6 可视化一个代表性 token 的路由专家贡献与最终 MoE 输出（HumanEval+ 第 19 层 token 1234 'with'）：Original Top8 为全量执行；Top4-only 误差 1.83；MoDES K=5 误差 0.54；REAP（D64）通过在保留池内选 Top-8 把误差降到 0.16，但每 token 仍执行 8 个专家、不减少专家 FLOPs；**ExFold K=4 把被省略贡献迁移到方向对齐的保留专家、把校准标量折叠进门控权重，仅执行 4 个专家即达到最小误差 0.07**。折叠确实恢复了被省略的贡献。（附录 E 给出更多逐 token 案例。）

## 六、结论

我们提出 ExFold，一个免训练框架，用于联合加速 MoE prefill 与 decode。它结合阶段特定的保留集选择器与一个共享的有向投影器——把被排除的贡献折叠进路由器元数据。在多个 MoE 架构上，ExFold 在比专家丢弃保留更多质量的同时改善了 TTFT、TPOT 与服务吞吐。由于折叠只改动路由器元数据，它与 kernel、调度和并行优化保持互补。这些结果确立了**输出恢复**作为统一 MoE 推理加速的实用基础。

## 附录 B（节译）：投影器参数化与实现

设 L、E、H 为 MoE 层数、每层路由专家数与隐藏维度。各投影器族共用相同校准序列、源输出范数加权与 prefill Top-4 预算；对角与低秩替代方案经自定义 unfused 重建路径执行。

**标量共享模式**。对校准元组组 G，共享标量的加权闭式解为 $s^\star_G = \frac{\sum w_i u_i^\top v_i}{\sum w_i\|v_i\|_2^2 + \lambda}$（式 15）。全局变体全模型一组，层级变体每 MoE 层一组，成对变体每层每条有向源-目标对一组——只有成对形式保留有向的专家级差异，同时仍是标量元数据更新。目标指派用归一化重建损失（式 16）：$\ell_{s\to t} = \frac{\sum_i w_i\|u_i - s^\star_{s\to t} v_i\|_2^2}{\sum_i w_i\|u_i\|_2^2 + \epsilon}$，损失越低表示 $E_t$ 对 $E_s$ 贡献的重建越好。

**对角投影器**。每个隐藏维拟合一个系数（式 17，逐元素加权岭回归）。结果对角矩阵无法吸收进路由权重，必须在线作用于隐向量。

**标量+低秩投影器**。用随机化截断 SVD 拟合逐层正交基 $Q^{(l)}\in\mathbb{R}^{H\times R}$，参数化 $M_{s\to t} = s^\star_{s\to t} I + Q^{(l)} C_{s\to t}$（式 18–19）。实测工件收集秩 32 基并每层保留至多 1024 条有向对（按累计源加权能量排序），评估 R∈{8,16}；支持集之外的对只用标量项。基与逐对修正需要在线向量变换与大量状态，无法复用标准 FusedMoE 路径。

**实现差异（表 9）**：全局标量存 1 个标量、层标量存 L 个、成对标量存 P≤LE² 个——三者均可融合进 kernel；成对对角需 PH 存储、逐元素变换、unfused；标量+低秩需 P+LHR+PRH 存储、秩 R 变换、unfused。

## 译者点评

- **核心贡献是"换个问题"**：把"砍掉哪些专家"（资源削减）改写为"被砍掉的贡献如何用保留专家重建"（输出逼近）。这一形式化让 prefill/decode 两套截然不同的预算约束统一到同一个折叠算子上。
- **"方向对齐、幅度可分"的观察**是整个方法的支点：冗余集中在一个标量自由度上，所以一个逐对标量就够，无需向量投影器——这才使得折叠能吸收进路由元数据、走 FusedMoE 融合 kernel，零额外 kernel 开销。
- **decode 的 2.45× TPOT** 价值最高：batch 级专家并集是访存瓶颈，token 级稀疏化方法在此完全失效，ExFold 是少数同时压住两个预算的免训练方案。
- **工程友好**：免训练、32 条无标注序列即可校准、只改路由器元数据、与 vLLM FusedMoE 兼容、与 kernel/调度/并行优化正交，落地门槛低。
