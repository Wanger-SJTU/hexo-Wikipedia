​ 关注

rdma是高性能网络中必不可少的一部分。但是无论从协议角度，还是软硬件实现角度，rdma都是具有一定难度的课题。本专题准备和大家一起学习有关rdma的相关知识。由于本人一直从事的是ic设计相关工作，因此在本专题中对于rdma的理解更多是从硬件角度对rdma的理解。关于软件角度对rdma的理解可能会有漏缺，期待各位补漏与纠正。

一、先看什么是DMA
DMA即直接内存访问技术（DMA，Direct Memory Access），是一种在计算机系统中允许外设或子系统直接与内存交换数据的技术，无需中央处理器（CPU）的介入。

要弄清楚为什么需要DMA，就需要弄清楚在没有DMA时系统是如何工作的，以及这种情况弊端在哪里。图1是在没有DMA参与的情况下，网卡（NIC）收到数据，再存到缓存（Mermory）中的场景：

图1 无DMA参与情况下，NIC向Mermory传输数据
- NIC收到数据；
- CPU将NIC收到的数据复制到内核态的read_buffer中；
- CPU将内核态的read_buffer中的数据复制到用户态的buffer中；
- CPU将用户态buffer中的数据复制到内核态的scoket_buffer中；
- CPU将内核态的scoket_buffer中数据复制到Mermory；
- 数据传输完成。分析上述过程可知，在没有DMA参与的情况下，数据由NIC搬运到Mermory的过程中，前后一共经历了四次CPU_Copy。在数据包包长比较大的情况下，这四次数据copy会占用CPU相当多的工作周期。在这些被占用的工作周期内，CPU一直在重复简单的数据复制。而我们知道，CPU的最主要工作是计算，而不是进行数据复制，这种工作白白浪费了其计算能力，并且极大地限制了整个系统的处理能力。

弄清楚了系统在没有DMA参与时的工作过程，再分析一下DMA参与下系统的工作过程，便可以弄清楚什么是DMA。图2是在DMA参与的情况下，数据由网卡（NIC）搬运到缓存（Mermory）的场景。

图2 DMA参与的情况下，NIC向Mermory传输数据
- NIC收到数据；
- NIC以描述符的形式向CPU上报收到数据这件事；
- CPU处理收到的描述符信息；
- CPU把处理好的描述符信息发送给DMA_Engine；
- DMA_Engine根据收到的描述符信息读取NIC中的数据，并且发送给Mermory；
- 数据传输完成，DMA_Engine告知CPU数据传输已经完成。分析上述过程可知，在DMA参与的情况下，数据由NIC搬运到Mermory的过程中，CPU实现了数据的“零复制”。在这整个过程中，除了一些必要的控制命令由CPU处理外，整个数据复制过程都是由DMA_Enigne完成的。这样一来，CPU除了关注这一过程的开始和结束以外，其他时间可以去做其他事情。

关于DMA的相关讨论，感兴趣的同学可以查看本人之前对DMA讨论的文章，欢迎各位查阅与纠正。

 二、再看什么是RDMA
RDMA（ Remote Direct Memory Access ）即远程直接地址访问，通过RDMA，本端可以“直接”访问远端的内存，访问过程就像访问本地内存一样，直接绕过传统以太网复杂的TCP/IP网络协议栈读。此过程对端并不感知，且这个读写过程的大部分工作是由硬件完成，而非软件。

类似于DMA，想要弄清楚RDMA，需要先弄清楚在没有RDMA参与的情况下，即普通NIC（网卡）是如何工作的。图3是无rdma参与下的，即使用传统的TCP/IP协议栈来实现本端节点A向远端节点B传输数据的示意图。 

图3 通过TCP/IP协议栈实现A节点向B节点传输数据
- 初始化阶段。A和B节点的应用程序通过调用套接字接口函数建立连接，分别在各自的主机内存中申请用于存放待发送和待接收数据的缓存（buffer）。此缓存位于用户空间。
- 发送阶段。A节点用户程序再次调用套接字函数，目的是获取数据缓存地址和长度等信息。随后进入内核态，位于用户态缓存中的数据被复制进内核态。随后，通过TCP/IP协议栈对数据进行层层封装，封装好报文依旧存在内核态缓存中。
- A节点的网卡驱动告知网卡有数据待发送，软件工作结束，返回用户态。网卡通过DMA将主机内存中（即内核态缓存）的封装好的数据搬运到硬件缓存中来，然后将其通过网络发送到节点B。
- 节点B接收到数据后，将数据缓存在自己硬件缓存中，在将其通过DMA搬运到主机内存中，此时数据已经进入到内核态缓存中，并向CPU发出中断，通知CPU有新数据待处理。
- B节点的CPU接收到中断之后，在通过内核态中的TCP/IP协议栈对数据进行解封装，提取出有效的应用层数据。
- 提取出的有效数据被复制到用户态，提交给用户程序。至此，一次完整的数据和发送操作完成。分析上述过程可以发现，整个过程中发生了5次数据的复制：

- A节点，CPU将数据由用户态复制到内核态；
- A节点，通过DMA将数据从内核态的复制到硬件缓存；
- 数据在网络中的传递，最终由A发送到B，存在B的硬件缓存上；
- B节点，通过DMA将数据由B的硬件缓存复制到内核态缓存；
- B节点，CPU将数据用内核态复制到用户态。在整个过程中，即使已经有了DMA的帮忙，CPU中依旧存在数据复制，而且CPU频繁在用户态和内核态切换。此外，CPU还需要承担发送节点的数据封装与校验、接收节点的数据解封装和校验、以及虚拟地址和物理地址的转换等任务。上述的CPU非计算任务极大地消耗的CPU的时钟，浪费了CPU宝贵的算力。不仅如此，还会造成数据传递延时大，速率低。

正是因为传统TCP/IP协议栈的种种弊端，使得该方案在云计算、大模型训练和推理过程中无法适用，RDMA技术应运而生。图4是RDMA参与下的A和B两节点间数据传递的示意图。

图4 通过RDMA技术实现A节点向B节点传输数据同样以A节点发送数据，B节点接收数据为例进行说明，在rdma中即send-recive操作（后续会详细说明）。

- A、B节点的软件通过控制通路进入内核态，创建两端通信所的必要条件，包括MR、QP、CQ等（这些概念后续会说明）。
- 在数据通路上，A节点的应用直接告诉rdma网卡有数据待发送，并将缓存的地址信息、包长信息等告诉硬件。
- 在数据通路上，B节点的应用直接告诉rdma网卡有数据待接收，并将用于缓存的地址告诉硬件。
- A节点通过DMA将主机内存上的数据复制到硬件缓存中，并且利用硬件逻辑对数据进行封装，封装成标准的rdma报文。
- rdma报文通过网络发送到对端。
- 节点B收到数据之后，利用自己的硬件逻辑对报文进行解封装。
- 通过DMA技术，节点B将解封装之后的数据搬运到主机内存中，并告诉CPU数据传输完成。分析上述过程可以发现，整个过程中发生了3次数据的复制：

- A节点，通过DMA技术将数据从主机内存复制到硬件内存；
- 数据在网络中的传递，最终由A发送到B，存在B的硬件内存上；
- B节点，通过DMA技术，将数据从硬件内存复制到主机内存中。综合比较TCP/IP协议栈传输数据和RDMA网卡传输数据，可以发现RDMA技术存在如下优点：

- 本地内存零复制，即数据不需要在用户态和内核态之间复制。
- 内核旁路，数据面不经过内核态，避免了系统上下文切换。
- 数据的封装和解封装由rdma网卡来实现，释放了CPU宝贵的计算资源。
