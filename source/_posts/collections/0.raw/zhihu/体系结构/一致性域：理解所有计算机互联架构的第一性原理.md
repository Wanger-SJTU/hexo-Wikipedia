### 一致性域：理解所有计算机互联架构的第一性原理

### 忘掉所有名词

### NVLink、CXL、UPI、InfiniBand、PCIe、xGMI、UALink、RoCE——

先把这些名词全部清出大脑。它们是答案，但你还不知道问题是什么。问题搞错了，答案堆得再多也是噪声。

计算机互联架构的所有问题，归根结底只有一个：

<strong>Core 0写了一个字节，Core 1什么时候能看到？谁来保证它看到的是对的？</strong>

这个问题的答案，决定了你的互联架构长什么样、能扩展多大、延迟多高、程序怎么写。

这个问题有一个正式的名字：<strong>一致性（Coherency）</strong>。

而所有互联架构的本质，都是在回答：<strong>一致性域的边界画在哪里。</strong>

### 什么是一致性域？

把所有教科书的定义扔掉，看一个最朴素的例子。

两个CPU核，共享一块内存。Core 0往地址0x1000写了个42，Core 1去读0x1000，它应该读到什么？

<strong>如果硬件保证Core 1一定能读到42（或比42更新的值），那这两个核就在同一个一致性域里。</strong>

这件事听起来天经地义，但它背后需要一套极其精密的硬件协议在运转。

Core 0写了42，但42可能还躺在Core 0的L1 Cache里，还没写回主存。Core 1读0x1000，如果去主存读，拿到的是旧值。所以硬件必须有一种机制——<strong>让Core 1知道”Core 0的cache里有这个地址的最新副本，你得去找它要”。</strong>

这种机制就是缓存一致性协议。MESI、MOESI、MESIF，名字不重要，本质都一样：

硬件自动追踪每一个cacheline的状态：
  - 谁持有它？
  - 是脏的还是干净的？
  - 有几个副本？

当有人要写，硬件自动：
  1. 找到所有持有该cacheline的节点
  2. 告诉它们"你的副本作废了"（invalidate）
  3. 等所有人确认"我作废了"
  4. 然后才允许写入

这一切，软件完全不知道。`

ARM的AMBA CHI规范里，把这件事定义得很精确：

<strong>Coherency Domain</strong>: The set of components that maintain coherency for a set of memory locations.翻译成人话：一致性域就是<strong>硬件愿意帮你维护数据一致性的那个圈子</strong>。圈子内，你写了什么，别人都能自动看到。圈子外，你写了什么，没人知道，除非你自己去通知。

<strong>这个圈子的边界，就是计算机互联架构中最重要的一条线。</strong>

### 一致性域决定了什么？

#### 决定了你的编程模型

在一致性域内部，你可以写最普通的多线程程序：

```text
// 一致性域内部——正常写代码就行
// Core 0
```

shared_data = 42;
flag = 1;

```text
// Core 1
while (flag != 1);
```

printf("%d\n", shared_data);  // 硬件保证你读到42`

跨出一致性域，你就得自己搬数据：

```text
// 跨一致性域——你得手动做所有事情
// Node 0
```

shared_data = 42;
rdma_write(remote_node, remote_addr, &shared_data, sizeof(int));
rdma_write(remote_node, flag_addr, &one, sizeof(int));

// Node 1
rdma_poll(flag_addr);  // 你甚至不确定顺序是对的
rdma_read(remote_node, data_addr, &local_buf, sizeof(int));
// 你还得自己处理乱序、重试、超时……`

<strong>同一个任务，一致性域内10行代码搞定的事情，跨域可能需要500行代码加一个状态机。</strong>

#### 决定了你的延迟边界

一致性域越大，维护一致性的round-trip路径越长。

一致性域半径           维护一致性的延迟
──────────────────────────────────────────
Die内部（几mm）        ~1-10ns
Package内部（几cm）    ~10-30ns  
同机跨Socket（几十cm） ~80-150ns
Rack内CXL Switch      ~200-500ns
──────────────────────────────────────────
       ↑
       这里有一条延迟断崖
──────────────────────────────────────────
跨机器RDMA             ~1-2μs    ← 一致性域通常不会扩展到这里
跨数据中心             ~ms级     ← 绝不可能有硬件一致性`

为什么断崖在那个位置？

一致性协议的一次完整操作（查询→通知→确认）至少需要一个round-trip。信号在PCB上跑大约 5\text{ns/m}，在铜缆中更慢。当物理距离增大到round-trip需要几百ns时，每次cache miss都得等这么久。

CPU一秒钟可能产生<strong>几亿次cache miss</strong>。每次多等几百ns，整体性能直接崩塌。

\text{性能损失} \approx \text{CacheMissRate} \times \text{CoherencyLatency} \times \text{IPCLoss}

<strong>这就是物理定律给一致性域划定的最大半径。</strong>

#### 决定了你的故障域

这一点极少有人提，但至关重要：

<strong>一致性域 = 故障域。</strong>

一致性域内任何一个节点挂了，整个域的状态就不可信了——因为它可能持有某些cacheline的唯一最新副本，也可能正处于一个一致性协议的中间状态。

4路SMP（一个一致性域）：
  - 一个CPU挂了 → 整机停摆
  - 故障影响范围 = 整个一致性域

4台独立机器（四个一致性域）：
  - 一台机器挂了 → 其他三台继续工作
  - 故障影响范围 = 单个一致性域`

一致性域越大，一次故障的爆炸半径越大。这不是工程可以绕过去的——它是一致性语义本身的逻辑必然。

#### 决定了你的可扩展性上限

维护一致性需要追踪状态。追踪状态需要存储空间和通信带宽。

<strong>广播式Snoop</strong>：每次写操作，问所有人”你有这个cacheline吗？”。通信量 O(N)，N个节点就需要N倍的snoop带宽。早期SMP用这种方式，超过4-8路就扛不住了。

<strong>目录协议（Directory-based）</strong>：维护一张大表，记录每个cacheline被谁持有。查表就行，不用广播。但表有多大？

\text{目录大小} \propto \text{内存容量} \times \text{节点数的编码位数}

一个64GB内存、64字节cacheline、16节点的系统，目录条目数 = 64\text{GB} / 64\text{B} = 10^9，每条目需要记录16个节点的持有状态——这张表本身就要吃掉GB级别的存储。

而且每次远端访问都多了一跳查目录的开销。

<strong>不管用什么协议，一致性域的扩展成本都是非线性增长的。</strong> 这就是为什么历史上最大的SMP机器（SGI UV、Bull Sequana）也只做到几十路，不是工程师偷懒，是物理上不经济。

### 用一致性域重新理解所有互联技术

现在你手里有了这把钥匙，去开每一扇门。

#### UPI / xGMI：一致性域的”围墙”

Intel的UPI和AMD的xGMI/Infinity Fabric，本质上是<strong>在多个socket之间建立完整一致性域的专用通道</strong>。

UPI:
  - 每条链路 ~40GB/s
  - 一颗CPU通常3条UPI → 聚合~120GB/s
  - 延迟 ~80-130ns
  - 深度集成在CPU内部
  - Snoop filter在硅片里
  - 一致性协议的"快车道"`

为什么UPI带宽”只有”40GB/s一条链路，但它在一致性场景下的表现极好？

因为UPI不是通用数据管道，它是<strong>一致性协议的专用载体</strong>。它的每一个bit都在为snoop/invalidate/data transfer服务。协议开销极低，因为是从硅片级别co-design的。

对比CXL——CXL跑在PCIe物理层上，一致性协议是”叠加”上去的。就像在高速公路上开救护车，路是共用的，虽然带宽数字更大，但协议栈的层次更深，每一层都在加延迟。

#### CXL：试图推墙的人

CXL在干一件极其野心勃勃的事——<strong>把一致性域的围墙往外推</strong>。

CXL Spec 3.0定义了三种协议组合：

CXL.io  → 本质就是PCIe，设备发现和配置
CXL.cache → 设备缓存主机内存，设备可以snoop主机
CXL.mem → 主机用load/store访问设备内存`

CXL 3.0引入的Back-Invalidate（BI），是关键一步：

<strong>设备不再只是被动地被主机snoop，设备可以主动invalidate主机的cacheline</strong>。这意味着一致性变成了双向的。主机和设备，甚至多个主机之间，可以通过CXL Switch建立一个硬件一致性域。

<strong>但推墙是有代价的。</strong>

一致性域大小        CXL能支撑吗？         制约因素
──────────────────────────────────────────────────
2-4节点共享内存     ✓ 可行               延迟200-500ns，可接受
8-16节点           勉强，看workload      一致性流量开始吃带宽
32+节点            ✗ 不现实              目录开销和一致性流量爆炸
跨Rack             ✗ 不现实              物理距离→延迟不可接受`

CXL的真实价值不是”替代UPI做Scale-Up”，而是在一致性域边界之外、消息传递域之内的那片<strong>真空地带</strong>，提供了一种新的选择：

<strong>有硬件一致性保证的远端内存访问，但延迟比本地DRAM高，规模比传统SMP小。</strong>

#### NVLink / UALink：带宽压倒一致性

NVLink的设计哲学和UPI/CXL完全不同。

GPU的核心需求不是cacheline级别的一致性，而是<strong>海量数据搬运</strong>。一个Transformer的all-reduce操作，需要把几个GB的gradient在8张GPU之间同步。它不需要硬件帮你追踪每一个cacheline的状态——它需要的是<strong>管道够粗</strong>。

NVLink 5.0:  ~200GB/s 单链路
NVSwitch:    聚合TB/s级

对比：
CXL 3.0:    128GB/s（x16）
UPI 2.0:    ~40GB/s 单链路`

NVLink提供的是<strong>有限一致性</strong>——它支持一定程度的地址空间共享和原子操作，但不维护完整的cacheline级别一致性。它不追踪每一个64字节cacheline的状态，因为GPU不需要这个。

<strong>NVLink为带宽优化，牺牲了一致性的完整性。</strong> 这是完全正确的trade-off，因为GPU workload的特征就是大块数据搬运，不是细粒度的cacheline共享。

UALink 1.0（AMD/Intel联盟，2024年）走的是类似路线：高带宽GPU互联，目标200GB/s，一致性比CXL更靠近GPU的需求。

#### InfiniBand / RoCE：一致性域之外的世界

InfiniBand和RoCE的世界里，<strong>没有硬件一致性</strong>。

IBTA Spec定义的RDMA语义非常清晰：

你可以读写远端内存，但硬件不保证你读到的值和远端CPU看到的值一致。你写了一个RDMA Write，数据到了对面的内存。但对面CPU的cache里可能还有旧值。你得自己用memory barrier、completion notification来协调。

这就是一致性域边界之外的世界：一切由软件负责。

一致性域内部（UPI/CXL）：
  CPU执行: load [addr]
  硬件自动: snoop → invalidate → fetch → 返回最新值
  程序员：什么都不用管

一致性域外部（InfiniBand/RoCE）：
  程序执行: post_rdma_read(remote, addr, len)
  硬件只管: 把远端那块内存的bit搬过来
  程序员：自己保证"搬过来的是对的"、"搬的时候没人在改"`

### 一致性域的分层架构：真实世界的样子

真实的计算系统不是只有一个一致性域，而是<strong>一致性域的层级嵌套</strong>：

┌──────────────────────────────────────────────────────────────────┐
│ Layer 0: Core内部                                                │
│   范围: 单个CPU核心                                              │
│   延迟: ~1ns                                                     │
│   一致性: L1/L2 cache内部，trivial                                │
│   标准: CPU微架构内部，无公开标准                                  │
├──────────────────────────────────────────────────────────────────┤
│ Layer 1: Die/Package内部                                         │
│   范围: 同一颗芯片上的所有核心                                    │
│   延迟: ~10-30ns                                                  │
│   一致性: 片上环形总线/Mesh，全硬件一致性                          │
│   标准: AMBA CHI (ARM), Intel Mesh, AMD Infinity Fabric           │
├──────────────────────────────────────────────────────────────────┤
│ Layer 2: 跨Socket                                                │
│   范围: 同一台机器的多颗CPU                                       │
│   延迟: ~80-150ns                                                 │
│   一致性: 全硬件一致性（ccNUMA）                                   │
│   标准: UPI (Intel), xGMI (AMD)                                   │
├──────────────────────────────────────────────────────────────────┤
│ Layer 3: Rack内（新兴）                                           │
│   范围: 同一机架内的多台机器/多个设备                              │
│   延迟: ~200-500ns                                                │
│   一致性: 硬件一致性，但规模受限                                   │
│   标准: CXL 3..1 (Compute Express Link Specification)          │
├──────────────────────────────────────────────────────────────────┤
│ Layer 4: 跨Rack / 集群                                           │
│   范围: 数据中心内多台机器                                        │
│   延迟: ~1-10μs                                                   │
│   一致性: 无硬件一致性，RDMA提供远端内存访问语义                    │
│   标准: IBTA Spec (InfiniBand), IEEE 802.3 + RoCEv2               │
├──────────────────────────────────────────────────────────────────┤
│ Layer 5: 跨数据中心                                              │
│   范围: 地理分布式                                                │
│   延迟: ~ms级                                                     │
│   一致性: 纯软件（Paxos/Raft/最终一致性）                         │
│   标准: 无硬件标准，全靠软件协议                                   │
└──────────────────────────────────────────────────────────────────┘`

<strong>每上升一层，一致性域的半径变大，但维护一致性的代价急剧上升，直到某一层之后，硬件一致性变得不再经济，软件接管。</strong>

那条”硬件一致性不再经济”的线，就是所有架构争论的焦点。

UPI/xGMI画在Layer 2和Layer 3之间。 CXL试图把它推到Layer 3和Layer 4之间。 NVLink在Layer 2-3之间走了一条”高带宽、弱一致性”的差异化路线。 InfiniBand接受了Layer 4的无一致性现实，把精力全花在降延迟和提带宽上。

<strong>没有谁是对的，因为每一层的workload需求不同。</strong>

### 所以Scale-Up和Scale-Out是什么？

现在可以回答这个问题了：

<strong>Scale-Up = 在同一个硬件一致性域内扩展计算能力。</strong> <strong>Scale-Out = 跨越一致性域边界，用软件协调多个独立一致性域。</strong>

Scale-Up:  硬件担保一致性 → 编程简单 → 规模受限于物理定律 → 故障域大
Scale-Out: 软件担保一致性 → 编程复杂 → 规模理论无上限   → 故障域小`

但这对概念<strong>没有任何标准定义过</strong>。它是三十年前产业界约定俗成的说法，在一致性域边界清晰的年代（box内 vs box间）很好用。

<strong>今天，边界正在模糊。</strong> CXL把一致性域推到了rack级别，NVLink在节点内打开了高带宽但弱一致性的通道。用Scale-Up/Scale-Out这种二元对立去描述一个连续光谱，越来越力不从心。

### 一致性域作为第一性原理

如果你只记住一件事，记住这个：

<strong>一切互联架构决策，都是在回答”一致性域的边界画在哪里”。</strong>

- 边界画大了：硬件复杂度爆炸，延迟上升，故障域变大，但软件写起来简单。
- 边界画小了：硬件简单，延迟可控，故障隔离好，但软件需要处理分布式一致性的所有噩梦。
每一种互联技术，都是在这条trade-off曲线上选了一个点：

\text{系统总复杂度} = \text{硬件一致性开销} + \text{软件一致性开销} = \text{常量}

<strong>复杂度不会消失，只会在硬件和软件之间搬家。</strong>

UPI选择让硬件承担最大的一致性责任，换来最简单的编程模型。InfiniBand选择让硬件只管搬数据，一致性全交给软件。CXL在两者之间找了个折中点。NVLink为GPU workload的特殊性质，走了一条高带宽弱一致性的差异化路线。

<strong>没有最优解，只有在具体约束条件下的最合适解。</strong>

而找到那个最合适解的方法，就是回到第一性原理：

- <strong>你的workload需要什么级别的一致性？</strong> 是每个cacheline都要追踪，还是大块数据搬运就够了？
- <strong>你能容忍多大的延迟？</strong> 这决定了一致性域的物理半径。
- <strong>你需要多大的带宽？</strong> 一致性流量和数据流量要共享链路带宽。
- <strong>你的故障域能有多大？</strong> 一致性域越大，爆炸半径越大。
- <strong>你愿意让硬件和软件各承担多少复杂度？</strong> 这决定了你在trade-off曲线上的位置。
回答了这五个问题，架构自然浮现。不需要任何marketing术语。

<strong>一致性域的边界在哪里，架构就长什么样。这是第一性原理，其他一切都是推论。</strong>
