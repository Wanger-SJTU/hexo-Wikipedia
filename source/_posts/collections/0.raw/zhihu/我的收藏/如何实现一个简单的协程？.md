实现一个可用的协程最简单的方法是用宏，asio中就有一个非常优雅的实现，只有70行代码，可以独立拿出来使用（coroutine.hpp），且品质足够可用于生产环境。我专门写过一个demo，很容易看懂，在这里：

这种协程的优点就是简单、写出来的代码可读性好、不需要高版本编译器的支持，缺点是调试比较麻烦（这和其它的宏代码缺点类似）。

coroutine.hpp 则采用的是一种极为轻巧的协程实现方式：利用 switch-case 和宏模拟出协程的挂起（yield）与恢复（resume）。

coroutine.hpp 的核心思想是通过宏将协程体改写成一组 switch 标签，利用局部变量持久化状态，从而在多次调用间保持执行位置。这种技术通常被称为“Duff's device”的变种，也是实现状态机的一种优雅方式。

核心数据结构

类 coroutine

```cpp
class coroutine
{
public:
  coroutine() : value_(0) {}
  bool is_child() const { return value_   0; }
  bool is_parent() const { return !is_child(); }
  bool is_complete() const { return value_ == -1; }
private:
  friend class coroutine_ref;
  int value_;
};
```


coroutine 类仅持有一个整型 value_，它表示协程的当前状态：

- value_ == 0：初始状态，表示协程从未执行或刚进入。
- value_   0：表示协程正停留在某个 yield 点（标签号）。
- value_   0：表示协程处于“子协程”分支（fork 产生的分支），其绝对值为标签号。
- value_ == -1：表示协程已结束。
类 coroutine_ref 

```cpp
class coroutine_ref
{
public:
  coroutine_ref(coroutine  c) : value_(c.value_), modified_(false) {}
  coroutine_ref(coroutine* c) : value_(c- value_), modified_(false) {}
  ~coroutine_ref() { if (!modified_) value_ = -1; }
  operator int() const { return value_; }
  int  operator=(int v) { modified_ = true; return value_ = v; }
private:
  void operator=(const coroutine_ref );
  int  value_;
  bool modified_;
};
```


coroutine_ref 是 coroutine 的引用包装，主要作用是在宏展开期间安全地读写 value_。其析构函数有一个关键行为：如果 modified_ 为 false（即宏块中没有对 value_ 赋值），则自动将 value_ 设为 -1，标记协程结束。这一设计保证了协程在正常退出（没有遇到 yield）时能自动清理状态。

宏的魔法

CORO_REENTER 

```text
#define CORO_REENTER(c) \
  switch (coroutine_ref _coro_value = c) \
    case -1: if (_coro_value) \
    { \
      goto terminate_coroutine; \
      terminate_coroutine: \
      _coro_value = -1; \
      goto bail_out_of_coroutine; \
      bail_out_of_coroutine: \
      break; \
    } \
    else case 0:
```

CORO_REENTER 是协程体的入口宏。它展开为一个 switch 语句，其控制表达式是 _coro_value（即协程的当前值）。第一次进入时 value_ 为 0，所以跳转到 case 0: 开始执行。如果协程已经结束（value_ == -1），则进入 case -1:，因为 _coro_value 非零（为 -1），会执行 goto terminate_coroutine，进而将 value_ 置为 -1 并跳出协程体。

这个宏还隐藏了两个标签 terminate_coroutine 和 bail_out_of_coroutine，它们用于处理协程的终止和跳出。

CORO_YIELD

```cpp
#define CORO_YIELD_IMPL(n) \
  for (_coro_value = (n);;) \
    if (_coro_value == 0) \
    { \
      case (n): ; \
      break; \
    } \
    else \
      switch (_coro_value ? 0 : 1) \
        for (;;) \
          case -1: if (_coro_value) \
            goto terminate_coroutine; \
          else for (;;) \
            case 1: if (_coro_value) \
              goto bail_out_of_coroutine; \
            else case 0:
```

CORO_YIELD 是挂起宏。它接受一个唯一的标签号（由 __LINE__ 或 __COUNTER__ 生成），展开后包含一个 case (n): 标签。当协程执行到 yield 时，它会将 _coro_value 设置为 n，然后 break 跳出当前块，从而让协程函数返回（挂起）。下次再进入时，switch 会直接跳转到 case (n):，接着执行 yield 之后的代码。

CORO_FORK

```cpp
#define CORO_FORK_IMPL(n) \
  for (_coro_value = -(n);; _coro_value = (n)) \
    if (_coro_value == (n)) \
    { \
      case -(n): ; \
      break; \
    } \
    else
```

CORO_FORK 用于创建协程分支，模拟“fork”操作。它先将 _coro_value 设为 -n，然后进入一个循环。第一次进入时 _coro_value == -n，不满足 if 条件，执行 else 分支（即用户代码）。当用户代码中再次调用该协程时，_coro_value 被改为 n（因为循环的增量部分 _coro_value = (n)），满足 if 条件，跳转到 case -(n): 并 break，从而执行另一个分支。

工作原理：状态机与 Duff's device
上述宏组合在一起，实质上是将协程体转换成一个巨大的 switch 状态机。每个 yield 或 fork 点对应一个唯一的整数标签，协程的 value_ 存储了当前状态。当协程函数被调用时，通过 switch (value_) 直接跳转到上次挂起的位置。

这种技术的鼻祖是著名的 Duff's device，它利用 switch 和 case 标签可以穿透循环的特性，将循环展开与状态跳结合。coroutine.hpp 采用了相同的思路，但更专注于协程的挂起/恢复。

下面是一个简化的例子，说明宏展开后的代码形态：

```text
bool Consume(char c) {
  reenter(this) {          // 展开为 switch (coroutine_ref _coro_value = this) case 0:
    while(isalpha(c)) {
      method_.push_back(c);
      yield return true;   // 展开为 case __LINE__: ; break;
    }
    // ...
  }
  return false;
}
```

第一次调用 Consume 时，value_ 为 0，进入 case 0:，执行 while 循环，遇到 yield 时将 value_ 设为标签号并 break，函数返回 true。第二次调用时，value_ 等于该标签号，switch 直接跳转到对应的 case，继续执行循环的下一次迭代。

示例：解析 HTTP 请求行
test_coroutine.cpp 提供了一个完整的例子：解析 HTTP 请求行。该协程逐个字符读取，并在每一步都可能挂起（等待下一个字符）。这种“增量解析”正是协程的典型应用——无需一次性将整个字符串加载到内存，也无需编写复杂的状态机。

```text
bool Consume(char c) {
  reenter(this) {
    // 读取 method
    while(isalpha(c)) {
      method_.push_back(c);
      yield return true;
    }
    // 检查空格
    if(c != ' ') yield return false;
    else yield return true;
    // ...
  }
  return false;
}
```

在 main 函数中，我们遍历字符串，每次调用 Consume 传入一个字符。协程内部在 yield 处挂起，并返回 true 表示还需要更多字符；如果遇到错误则返回 false。当整个字符串处理完毕，协程最终返回 false（因为 reenter 块结束，value_ 被自动设为 -1）。
