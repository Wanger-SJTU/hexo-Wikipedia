我只用一张图，就能让你明晰当下所有刷机救砖之法。当你掌握了这些刷机原理后，不管手机、路由器还是电视盒子，不管什么品牌，你都不再迷惘，是否会刷成砖心中都有数。

首先，你要明白一件事情，刷机手段并不是极客们发明的，而是厂家本来就提供的、方便自己（和合作厂商）开发、调试和测试的重要手段，极客们只是借用而已。

分析 CPU 的启动链，我们可以更好地理解所有刷机方式。记住，这些方式都是厂家为了方便<strong>研发调试/售后维修/小批量生产烧录</strong>留的“后门”，目标是做到<strong>不依赖于外部硬件工具，仅靠主板自己</strong>就能烧录或修改 Flash 芯片（Nand/eMMC/UFS）中的数据（文件），厂家一般称之为<strong>在线</strong>烧录（准确来说是在板）。

CPU 的启动流程如下图左侧蓝色箭头所示，主要就是 PBL -> bootloader -> Android/Recovery。下图右侧为电脑上运行的工具软件，通过某种线缆与设备对接。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_d13a049facf6.jpg)![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_001afcd15ece.webp)

刷机原理一张图SoC 内部集成有只读存储器（iROM，也称 Boot ROM，用于存储PBL程序）和静态RAM（iRAM，在DDR工作前加载和执行 bootloader），受限于 CPU 金贵的硅面积，它们的容量都很小，因此，iROM 中的 PBL （初级引导）程序一般不会很复杂，主要就是初始化 Flash 控制器并引导 Flash 中的 SBL（bootloader 之一）。但为了方便烧录和售后救砖，PBL 一般还带了 EDL 功能（如下图为高通的 9008 刷机工具界面）。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_38293623cabf.jpg)

高通 9008 刷机工具SoC 上电后，PBL 会首先检查某些引脚的状态，如高通会检查 USB 口的 D+ 和 D- 有没有短接（工程线中的按钮功能）在一起，若发现短接，PBL 就不往下引导，而是初始化 USB-CDC 模拟串口，等待上位机的指令。此时电脑上会看到一个虚拟串口，通过厂家提供的 EDL 软件，能够驱动 PBL 对整块 Flash 进行读写操作。因为 PBL 在 CPU 内部，不管 Flash 有没有数据，Flash 中的 bootloader 是否破坏，都不影响 PBL 的执行。所以 EDL 工具能做到终极救砖，只是一般不提供给普通用户。提供 PBL - EDL 刷机的 CPU 一般都刷不死，除非 CPU 或 Flash 本身坏掉了。

能做到终极救砖的还有 JTAG 仿真。CPU 都会集成一个 Debug 模块，通过 JTAG 接口连接电脑的仿真调试套件。Debug 模块是一个独立的阉割版处理器，在 CPU 的任何执行状态，Debug 都能同时监控和操作包括 CPU 在内的很多硬件模块，功能非常强大，操作 Flash 控制器实现闪存的读写只是小菜一碟。但是，因为 JTAG 的管脚比较多，不但会占用 CPU 的 IO 资源（一般是复用管脚），还会占用板卡的面积，所以通常只用在初始开发阶段，正式产品上一般是不用的，所以通常这条路走不通。

正常使用场合，PBL 会加载闪存 boot 分区中的 bootloader （通常不止一级）到 iRAM后，CPU 执行权交给了 bootloader。

不像 PBL，bootloader 位于 eMMC 或 UFS 中，可持续升级改进，功能自然会比 PBL 强。bootloader 通常会利用 CPU 的主 UART （一种TTL电平的原始串口）跟上位机电脑（串口调试助手）通信，为用户提供命令行操作接口。用户通过执行 bootloader 开放的命令，可以实现许多调试功能，操作 Flash （如修改分区表、备份或烧录数据）自然不在话下。因为 bootloader 运行在 iRAM 或 DDR 中，通常整个 Flash 空间都是可以操作的。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_337692119144.jpg)

某盒子启动时的 TTL 打印但是，bootloader 开放 UART 命令行接口仍会占用 CPU 的 IO 管脚和电路板的 Layout 面积（到少要提供 GND、TXD、RXD 三个焊盘），如下图，所以有些厂家或产品并不会引出 UART 管脚。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_e1344183c85e.jpg)

即使厂家引出了TTL接口，要拆开外壳连接电路也挺麻烦的。所以厂家为了方便用户，一般会用外接的 USB 口，实现与上位机烧录工具（如 Fastboot）的通信，借助这些工具，用户就可以轻松访问或烧录 Flash 数据。正常情况，bootloader 会引导主系统（如 Andoird），但跟 PBL 一样，bootloader 也会通过检测某些引脚的电平状态（如按钮组合或线路短接）或 UART 的 RX（键盘按任意键）数据，来决定是否要停留在 bootloader 状态，还是要进入 fastboot 模式 ，或者要引导 Recovery 系统。通过 bootloader 刷机的前提条件，自然是 bootloader 程序没有被破坏，否则只能回溯到上一级 EDL 救砖了。

当用户通过特殊的管脚状态或显式的 bootloader 指令（如串口命令、主系统的自动更新指令标记、Reboot_to_LibreELEC.apk 标记）指定进入 Recovery 系统时，CPU 就会加载执行功能更强大的、独立分区的、与主系统同启动等级的 Recovery 系统。

Recovery 作为一个完整的 Linux 系统，可以借助已有的生态，轻松开发出强大的功能。如下图为 TWRP 的截图，作为一个流行的第三方 Recovery 系统，它提供了复杂的 GUI 界面，不需要借助外部电脑即可完成复杂的操作。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_28966795e085.jpg)

手机厂商自带的 Recovery 系统通常比较简单，只能实现主系统的出厂恢复、系统升级、数据清空等基本操作，一般通过音量键和开机键进行操作，如下图：

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_84ed7de643b9.jpg)

通过 Recovery 进行系统升级，也就是我们常说的卡刷，原理是，用户先把刷机包（update.zip，里面可包含 bootloader 和主系统的镜像）拷贝到自身的 Flash 某分区或外置 SD卡/U盘中，然后通过 Recovery 解压这个刷机包，并把各镜像烧录到正确的分区中。

但 Recovery 处于上电启动链的最末端，如果启动链中任何一级 bootloader 出错（通常是错误操作Flash分区或刷入错误的 bootloader 镜像引起的），都进不了 Recovery，更不用谈刷机或 root 了。

除了这些<strong>在线</strong>烧录方式，还有更硬核的<strong>离线</strong>烧录方式，一般也称生产烧录方式，是通过专门的一对多 Flash 烧录器，一次性同时烧录多片 Flash 裸片，烧写成功后再贴片焊接到主板上。

手机维修店一般也有生产烧录的软硬件，能够对拆焊下来的 Flash 芯片轻易读出数据或烧录镜像。维修店的烧录器通常是一对一的，结合各种封装的座子夹具，能应对各种闪存芯片。作为一个合格的极客，自然也会配置这些，淘宝上价格也不贵。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_663963973101.jpg)

有趣的是，维修界一般称 Flash 芯片为字库芯片，年轻的工程师听到字库二字，可能会一脸懵逼。这是历史遗留下来的习惯叫法，大家也不要嘲笑人家，你较真反而显得你无知。
