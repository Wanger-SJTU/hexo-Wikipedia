前面的文章中我们一起学习了三类利用DLP提升性能和能耗效率的架构：向量体系结构、SIMD指令集扩展和GPGPU，并且对前两者进行了对比。

今天，我们一起来看下向量体系结构和GPGPU之间有哪些异同点。

导图

一、GPGPU 与向量处理器: 两种数据级并行计算模式

1.1 SM vs 向量处理器

图1 向量处理器和GPGPU图1为了展示硬件结构对lane的个数进行了简化。

首先向量处理器与GPGPU中的SM(流式多处理器/多线程SIMD处理器)概念类似，GPGPU中多个SM可以像MIMD架构一样工作，而向量计算机中拥有多个向量处理器也是类似。

SM和向量处理器内部所有车道(lane)以数据级并行的形式执行SIMD指令，向量处理器中叫向量指令，NVIDIA GPGPU中叫做PTX指令。

两者的最大区别在于GPGPU SM支持多线程，而大多数向量处理器则没有采用。这是因为两者用不同截然不同的方式隐藏长延迟操作。

向量体系结构通过深度流水化访存逻辑使向量内的所有元素分担长访存延迟，通过深度流水化计算单元+Chaining/Forwarding掩盖长计算延迟。

而GPGPU SM则依赖于多线程之间的零延迟切换来隐藏长延迟操作。

上层”通用并行多线程”与”深度向量流水”两种不同计算模型的目标驱动着层微结构上也有显著差异。

SM倾向于拥有更多的车道，因此仅需更少的时钟周期去完成一条SIMD指令。比如NVIDIA Tesla V100每个SM支持64车道，而向量处理器大多采用4~8车道。

SM倾向于拥有更多寄存器，因为每个线程拥有私有的寄存器空间，同时还需多线程的支持。NVIDIA Tesla V100每个SM支持256KB的寄存器文件，Andes AX45MPV每个向量处理器支持4KB的向量寄存器。这也导致寄存器结构不同，向量处理器拥有一个承载向量的寄存器堆，而GPGPU中单个向量会分散在所有车道的寄存器中。

不过这两方面的差别正在减弱，当下高性能领域的向量处理器也开始采用长向量+更多车道的微结构，比如AraXL RISCV向量处理器支持64Kb宽的向量+64车道微结构。

关于Vector Chaining和当下向量处理器的趋势将作为补充放在本文末尾，感兴趣的同学可以移步阅读。

1.2 标量处理器
在向量处理器中，常在片上配置标量寄存器，用于执行零散的标量指令并将结果通过硬件广播至所有向量车道，同时还原生支持固定步长(strided)的访存操作。

图2 GPGPU和Host通信而在典型的 GPGPU 架构下，CPU 与 GPU 之间必须经由 PCIe 总线和全局显存完成通信，高延迟使得在 GPU 上执行零散的标量指令变得低效，因此往往只能在单一车道（lane）上执行此类操作并掩码其余车道，这不仅带来更大的调度与掩码开销，也显著削弱了执行效率和能耗表现。

1.3 编程思路
在 GPGPU 与向量处理器的编程范式上存在显著差异：对于 GPU 程序，开发者通常可以沿用熟悉的串行思路，先按步骤编写逻辑，再在必要处插入并行指令；而在向量处理器上编程时，则必须从整体入手，设计并优化可向量化的循环结构，才能最大化地发挥 SIMD 硬件的性能优势。

这是因为在向量体系结构中，由于编译期无法确定实际向量长度，编译器或运行时必须根据程序所请求的向量长度和硬件所支持的最大并行向量长度，采用条带化(strip-mining)技术，将原始循环划分为多个子循环，并将向量长度寄存器(VL)设置为每个子循环所能处理的最大元素数；硬件则据此生成对应的掩码，确保只对有效元素进行计算。

相比之下，在 GPGPU 编程模型中，线程的生成与调度对程序员几乎透明，程序员只需定义kernel和线程网格/块(grid/block)维度，硬件会自动将线程映射到SM上执行，并在遇到分支和越界访问时由底层的掩码机制自动处理，无需手动管理向量长度或掩码。

二、向量处理器内容补充

2.1 Vector Chaining

图3 Vector ChainingVector Chaining是一种数据旁路技术，一个向量操作的输出直接用作另一个向量操作的输入，而不需要将中间结果写回存储单元或向量寄存器文件。

图4 Vector Scoreboard支持该功能的关键组件是scoreboard，记分板跟踪向量指令的生命周期和指令信息，生命周期包括已发射、正等待源操作数、功能单元开始操作第一个元素、整个向量元素操作完毕、以及已写回向量寄存器。

控制逻辑根据记录的状态识别依赖关系，并在功能单元开始操作第一个元素后判断chaining的可能性，可能由于资源冲突导致无法进行数据旁路。

允许数据旁路后，控制信号会配置数据转发路径进行正确连接。

2.2 当下向量处理器微结构趋势
长向量操作+更多车道并行已成当今高性能向量处理器发力的方向，意在提升数据级并行的能力，这方面改进也使得向量体系结构正在获得吸引力。

长向量(long vector)操作是指一个向量指令能够处理更多的向量元素，这受限于向量寄存器(VRF)的宽度，RVV架构下每个向量寄存器最大支持64Kb宽度，但大多数向量处理器仅支持1024~4096-bits。

长向量(long vector)操作的好处一方面体现在能够将指令的固定成本(比如取指、译码、发射、以及长延迟操作)分摊在更多的元素上，这也是向量处理器隐藏延迟的方式。另一方面VRF相当于缓存，更大的VRF可以提升数据的局部性/复用度，也就提升了对内存延迟的容忍度。

更多车道并行对DLP的提升更为直观，也是长向量操作的基本硬件支持。

那么代价是什么？

一般而言，向量处理器支持超过8条车道是有挑战的，芯片内部为了把数据从主存或高速缓存分发到每一条车道的向量寄存器文件，以及向量在车道之间做像滑动、压缩、掩码和归约这类操作所需的”无处不在的全连通(all‑to‑all)”布线，就会急剧增多。这种布线不仅在物理上占用巨大面积，还会带来极高的布线拥塞、时序难以收敛、功耗激增等问题，最终在工艺实现上几乎不可行。

当下的向量处理器也在借鉴GPGPU多级互连的思想扩展车道数目。

图5 AraXL 微结构AraXL支持64Kb的向量长度和64条车道，它是怎么做到的呢？

首先采用基于vector cluster的层次化结构，每小组件内部实现全互联使得连线规模不会指数级膨胀。

然后外部采用可扩展的接口，包括用于指令下发的REQI接口，用于访存的GLSU接口，以及用于处理向量排列操作的RINGI接口。这些接口的首要目标都是时序，而非延迟，因为长向量操作使得它对延迟更加不敏感。因此这些互连接口允许采用多级结构，而不再约束为单周期完成。

图6 AraXL GLSU接口GLSU接口是时序最为紧张的接口，AraXL将其分为三个流水级。Align流水级负责处理内存非对齐访问，Addrgen流水级负责对访存事务进行“拆包”和“打包”，Shuffle流水级负责处理访存数据重排操作，比如根据向量指令的元素宽度调整访存数据与Cluster的映射关系，比如RVV vector indexed segment这样的数据重排操作。

Vector Cluster内部与GLSU交互的VLSU模块负责将更小的数据块与内部的VRF进行互联。

图7 AraXL RINGI接口AraXL重新设计了用于处理向量排列操作的全连接互联结构，改为环形互连结构的RINGI接口。RINGI接口在cluster之间移动数据，SLDU组件在正确的时间使用该数据。能够显著加速高性能计算和机器学习的典型应用场景：slide-by-1操作，也就是向量寄存器整体左移或右移一个元素。
