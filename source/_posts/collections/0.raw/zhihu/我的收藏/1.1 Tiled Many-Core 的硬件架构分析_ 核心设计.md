#### 流处理器核心与通用处理器核心

在开篇提到的参考教材中有一种倾向（开篇第4页 ”尤其以集成大量流处理器核为代表的众核处理器，所能提供的运算单元数量非常庞大，这类处理器不仅通过 VLIW 技术发掘应用级并行性，还能通过编译技术充分发挥任务级并行性。“），即流处理器 / VLIW 是目前的 Tiled Many-Core 设计的主流。的确，早期的众核处理器中，最有代表性的 Cell 和 TI DSP 都是流处理器。

本文无意讨论两种设计思路之间的区别，但近几年的众核处理器发展，越来越多使用了传统处理器核，如我们关注的 Xeon Phi， Esperanto ，Tenstorrent ，又或者是 Cerebras ，SpiNNaker (ARM9) ，“火苗”高通量处理器<span class="wikilink wikilink--missing" title="未导入的页面">1</span>(#ref_1) (Rocketchip) 均不能归于参考教材所提到的这一类。其他不在本文讨论中的众核处理器，申威 26010 及其后续是多发乱序 SIMD 核心、PEZY-SC 是某种实现了 SMT4 的 RISC 核（甚至没有实现向量/矩阵部件）、Graphcore IPU 在类似的想法上实现了向量部件<span class="wikilink wikilink--missing" title="未导入的页面">2</span>(#ref_2)、，只有 Preferred Network 的 MN-Core 在形式上使用了 VLIW （况且 MN-Core 的 VLIW 不是操纵单个核心，而是一个核组）。

#### Tenstorrent Tensix 架构详述

本系列以 Tenstorrent 为核心的研究对象，因而在此我们将详细介绍 Tensix 的架构。

![](/images/collections/0.raw/zhihu/%E6%88%91%E7%9A%84%E6%94%B6%E8%97%8F/asset/img_0606a50fbe17.jpg)

Tenstorrent Tensix 的基本架构在本节中，我们暂时不会介绍 NRISC 与 BRISC（两者跟数据搬运关系更大）。其中 UNPACK 将数据从 L1 cache 搬运到 SRC ，PACK 将数据从 DST 搬运到 L1 。图中最下方包括 FPU / SFPU 的部分是实际的数学运算部分。FPU 是用于例如矩阵乘法的 `high-density tensor math unit` ；SFPU是 SIMD unit ，用于各种激活函数等。如果看作传统的流水线，那么可以把 TRISC 看作传统的取指/发射， UNPACK-PACK 构成了传统意义上的 LSU ，而 FPU-SFPU 则是传统流水线中的 ALU/VPU 部分。

关于 L1 cache 和 PACK-UNPACK 设计的问题，由于牵扯到 Packet 的问题，我们将在之后具体讨论。跟传统的通用处理器核相比，主要的区别是 high-density tensor math unit 的存在，以及 SFPU / FPU 是互相独立的。这么设计的目的是什么？

#### 矩阵加速

数值计算的对象，大致可以分成向量，稀疏矩阵和密集矩阵三种。数学上，矩阵加减法与内积都可以通过逐行逐列向量运算实现，可以不用独立的计算单元。但进行矩阵外积（乘）时，朴素的方法是 C_{i,j}=\sum_{k=1}^n A_{i,k} B_{k,j} ，也就是说对每个元素都需要做一次向量运算，或者是对单个元素 A_{i,k} ，broadcast A_{i,k} 到向量 B_{k,j} 上去。

当然， Strassen 类的分块方法可以加速这一过程，但分块到头也总要做 2 x 2 的矩阵的乘法（何况在过去的实践中，分块过小性能并不一定会有提升）。因此，要真的让矩阵运算达到极致性能，专门设计一个部件来完成这些工作确实是必要的。

需要指出的是，矩阵单元真正开始大规模出现是跟 AI 密不可分的。最早引入矩阵加速概念的 NVIDIA 的 Tensor Core 一类，近期的典型案例还有 Apple AMX/ARM SME 等等。其共同特征有以下几点：

- 面向 GEMM 操作，SRC1 可以是矩阵或向量、 SRC2 一般是向量，输出外积
- 实现的往往是 outer-product-and-accumulate 操作
- 兼容（甚至着重在）低精度运算（bf16 fp16 int8）上
- 均是作为某种 "协处理器" 存在

#### 向量 x 向量

以 Apple AMX 为例，寄存器模型上，AMX 有三个 register pool X, Y 和 Z 。在 AMX 指令中，x 和 y 分别是 register pool X 与 Y 中 64-byte 长的一个寄存器（register pool X 和 Y 各有 8 个这样的寄存器） 。而 z 则直接是一个 64 x 64-byte 的二维寻址寄存器（矩阵寄存器）。上述一共有 80 个 64-byte 的寄存器。

对每组 register pool 各有一组从内存中读写的 ld(x,y,z) st(x,y,z) 指令。运算指令上，大概可以分为向量和矩阵两种模式。矩阵模式允许形如 `z[j][i] ±= f(x[i], y[j])`  这样的操作，而向量模式允许形如 `z[_][i] ±= f(x[i], y[i])` 这样的操作。在此基础上对浮点数提供了 fma/fms ，对整数提供了 mac ，此外提供了 vecint/vecfp 和 matint / matfp 开头的一系列指令来完成 Indexed, shuffle, 以及一些常见的其他操作。

#### 矩阵 x 矩阵

具体到 Tenstorrent 而言，FPU 有更加与众不同的地方，即 SRC2 也可以是矩阵。

> Matrix engine (aka FPU)** that performs Matrix multiplication, elementwise, and dot product operations on small matrices (or tiles) of shape 32x32 and similar

编程指南<span class="wikilink wikilink--missing" title="未导入的页面">5</span>(#ref_5)中详述了这一部分，并补充了 tranpose 操作的存在。这种想法可能更类似于<span class="wikilink wikilink--missing" title="未导入的页面">6</span>(#ref_6)<span class="wikilink wikilink--missing" title="未导入的页面">7</span>(#ref_7)RISC-V 的矩阵扩展（两种扩展的区别主要在于是否依赖 V register）或者是 NVIDIA Tensor Core<span class="wikilink wikilink--missing" title="未导入的页面">8</span>(#ref_8)。

#### 矩阵？向量？

[](https://zhuanlan.zhihu.com/p/12618700803)

这篇文章主要是从 AI 的角度来讨论，作者对此恐怕没有太多能补充的。设计上考虑稀疏比较多的架构，影响力比较大的可能就是 Graphcore （PEZY 可能也可称之为类似的思路）和 Cerebras 。这几家相比 AI ，可能在传统 HPC 的应用更受欢迎。比如 PEZY 最近发表的基因解析方案<span class="wikilink wikilink--missing" title="未导入的页面">9</span>(#ref_9)（四块 PEZY-SC3 性能略微超过八块 NVIDIA H100），Cerebras 主攻的 CFD 等等。当然， Cerebras 有特殊的 scaling ，在大语言模型方面有自己的优势。而 Graphcore<span class="wikilink wikilink--missing" title="未导入的页面">10</span>(#ref_10)从过去的表现看可能并不真的适合深度学习方案，在性价比上劣于 NVIDIA 。

当然，这个话题继续讨论下去，就变成 “我们为了什么需求做硬件” 的问题，牵扯到许多复杂的因素，也超出了本文的讨论范围。

#### 稀疏矩阵与向量运算

Tenstorrent 的 SFPU 采用的是某种 Vector Engine ，但 ISA<span class="wikilink wikilink--missing" title="未导入的页面">11</span>(#ref_11) 并没有用 RVV ，其向量特征可能主要体现在 lane 相关的控制上。这可能是因为 Tenstorrent 对 SFPU 的定位是激活函数与后处理（实现的大多数操作是 int 和 fp 的算数操作，也只能从 DST 寄存器里进行 SFPLOAD/SFPSTORE 操作）。类似的倾向还表现在 MDGRAPE-4A 上，虽然使用了 RISC-V ，但仍然自己设计了 128-bit SIMD 来做固定管线的后处理。在这种场景下，用 RVV 并不一定有明显的优势。
