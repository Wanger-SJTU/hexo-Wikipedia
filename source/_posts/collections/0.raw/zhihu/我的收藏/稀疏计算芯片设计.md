而在面向 AI 的计算中，如果有这种超级稀疏矩阵计算加速，可以使用 block-sparsity flashattention 来进行加速，兼容密集计算硬件。更多情况下是使用结构化稀疏或细粒度下的非结构化稀疏( 如 NV tensor core 支持 2:4 半结构化权重矩阵稀疏)，此时无需使用 CSR CSC 进行 meta array 存储，而是使用 index 或 bitmap。尽管粒度不同，但是共性问题和超级稀疏矩阵计算是相同的：使用内积时面临的是坐标匹配问题，使用外积计算时面临的是如何 merge 大量中间结果的问题。在结构化稀疏中外积和 Gustavson 其实区别没那么大。内积依然是最弱的，因为坐标匹配问题的确无法解决。

本文针对内积、外积、Gustavson 积三种计算方式，分别选择了 target on TPU、GPU、CPU 三种平台。

## 1. 内积 temporal-unroll

《S2TA: Exploiting Structured Sparsity for  Energy-Efficient Mobile CNN Acceleration》

本文提出常见几种计算模型：1. dense 2. clock gated 3. weight sparsity

又有两种基于 dual sparsity 的模型：

4. spatial-unroll，导致在空间上有运算器空闲。 5. temporal-unroll，导致在时间上有运算器空闲。

当然这也没办法，这是内积的固然问题。要解决这个问题只能放弃 dual sparsity 采用 weight sparsity。

### 2.4 硬件架构

猜测的硬件架构如下图，每个 SP 有两个 tensor core，每个 tensor core 有两个 Octet，每个 Octet 的计算资源上有8个 FEDP，每四个 FEDP 负责一个 threadgroup 的计算，每个 Octet 负责间隔为4的 threadgroup 的计算任务。这样的话每拍每个 threadgroup 可以进行4个 FEDP，而每个step需要8个 FEDP，所以每个 step 需要两拍。这个结论和实测相符，说明猜测正确。

在 Octet 的数据复用层面，存在两个可复用角度：

- 在 threadgroup 分配上，相隔为4的 threadgroup 共享B，从而可以减少B访问带宽
- 在 step 上，step0,2，step1,3 共享一个A，step0,1，step2,3共享一个B因此在 Octet 设计上每个 Octet 管理相隔为4的threadgroup，同时对 A B C 三个矩阵都设置了缓冲器。

因此计算一个 161616 的 GEMM 所需的时间是 4\text{set}\times 4\text{step}\times 2\text{cycles}/\text{step}=32 

## 3. 外积 tensor core

《DSTC: Dual-Side Sparse Tensor Core for DNNs  Acceleration on Modern GPU Architectures》

首先提出在 dual sparsity 时内积的缺点，因此使用外积计算 dual sparsity

切换为外积计算模式后，和超级稀疏矩阵中的计算一样，也分为三个部分：multiply, merge, write-back

### 3.1 硬件架构设计


与传统内积的 tensor core 不同，此时 Octet 执行外积操作。每个 Octet 执行 818 的外积运算，每个 tensor core 执行 848 的外积运算。

### 3.2 warp 级 tile


前面说的是在 warp 级做的计算，下面是在 inter-warp 间的 tile 和 unroll 计算过程。相对于对一整个大矩阵进行 bitmap 压缩，这样会造成 partial matrix 分散在各个 warp 中，导致 merge 阶段要跨 warp 进行从而使 mem locality 丧失。本文采取的在 Tm*Tn 维度上进行 bitmap 压缩，使得数据局部性增强。为了配合这个技术又使用了二级 Bitmap 表示方式：

### 3.3 TIA and merge phase


TIA 的作用是把 bitmap 转换为密集的、可以索引 Accu SRAM 的index。前两级使用的归并排序的网络，微架构上用 bitonic 或 insertion 都行，本文选择了 crossbar 和 barrel shifter。最后一级也是 shifter。但这个需求有一个更优的方法，将在下一节介绍。

operand collector 把不同时间上对同一个 bank 的请求进行压缩从而提高带宽利用率。

### 3.5 如何支持非结构化稀疏

外积计算的本质是把 A 进行列压缩，把 B 进行行压缩，因为无需进行 index 匹配，所以在计算上呈现密集的行为，所以计算资源不会有内积一样空闲的情况。因此支持非结构化稀疏就比较简单了，根据 non-zero value 的数据多少动态改变 Step 的数量即可。

### 4.2 reverse butterfly network

然而这种网络并不是 optimal，已证明 reverse butterfly network 是 pareto optimal 的交换网络，交换所需的节点数量最少，所以利用这个特性，如果能用 reverse butterfly network 完成这个工作那应该是硬件效率最高的

Benes 也是 reverse butterfly network 的一种，利用 Benes subnetwork 的递归和分治特性，如果每个 subnetwork 内部可以实现保序，在 subnetwork 外层实现奇偶分治，就可以递归地实现保序数据压缩。

最终通过级联的 prefix scan 和 reverse butterfly network 可以实现这个效果。prefix scan 将 bitmap 变换为 index，reverse butterfly network 通过 C = (inA.valid∧inA.index[l])∨(inB.valid∧¬inB.index[l])  实现奇偶分治路由
