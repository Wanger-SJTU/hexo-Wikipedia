尽管文本在大多数3D程序中随处可见，但OpenGL本身并没有提供用于文本渲染的原生API。为了弥补这一不足，Mark Kilgard引入了<strong>纹理字体</strong>[Kilgard 1997]。这一技术拥有不错的性能表现，以及在大多数情况下不错的渲染质量。然而，这一技术在正交投影模式(屏幕空间)下，当字体较大时，由于像素化的影响，在字体较小时，由于不正确的hinting和定位，渲染质量下降严重。在本文，我们介绍一种用于正交投影模式的高质量纹理字体渲染方法。这一方法可以做到在屏幕上精确呈现任意形状的字符。

### 1.概述

Mark Kilgard[1997]引入了一个基于OpenGL的纹理字体方案。这一方案将多个光栅化后的字符打包到一张只有alpha通道的纹理中，通过一个查找表，在需要显示字符时定位字符在纹理中的位置，然后将位置信息作为一个四边形的纹理坐标进行渲染。这一方案允许对字符进行任意的旋转，缩放，以及投射在任意的3D表面上。此外，这一方案还可以直接载入标准的位图字体文件进行渲染(比如X11的字体文件)，这使得我们可以使用标准的字体创作工具来实现渲染一些特殊的字符。这一方案的主要缺点是，当分辨率较高时，即使使用了双线性过滤，字符仍然会变得马赛克化(如图2)。为了解决这一问题，Chris Green[2007]引入了有向距离场取代光栅化的字符。随后，Gustavson[2012]证明有向距离场可以被高效计算。但不幸的是，在分辨率非常高时，仍然会出现走样，这时，我们只能采用向量字体来实现较为完美的渲染效果。在可编程着色器到来之前，人们使用贝塞尔曲线和线段来逼近实现向量字体，这一方式计算代价非常高。Loop和Blinn[2005]引入了一个分辨率无关的二次和三次样条曲线渲染方法。通过对字符进行恰当地细分，我们可以使用这一渲染方法实现分辨率无关的高质量字体渲染(并且支持反走样)。最近，Kilgard[2012]提出了一个包含两步(模板和覆盖)的GPU加速方法，这一方法满足了OpenVG的大部分标准。

尽管，看上去向量方法是文本渲染的最佳解决方案，但这一方法无法进行hinting。这一因为向量方法是分辨率无关的,但hinting和光栅化后的像素网格却密切相关。历史上，hinting(和光栅化一起)在低分辨率场景被引入使用。实际上，文本的视觉表现依赖于设备的DPI(每英寸点数)和PPI(每英寸像素数)，Maxim Shemarev [2007]给出了在不同系统上渲染高质量文本的几个准则：

- 为LCD平板使用水平RGB次像素反走样
- 不使用水平hinting，只使用垂直hinting
- 使用来自未hinting字符的精确advance值
- 使用来自kerning表的精确的高分辨率值
我们将解释如何使用上述准则进行简单的文本渲染。

### 2.文本纹理化

文本纹理化已经被广泛应用。这一方法的主要思想是将光栅化后的字符渲染到一个或多个纹理，然后通过渲染带有纹理的四边形来渲染文本。这一方法有多种变体，有的将一整句话渲染到一张纹理，有的渲染一个单词，有的渲染一个字符。有的将所有要使用的字符渲染到一张纹理。我们这里讨论将所有要使用的字符渲染到一张纹理这一方法，使用这一方法允许只使用一张纹理和一个顶点缓冲来渲染所有文本。为了处理字体文件，我们使用了FreeType库。FreeType库可以在大多数平台使用，并且提供了独立于字体格式的处理字体的统一方式。它还支持输出高质量的光栅化字符。除了FreeType库外，还有一个Barret编写的用于处理TrueType字体的单文件处理库。

<strong>2.1.纹理集</strong>

在二维纹理上存储字符是一个典型的<strong>装箱问题</strong>。这一问题是组合优化的经典问题：给定一个矩形序列 (R_1,R_2,...,R_n),R_i=(w_i,h_i) ，求一个多边形(P_1,P_2,...,P_n),P_i=(x_i,y_i) 可以包括所有矩形，并且任意两个矩形不存在相交或包含关系，同时满足最小化包装大小。这一问题已经被人们大量研究，并且给出了许多有效的算法。这里，针对我们的问题，我们应该使用在线包装算法(即对未来要包装的对象信息未知)，从而可以在需要时即时地存储新的字符到纹理上。Jukka Jylänki[2010]给出了大量装箱算法的测试反馈。这里，我们基于这一测试反馈，选择使用Skyline Bottom-Left算法。根据我们的使用经验，这一算法似乎非常适合快速随机字符的存储使用。图3给出了使用这一算法产生的一个字符包装的结果。

字体hinting是通过具体的指示(hints)调整定义字符轮廓的控制点，从而使字符的轮廓可以更好地和像素网格对齐。在较低的屏幕分辨率下，hinting的作用非常大，它可以让字符更加清晰易读，如图4所示。当没有字体文件不包含hinting时，可以使用FreeType的auto-hinting。

![](/images/collections/0.raw/zhihu/%E7%BC%96%E7%A8%8B%E5%90%91/asset/img_6dc7d4d69154.jpg)

图4：顶部是没有使用hinting渲染的文本，底部是使用hinting渲染的文本。hinting版本更加清晰，但由于没有考虑字形，文本串变得更长为了获得更好的渲染质量，Shemarev [2007]建议不使用水平hinting，只使用垂直hinting。hinting通常由光栅化引擎(在这里就是FreeType)负责，但FreeType并没有选项可以不使用水平hinting(注意，可以通过外部工具编辑字体文件的hinting)。但我们可以使用一个技巧，指定一个超大的水平DPI(100倍于垂直DPI)，然后指定一个变换矩阵对字符进行缩放来减少水平hinting的影响，代码如下所示：

FT_Set_Char_Size( face, (int)(32*64), 0, 72*scale, 72 );

我们使用这一技巧渲染了图1最右边只有垂直hinting的字符。这一技巧通过牺牲垂直方向的精度来保证水平方向的精度。

<strong>2.3.次像素定位</strong>

FreeType库可以在RGB模式下使用次像素反走样进行字符光栅化。这只解决了一半的问题，我们还需要使用次像素来更为精确地显示字符纹理。使用包含小数的像素坐标不解决这一问题，纹理插值会让其对应整数像素坐标。通过使用一个大小在0到1像素之间的次像素值，我们可以在片段着色器中更加精确地进行文本渲染。片段着色器代码在下面给出。

表1：依赖于偏移值s的三种不同情况下的次像素定位`uniform sampler2D texture;
uniform vec2 pixel;
varying float shift;

```cpp
void main()
{
	vec2 uv = gl_TexCoord[0].xy;
	vec4 current = texture2D(texture, uv);
	vec4 previous = texture2D(texture, uv+vec2(-1,0)*pixel);
	float r = current.r;
	float g = current.g;
	float b = current.b;
	float a = current.a;
	if( shift  1..0 )
	{
		float z = 3.0*shift;
		r = mix(current.r, previous.b, z);
		g = mix(current.g, current.r, z);
		b = mix(current.b, current.g, z);
	}
	else if( shift  2..0 )
	{
		float z = 3.0*shift-1.0;
		r = mix(previous.b, previous.g, z);
		g = mix(current.r, previous.b, z);
		b = mix(current.g, current.r, z);
	}
	else if( shift  1.0 )
	{
		float z = 3.0*shift-2.0;
		r = mix(previous.g, previous.r, z);
		g = mix(previous.b, previous.g, z);
		b = mix(current.r, previous.b, z);
	}
	gl_FragColor = vec3(r,g,b,a);
}
```


需要注意某些情况下，次像素渲染可能会造成或多或少的严重彩色条纹，可以通过调节像素之间的权重来减少。可以通过FreeType库的FT_Library_SetLcdFilter来调整寻求模糊强度和彩色条纹之间的最佳折衷。

<strong>2.4.Kerning和Advance值</strong>

Kerning值是用来手动或自动调整两个字符间的空间，来让渲染结果看上去更好(如图5)。Kerning值加上字符的Advance值定义了显示下一个字符要移动的水平距离(如图6)。一个Kerning值对应一个<strong>字符对</strong>，用于在两个字符间增加或减少空间。字体文件可能包含了一个可选的kern表用于指定字符对间的Kerning值。然而，由于更精细的字符定位表(GPOS)的普及(处理起来更加复杂)，包含kern表的字体越来越少。FreeType库可以直接访问kern表，访问GPOS表则需要HarfBuzz或Pango库。使用FreeType库可以方便地获取高分辨率的未hinting字符得kerning和advance值。

物理设备产生的光的亮度通常不是线性的，这就造成渲染的文本一定的视觉效果不佳。比如，白色背景上的黑色文本，对应的相反颜色实际上并非是黑色背景上的白色文本，为了获得更佳的显示效果需要我们针对每个渲染的字符进行Gamma校正，而不仅仅是对整个帧缓冲进行Gamma校正。

### 3.总结

我们在本文给出了遵循Shemarev [Shemanarev 2007]准则，实现高质量文本渲染的方法。这一方法不仅速度快，而且内存需求较低。如果读者需要进行高频的文本缩放或在透视投影下使用文本，有向距离场方法会更合适。在正交投影模式下，组合使用上述两种方法可以在速度，质量和内存需求上得到更好的结果。对于中高分辨率的场景，向量方法更加合适，特别适合对于精度要求高的CAD软件。

下面的Python代码给出了用于演示高质量2D文本渲染使用的Skyline Bottom-Left装箱算法。这一代码的输出效果如图7所示。

#!/usr/bin/env python

```cpp
import sys
class Bin:
	’’’
	Bin packer class
	================
	The algorithm is based on the article by Jukka JylaÌ´Lnki : "A Thousand
	Ways to Pack the Bin - A Practical Approach to Two-Dimensional
	Rectangle Bin Packing", February 27, 2010.
	Example usage:
	--------------
	bin = Bin(512,512)
	region = bin.pack(20,20)
	region = bin.pack(10,10)
	...
	’’’
	def __init__(self, width=1024, height=1024):
		""" Initialize a new bin of given size. """
		self.width = width
		self.height = height
		self.nodes = [ (0,0,self.width), ]
		self.used = 0
		def fit(self, index, width, height):
		""" Test if region (width,height) fits into self.nodes[index]"""
		node = self.nodes[index]
		x,y = node[0], node[1]
		width_left = width
		if x+width > self.width:
			return -1
		i = index
		while width_left > 0:
			node = self.nodes[i]
			y = max(y, node[1])
			if y+height > self.height:
				return -1
			width_left -= node[2]
			i += 1
		return y
	def merge(self):
		""" Merge nodes where possible """
		i=0
		while i  len(self.nodes)-1:
			node = self.nodes[i]
			next_node = self.nodes[i+1]
			if node[1] == next_node[1]:
				self.nodes[i] = node[0], node[1], node[2]+next_node[2]
				del self.nodes[i+1]
			else:
				i += 1
	def pack(self, width, height):
		"""
		Try to pack the given region (width,height) of given size and return
		the newly allocated region as (x,y,width,height) or None
		"""
		best_height = sys.maxint
		best_index = -1
		best_width = sys.maxint
		region = 0, 0, width, height
		for i in range(len(self.nodes)):
			y = self.fit(i, width, height)
			if y >= 0:
				node = self.nodes[i]
				if (y+height  best_height or
					(y+height == best_height and node[2]  best_width)):
					best_height = y+height
					best_index = i
					best_width = node[2]
					region = node[0], y, width, height
		if best_index == -1:
			return None
		node = region[0], region[1]+height, width
		self.nodes.insert(best_index, node)

		i = best_index+1
		while i  len(self.nodes):
			node = self.nodes[i]
			prev_node = self.nodes[i-1]
			if node[0]  prev_node[0]+prev_node[2]:
				shrink = prev_node[0]+prev_node[2] - node[0]
				x,y,w = self.nodes[i]
				self.nodes[i] = x+shrink, y, w-shrink
				if self.nodes[i][2]  0:
					del self.nodes[i]
					i -= 1
				else:
					break
			else:
				break
			i += 1
		self.merge()
		self.used += width*height
		return region
```
