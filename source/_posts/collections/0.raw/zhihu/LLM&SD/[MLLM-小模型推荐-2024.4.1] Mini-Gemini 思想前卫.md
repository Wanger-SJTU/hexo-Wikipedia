论文名：Mini-Gemini: Mining the Potential of Multi-modality Vision Language Models

论文链接：[https://arxiv.org/abs/2403.18814](https://link.zhihu.com/?target=https%3A//arxiv.org/abs/2403.18814)

开源地址：[https://github.com/dvlab-research/MiniGemini](https://link.zhihu.com/?target=https%3A//github.com/dvlab-research/MiniGemini)

本论文同时也是 LLaMA-VID 佬的作者，代码和数据全部开源，值得关注。

### 简介

之前的多模态小模型大部分是使用 phi2-2.7b 语言模型，最近 google 开源了 gemini 系列，也包括了小模型，作者基于这个基座进行研究。

作者主要是探索了 3 个方面

- **高分辨率视觉 token**。高分辨率视觉 token 重要性不言而喻，不过作者建议在不增加视觉 token 数目的情况下使用额外的视觉编码器进行高分辨率细化
- **高质量数据。**作者基于开源数据，构建了一个高指令的数据集**，**可以促进精确的图像理解和基于推理的生成
- **扩展 VLM 应用场景**。使其可以结合文生图模型，解锁文本生成和图像生成功能
基于这些策略，实现了可观的性能增益。部分指标超越闭源模型。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_3f92286a6103.jpg)

下面对每个点进行说明

### 1 双视觉编码器和 token mining

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_dfd691f190f0.jpg)

为了提高模型对小物体的理解和感知能力，高分辨率信息是非常重要的。作者使用了 ConvNeXt 作为高分辨率信息注入编码器。需要注意，ConvNeXt 必须使用和文本对齐的版本，具体是 LAION-pretrained ConvNeXt。

低分辨率分支依是 CLIP-ViT，输出维度 (N,C)，高分辨率选择 LAION-pretrained ConvNeXt，输出维度是 (N'，N'，C)，一般来说 N' 是图片输入尺寸的 ，然后可以通过 reshape 操作，变成 (NxM^2, C) 唯度。

这个 reshape 很有讲究，其意思是低分辨率分支中的一个 token 对应高分辨率分支中的 M^2 个 token，且是空间关系上对应的，类似 pool 操作，**空间关系一定要保留，后续有用**。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_1fac3ecd8119.jpg)

得到上述两个特征后，现在需要做的是将高分辨率信息注入到视觉 token 中。作者采用的方法是交叉注意力方式，主要也是为了**保持 token 数不变**。**

以低分辨率的 CLIP 输出为 query，KV 是高分辨率特征，这样就可以保证输出数目不变。如上 (a) 所示。公式为：

>               TV = MLP(Q + Softmax(φ(Q) × φ(K)T ) × φ(V ))

注意上述做法要保证任何一个低分辨率 token 都只会和 M^2 个子区域进行相似度计算**，这样可以确保是高效且非常合理的。**并不是无脑的 N 个 token 和 NxM^2 个 token 进行注意力计算。我觉得作者这种设计非常好，很合理。**

作者为了体现这个设计的优点，还举了一个 token 数扩展的例子。**也就是说上述设计可以轻松实现 token 数不变，也可以实现 token 数扩展的功能**，如 (b) 所示。核心做法是要确保 HR 输入分辨率是 LR 输入的 4倍，然后再将两者分辨率 concat 起来就可以得到 5xN 的 token，后续计算就可以也采用交叉注意力方式得到最终扩展 5 倍的视觉 token 了。

### **2 高质量数据****

- 预训练阶段**：来自 LLAVA 过滤 CC3M 数据集的558K图像标题对和来自 ALLAVA 数据集的 695K 采样 GPT-4V 响应字幕 总共 1.2M 
- **指令微调阶段**：从 LLAVA 数据集中采样 643K 单回合和多回合对话(不包括21K TextCaps 数据)；来自ShareGPT4V，10K LION-GPT-4V 描述数据；来自 ALLAVA 数据集的 700K GPT-4V 响应指令对，以及来自LIMA 和OpenAssistant2 的 6K 纯文本多轮对话。为了增强 OCR 相关能力，我们进一步收集了 28K QA 对，其中包括 10K DocVQA 、4K ChartQA 、10K DVQA 和 4K AI2D 数据。一般来说大约有 1.5M 条与指令相关的对话
除了上述的数据外，作者前面说过希望扩展 MLLM 的应用场景，也就是希望 MLLM 能用于文生图场景，类似 DALLE3 这种。作者的做法，**让 MLLM 通过特殊的 token 来激活输出适合 DALLE3 或者 SDXL 的文本，然后将该文本直接丢给这些模型，实现文生图功能。**

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_147e1555ddde.jpg)

如上图所示，通过在用户输入指令最后显式的写 ** token**，然后 MLLM 会在回复的最后返回  和  以及中间内容。这个内容就可以直接丢给 SDXL 了。

**为了能够实现这个功能，核心是要构建数据。作者构建了 13k 条数据。训练数据包括 2 个方面

(1) Simple instruction re-caption**

采用 LAION-GT-4V 中的8K 描述性图像cation 数据，并让 GPT-4 在 SD 域中反向推断相应用户的短输入和目标caption，具体 prompt 如下图：

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_60ef1b8e8072.jpg)

给定一些描述性图像描述案例，然后再给定一些高质量的能用于 SDXL 的 prompt 文本，同时注入 GPT4V 生成的图文描述数据，让 GPT4 仿照这个格式，基于给定的图片描述生成训练样本，包括用户输入，相关图片描述和适用于 SDXL 的 prompt

**(2) In-context prompt generation**

基于LIMA 和 OpenAssistant2 中的一些高质量的真实世界对话上下文生成提示，生成适合对话上下文的图像，总共生成了 5K 条指令。**对于这两种数据，在对 GPT-4 的每次查询中，从 GigaSheet 中随机抽取5个高质量的SD文本到图像提示，作为上下文示例，以获得生成的目标提示。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_2f38216b449c.jpg)

### 实验**

实验部分，作者做的非常详细。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_6ba5968cfeab.jpg)

- Info mining 就是前面提到的维持 token 数不变下的设计，可以发现**大部分任务确实都有涨点**
- **继续扩展 HR 分辨率但是保持 token 不变，依然能够涨点，但是涨幅比较有限**
- Conv-B 作为高分辨率编码器，效果不太好，这说明两个编码器的容量应该要匹配才是合理的，同样的如果换成超大的 ConvX-XXL 效果也不是很好，没有达到预期。不过由于 ConvNeXt 是始终不训练的，XXL 在有些任务上掉点这个没有想太清楚，有可能是 XXL 本身的问题，和 LLM 训练是无关的。
![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_1cdac4b7aeda.jpg)

作者还专门调研了每个数据集的作用，如上所示。主要涨幅在于 Text VQA 和 MM-Vet，MME 任务涨点不多，可能是不太需要高分辨率信息。

如果扩展 token，性能还可以进一步提高，说明这种方法是可行的，只是代价有点高。

个人看法：**虽然作者做了不少数据的实验，但是似乎评测集过少。而且和大部分作者类似，都缺失对数据集的深入分析。可能是比较脏的火，大家还是习惯以 model 为中心**

**

在论文最后，**作者说对于视觉理解来说，计数能力和复杂视觉推理能力还远远不能令人满意。这可能是由于缺乏相应的训练数据，尤其是在预训练阶段。同时，对于基于推理的生成，在这项工作中使用文本来桥接 VLM 和扩散模型，因为在基于嵌入的方法中没有发现明显的增益。后续将尝试找到一种更先进的视觉理解、推理和生成方式。

也就是说作者其实一开始是想将文生图功能集成进来，做成端到端，但是发现不太 work，所以设计了折中方案。
