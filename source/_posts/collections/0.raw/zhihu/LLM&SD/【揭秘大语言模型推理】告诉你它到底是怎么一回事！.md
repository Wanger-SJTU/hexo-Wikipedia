### 大语言模型是什么？

大语言模型（Large Language Model，简称 LLM）是一种基于深度学习的人工智能模型，它被训练**来理解和生成人类语言**。可用于各种自然语言处理任务，如文本生成、文本分类、情感分析、机器翻译和对话系统等。**大语言模型的一个关键特性是规模大**。这些模型通常有数十亿甚至数万亿的参数。这使得它们能够学习和理解语言的复杂性和多样性。这种规模的模型可以生成流畅、连贯且在很大程度上看起来像人类写作的文本。**另一个特性是基于[Transformer 结构](https://link.zhihu.com/?target=https%3A//arxiv.org/abs/1706.03762)。Transformer 结构的关键特性是它的自注意力（self-attention）机制，这使得模型能够在处理文本时考虑到各个单词之间的关系**。这种机制使得Transformer模型能够处理长距离依赖（即文本中相隔较远的单词之间的关系），并且可以并行处理文本，从而提高计算效率。**
让全球刮起 AI 风潮的 ChatGPT，就是 OpenAI 基于 GPT-3.5（Generative Pretrained Transformer）-175B（1750 亿参数）开发的一个大语言模型聊天应用。ChatGPT 的优秀表现充分验证了 规模大+预训练+Transformer结构 **的大语言模型的智能化潜力。这一突破性的应用不仅展示了AI在理解和生成人类语言方面的强大能力，也为人机交互设定了新的标准。**
因此，在全球范围内，这类大语言模型如雨后春笋般争先恐后地推出，希望能够在各自的领域中实现类似的突破。

### 
大语言模型推理

#### 
什么是推理？什么是部署？

讲大语言模型推理之前，先辨析这两个概念。

大语言模型推理：**推理是指**使用训练好的模型进行预测的过程**。对于大语言模型来说，推理通常涉及到**给定一段输入文本**（例如，一个问题或者一个对话的上下文），**模型会生成一个输出**（例如，一个答案或者一个对话的回复）。在进行推理时，**模型的参数是固定的，不会发生改变**。

**大语言模型部署**：部署是指将训练好的模型应用到**实际环境中的过程**。这可能涉及到将模型移植到一个服务器上，然后通过API接口提供服务，或者将模型嵌入到一个应用程序中。在部署过程中，需要考虑**模型的性能、可用性、安全性等因素**。**
理论上来说，模型推理属于模型部署的一部分，也是模型部署最核心的一个部分。本文章主要是聚焦于大语言模型推理这个范围**。关于部署的部分，暂不会涉及。

#### **模型推理为什么重要？****

大语言模型推理的重要性主要体现在以下几个方面：

性能和效率**：推理是模型应用的关键环节，其性能和效率直接影响到模型的实用性。如果推理速度慢，那么模型在实际应用中的体验将大打折扣。例如，如果一个聊天机器人的回复速度过慢，那么用户可能就会失去耐心，不愿意使用这个机器人。

**成本**：大语言模型的推理通常需要大量的计算资源，这意味着高昂的成本。例如，OpenAI的GPT-3模型有1750亿个参数，如果使用传统的CPU进行推理，那么成本将非常高。因此，如何降低推理成本，提高推理效率，是大语言模型推理面临的重要问题。**
*推理的本质是性能优化，降本提效。***

### **大语言模型推理有哪些挑战？

随着大语言模型的应用爆发式增长，大语言模型推理需求部署需求也日益增长。作为业务落地的最后一站，模型推理存在巨大挑战。
从上文可知，大语言模型的两大特性分别是模型参数大和基于Transformer结构。而这两大特性带来了诸多挑战。**

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_4911906ec00e.jpg)

- **首先是计算量巨大。**
Transformer 结构的Self-Attention机制使得模型能够处理长距离依赖，但同时也带来了**计算复杂性的增加**。**自注意力机制（Self-Attention ）**的**计算复杂度是O(n^2 * d)**，**其中n是序列长度，d是模型的隐藏层大小**。

例如，GPT-3的一个版本有1750亿个参数，隐藏层的大小为12288。chatGPT限制长度的2048，计算量 = n^2 * d = 2048^2 * 12288 = 51,381,248,000,000。所以，理论上，每次推理需要进行大约**51.38万亿次**操作。**对算力是个很大的挑战。**

- **第二是显存占用大。**
Transformer的自注意力机制（Self-Attention ）在计算过程中**需要存储中间结果**，**而这些中间结果对于内存和缓存的需求是非常大的**。自注意力机制需要计算一个注意力矩阵，其大小为 (序列长度 x 序列长度)。

对于一个序列长度为 N 的输入，注意力矩阵就是一个 N x N 的矩阵。每个元素都是一个浮点数，如果我们使用 float32 来存储这些浮点数，那么每个元素就需要 4 字节的内存。因此，**对于一个序列长度为 N 的输入，自注意力机制需要的内存量就是 N x N x 4 字节。**

例如，如果序列长度为 2048，那么自注意力机制需要的**内存量就是 2048 x 2048 x 4 字节 = 16GB**。这还**只是一个**自注意力层的需求，如果模型**有多个自注意力层，那么需要的内存就会更多**。

而更重要的是，大语言模型通常有**数十亿甚至数万亿的参数**。以GPT-3.5为例，**模型参数为1750亿，如果以 FP32 进行存储，光是加载这个模型就需要内存700GB**。

- ** 还有硬件资源需求高和并发支持**
Nvida A100 GPU 是世界顶尖级的GPU，目前全世界范围内都是**一卡难求**。Nvida A100 GPU显存是80GB，一台 Nvida AGX服务器是 8*A100卡，总显存640GB。也就是说，**一台 Nvida AGX服务器加载不了一个1750亿参数的大语言模型。**

**所以，大语言模型推理对**硬件资源需求要求非常高。而在单个设备上进行推理，可能会面临显存不足的问题，甚至无法顺利完成部署。

为了解决这个问题，大语言模型需要采用**分布式推理，支持并发。**

**这导致推理成本巨高。**高昂的推理成本，让使用大语言模型应用的门槛陡增。所以主流大语言模型应用会限制用户量，限制用户提问量甚至限制用户提问的长度。这都是为了降低模型推理的成本。

### **大语言模型推理关心什么

降低模型推理成本是核心诉求，那如何来衡量模型推理效果呢？一般会参考如下指标：

- 延迟（Latency）**
延迟是指从输入文本数据到得到结果的时间。正常情况下，延迟越低越好。而由于人类阅读速度是有上限的。所以大语言模型的有一个合理延迟区间。

成年人的阅读速度：英文文本平均阅读速度大约是200-300词/分钟，即3-5词/秒。中文文本平均阅读速度大约是300-500字符/分钟，即5-8字符/秒。

分词器分词法则：对于**英文**，常见的分词器（如WordPiece或BPE）可能会将一个单词分为多个token，尤其是对于长单词或不常见的单词。

因此，英文中的一个token并不总是对应一个完整的单词。所以模型输出速度可能需要提高到**5-10 tokens/秒**。对于中文，由于其字符性质，常见的分词器可能会将每个字符视为一个token，但也可能会将常见的词汇或短语合并为一个token。输出速度应达到**5-8 tokens/秒。**

实际上，为了提供流畅的用户体验，模型的输出速度可能需要远远超过这个速度，尤其是在交互式应用中，用户可能希望模型能够即时响应。合理的目标是使模型的输出速度**至少达到10-15 tokens/秒。一般来说，单token的延迟在100ms以内，可确保流畅的用户体验。**

- **First token latency**
指从输入文本到生成第一个单词的延迟。即用户在提问后等待出第一个结果的时间。也是实际应用中业务比较关注的另一个延迟指标。**一般在2-4秒内用户比较容易接受的**。

- **吞吐量（Throughput）**
指模型在单位时间内能处理的数据量（通常表示为每秒处理的tokens数量）。这个指标直接影响到模型在实际应用中的效率、成本和用户体验。

**吞吐量越大越好，但是因为硬件资源的限制，吞吐量都会有上限。****

- QPS（Queries Per Second）**
衡量系统或服务在每秒内可以处理的查询或请求的数量。**QPS越大，说明能支持的用户越多**，但是这个指标不仅仅受限于模型推理，更多的负载均衡以及服务策略等因素。

### **
大语言模型推理都在做什么？

聊完指标，我们再来看看主流的模型推理优化方案。

- 硬件选型**
模型推理的性能在很大程度上取决于硬件的性能。不同的硬件（如CPU、GPU、TPU、FPGA等）有不同的计算能力和内存特性，因此需要针对特定的硬件进行优化。例如，GPU和TPU都支持**并行计算**，可以大大加速模型的推理。

目前主流的推理硬件还是Nvida A100，A30,4090等。目前国产AI芯片和CPU以及边缘端设备都还不足以投入到实际应用中。还需要一段时间。

- **计算优化**
指提高模型推理时的计算速度和效率，使模型能够在更短的时间内返回结果。例如算子融合，矩阵计算优化等。

*算子融合：将多个算子（即模型中的操作）融合成一个更大的算子。可以减少算子之间的数据传输和同步，从而提高模型的运行效率。例如，如果你的模型中有一个卷积操作和一个激活函数操作，那么你可以将这两个操作融合成一个大的操作，这样在进行推理时，只需要进行一次操作，而不需要在两个操作之间传输数据。*

- **显存优化**
减少模型推理时所需的显存使用量，使模型能够在有限的显存资源上运行。例如KV cache技术，动态显存分配等。

- **模型量化**
在推理过程中，**将权重、激活动态**转化为更**低精度进行计算**。为了减少模型在推理阶段的显存占用以及提升模型的推理速度。但是，量化方案会直接决定精度，因此在选择量化方案时，一定要考虑硬件的条件。比如说，如果硬件芯片都没有支持INT8的计算单元，那么你软件的量化做的再好也没用。

- **分布式推理**
将模型推理任务分配到多个计算节点（例如，多台服务器或多个GPU）上进行。分布式推理的关键是如何有效地将任务分配到各个计算节点上，并合理地收集和整合各个节点的计算结果。也就是并行计算---将模型的计算分散到多个计算单元上，从而提高推理速度。常见的并行计算技术包括数据并行（Data Parallelism）、模型并行（Model Parallelism）和流水线并行（Pipeline Parallelism）等。

- **推理服务优化**
推理服务优化主要是指通过优化推理服务的架构和配置，提高推理服务的性能和稳定性。例如，可以通过负载均衡技术，将推理请求分配到多个推理服务器，从而提高推理服务的**吞吐量**。另外，还可以通过优化推理服务的配置，例如调整**批处理大小，优化内存管理**等，来提高推理服务的响应速度和稳定性。

总的来说，大语言模型推理优化方案是一个复杂而重要的问题。需要通过深入理解大语言模型的特性和推理过程，持续摸索去寻找更加有效的方法来解决这个问题，从而降低整个的模型推理过程的成本。
