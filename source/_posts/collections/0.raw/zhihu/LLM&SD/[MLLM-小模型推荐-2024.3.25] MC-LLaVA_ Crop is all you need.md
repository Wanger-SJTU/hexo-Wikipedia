### 简介

**这并不是一篇论文算法，而是一种解决输入分辨率限制的尝试**。在官方博客里面写的非常清楚。

整体方案就是通过多个裁剪块分别送给 ViT 进行视觉编码后，在输入到 LLM 中。方案特点在于在推理时候你可以根据任务难度设定不同个数的裁剪块来识别一些极小区域。同时考虑到裁剪块过多，作者还进行了简单粗暴的  visual token 剔除，可以确保整个系统在可控的算力成本下。

### 方法

作者提到他的方案基于两篇论文思想。

**(1) 视觉搜索****[V*: Guided Visual Search as a Core Mechanism in Multimodal LLMs](https://link.zhihu.com/?target=https%3A//arxiv.org/abs/2312.14135)

一个 LLM 引导的视觉搜索机制，采用具备世界知识的 LLM 进行高效的视觉查询。并且创建了 V∗ Bench，这是一个专门用于评估 MLLM 处理高分辨率图像和专注于视觉细节的能力的基准。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_aecd3675031f.jpg)

配备了视觉工作记忆**，该模型可以通过处理图像的较小部分来逐步进行推理，直到找到回答问题所需的所有信息。**论文流程看起来有点复杂，不过思想是容易理解的，也是通过不断的聚焦到小区域来回答问题。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_2c6422bdd7b9.jpg)

(2) 视觉裁剪****[Towards Perceiving Small Visual Details in Zero-shot Visual Question Answering with Multimodal LLMs](https://link.zhihu.com/?target=https%3A//arxiv.org/abs/2310.16033)

其思路是追踪模型的注意力，您可以找到最相关的部分。如果将图像裁剪到这些部分，可以在某些情况下将模型的性能提升高达10%。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_e6a812b65355.jpg)

作者想结合这两个论文思想，专门处理需要非常大分辨率的任务。

- 对原始大图进行重叠裁剪。作者觉得重叠裁剪会更好，因为重叠裁剪使得来自同一区域的视觉信息能够分散到多个嵌入向量中
- 每个裁剪块都记录相对全局图片位置坐标
- 然后采用如下做法对每个 patch 图像进行特征提取
![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_fd3433ee12dc.jpg)

假设当前图片经过编码器后，输出特征维度是 (728, 1152)，然后选择最后的 k 个序列(为啥是最后 k 个序列？难道是因为是重叠区域？)，其余序列丢掉。k 取决于你最终希望保留多少个 image token。

等所有 patch 特征都处理好后，再进行 concat ，然后类似 llava 丢到 llm 里面即可。

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_4de73bb1fb5c.jpg)

做法比较暴力，和 llava 1.6 有点类似。

模型是基于 Phi-2 语言模型和 SigLIP 视觉编码器训练了具有 32 亿参数的 MC-LLaVA 模型。该模型在各种不同分辨率的图像上进行了训练**，这意味着**提取的特征数量（K）是动态的**。该模型不仅支持任意数量的裁剪（M），还支持任意数量的提取标记（N)。

因此在推理时候有两个可调整的参数，可以使模型发挥最佳性能。作者在推理时候尝试了不同的 M 和 N。**当裁剪的块越多，并且保留的 token 越多情况下，模型就可以回复出非常小物体的物体。**

![](/images/collections/0.raw/zhihu/LLM%2526SD/asset/img_300062d7e9c1.jpg)
