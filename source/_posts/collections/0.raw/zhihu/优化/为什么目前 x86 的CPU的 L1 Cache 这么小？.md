这个问题已经被很多人回答很多遍了，我这里从索引的角度从逻辑上推导一下 L1 Cache Size 的问题。由于我并不清楚你对体系结构以及当今主流微架构的了解程度，我只能点到为止，希望你看了我的回答会有更多的疑惑。

一个最显著的问题是如何将大容量的内存映射到小尺寸的缓存上，这涉及到我们如何处理内存地址（程序访问的是虚拟内存，而内存访问需要物理地址），以及如何提高缓存的利用率。与此同时，我们还需考虑索引对于性能的影响。

上面短短的一小段内容，隐含了：

## 1.  page size是建立索引的关键（页表的单位，一个物理页和虚拟页共享偏移的尺寸）


## 2. 简单的缓存映射电路（还有什么比 mod 更简单呢？）


## 3. 并由1我们知道还需进一步比较偏移量以命中缓存行，我们需要这个比较尽可能并行，否则无法满足时钟周期的需求。这个并行度由 2 中的映射关系决定，每次映射后候选缓存位置越多，所需要的并行度越高，能耗也越大（在保证延迟不变的前提下）


## 4. 由 1，2 我们还可以发现，page size 和映射关系共同决定了缓存大小


更进一步的，再理解上述内容后，可以尝试回答：

## 1. 而 Intel 在将 32KiB 的 L1 data cache 扩容到 48KiB 的同时，访问周期多了 1cycle 又可能是为什么？


## 2.  M1 有 16KiB page size，访问周期与 Intel 上一代的 32KiB L1 均为 3cycles，它的 L1 data cache 多大，可能是为什么？


如果上面两个问题都能回答了，那么你应该是真的明白为什么 L1 cache 这么小了
