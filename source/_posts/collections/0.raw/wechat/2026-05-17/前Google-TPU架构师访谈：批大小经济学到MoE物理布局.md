当我们谈论 AI 时，我们往往关注模型的能力、参数规模和应用场景，却很少追问那些决定 AI 本质的底层问题：

- 为什么 Claude 的快速模式要贵 6 倍却只快 2.5 倍？
- 为什么 GPT-4 之后模型规模增长突然放缓？
- 为什么长上下文的价格会翻倍？
- 为什么 Ilya Sutskever 会说"流水线并行并不明智"？

为了回答这些问题，我们邀请到了前 Google TPU 架构师、现 AI 芯片初创公司 MatX CEO Reiner Pope，用一场两个多小时的黑板讲座，从第一性原理出发，拆解 Transformer 模型的计算、内存和通信本质。

通过 Reiner 的分析，你会发现：AI 的发展不仅受算法和数据的限制，更受物理世界的铁律约束。

## 一、批量大小：AI 推理成本与延迟的核心杠杆

### 1.1 为什么有"快速模式"和"慢速模式"？

几乎所有主流 AI 服务商都提供了不同速度的服务选项：Claude 的 Fast Mode 比普通模式贵 6 倍，速度快 2.5 倍；Cursor 的 Turbo 模式价格更高，响应更快。

很多人以为这是服务商的定价策略，但 Reiner 指出，这背后是 AI 推理最基本的物理规律：<strong>批量大小决定了成本和延迟的权衡</strong>。

"如果你不批量处理用户请求，成本会比批量处理高出 1000 倍，" Reiner 在黑板上写下第一个公式，"这就是为什么你可以花钱买速度，也可以花时间省钱。"

为了解释这一点，Reiner 引入了两个核心分析工具：屋顶线模型和 Transformer 推理的两个时间组成部分——权重操作时间和上下文操作时间。

### 1.2 屋顶线模型：计算与内存的永恒博弈

屋顶线模型是分析计算机系统性能的经典方法，它考虑两个核心资源：

- <strong>计算能力</strong>（FLOPS，每秒浮点运算次数）
- <strong>内存带宽</strong>（每秒能从内存读取多少字节）

对于 Transformer 推理来说，时间主要由两部分组成：

<strong>计算时间</strong>：执行权重矩阵乘法的时间，与批量大小成正比

<strong>内存时间</strong>：从内存读取权重和 KV 缓存的时间，由固定的权重读取时间和与批量大小成正比的 KV 缓存读取时间组成

```
计算时间 = (批量大小 × 活跃参数数量) / 硬件计算吞吐量
内存时间 = (总参数数量 / 内存带宽) + (批量大小 × 上下文长度 × 每token字节数 / 内存带宽)
总时间 = max(计算时间, 内存时间)
```

Reiner 特别解释了 KV 缓存的概念：在自回归推理中，模型每次生成一个新 token 时，都需要关注之前所有 token 的内部表示。为了避免重复计算，这些表示会被缓存起来，称为 KV 缓存。KV 缓存的大小与批量大小和上下文长度成正比，是长上下文推理的主要内存开销。

### 1.3 成本曲线的秘密：批量越大越便宜

如果我们把时间除以批量大小，得到每 token 的成本，就会看到一个非常有趣的曲线：

- 当批量很小时，权重读取时间占主导，每 token 成本极高，几乎与批量大小成反比
- 当批量增大到一定程度，权重读取时间被分摊，KV 缓存读取时间和计算时间开始占主导
- 当批量足够大时，计算时间成为瓶颈，每 token 成本趋于稳定，达到理论最小值

"这就是为什么批量处理如此重要，" Reiner 指着曲线的最低点说，"在批量大小为 1 时，你需要为每个 token 支付读取整个模型权重的成本；而在批量大小为 2000 时，这个成本被分摊到了 2000 个 token 上，几乎可以忽略不计。"

这也解释了为什么"慢速模式"的降价空间有限：KV 缓存是每个用户独有的，无法像权重那样被批量分摊。

### 1.4 最优批量大小的推导：300× 稀疏度法则

那么，多大的批量大小才能达到最优效率？Reiner 给出了一个惊人简单的公式：

<strong>最优批量大小 ≈ 300 × 稀疏度</strong>

其中，稀疏度是总参数数量与活跃参数数量的比值。例如，DeepSeek V3 有 7000 亿总参数和 370 亿活跃参数，稀疏度约为 19，那么最优批量大小约为 5700。

"这个 300 是一个硬件常数，" Reiner 解释道，"它是 GPU 的计算吞吐量与内存带宽的比值，单位是每字节的 FLOPs。从 A100 到 H100 再到 B100，这个比值一直保持在 300 左右，非常稳定。"

在实际部署中，服务商通常会选择比最优批量大 2-3 倍的批量，以留出一定的余量。这意味着，一个典型的前沿模型会以每 20 毫秒一个批次的速度运行，每个批次包含约 2000 个序列。

## 二、MoE 模型的物理布局：一个机架就是一个专家层

### 2.1 专家并行：把不同专家放在不同 GPU 上

随着混合专家（MoE）模型的兴起，如何在 GPU 集群上高效部署 MoE 成为了一个关键问题。MoE 模型由多个专家组成，每个 token 只会被路由到少数几个专家进行处理。

"部署 MoE 的最佳方式是专家并行，也就是把不同的专家放在不同的 GPU 上。"

例如，DeepSeek V3 有 256 个专家，如果部署在一个有 72 个 GPU 的 Blackwell 机架上，我们可以使用其中的 64 个 GPU，每个 GPU 放 4 个专家。

### 2.2 全对全通信：MoE 的甜蜜点与瓶颈

专家并行的通信模式是全对全（all-to-all）通信：每个 GPU 都可能向其他任何 GPU 发送 token，也可能从其他任何 GPU 接收 token。

"这是一种非常特殊的通信模式，它要求所有 GPU 之间都有高速、平等的连接。"

幸运的是，现代 GPU 机架的设计正好满足了这一需求。在 Nvidia 的 Blackwell 机架中，所有 72 个 GPU 都通过 NVSwitch 连接在一起，任何两个 GPU 之间的通信只需要两跳，带宽相同。

"一个 Blackwell 机架就是为 MoE 量身定制的，" Reiner 说，"它的全对全通信带宽正好匹配 MoE 的需求。"

然而，当我们试图把 MoE 层扩展到多个机架时，问题就出现了。机架之间的通信带宽通常比机架内部低 8 倍左右。
