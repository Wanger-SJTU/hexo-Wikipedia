## 一、批量大小：AI 推理成本与延迟的核心杠杆

### 1.1 为什么有"快速模式"和"慢速模式"？

几乎所有主流 AI 服务商都提供了不同速度的服务选项：Claude 的 Fast Mode 比普通模式贵 6 倍，速度快 2.5 倍；Cursor 的 Turbo 模式价格更高，响应更快。

很多人以为这是服务商的定价策略，但 Reiner 指出，这背后是 AI 推理最基本的物理规律：**批量大小决定了成本和延迟的权衡**。

> "如果你不批量处理用户请求，成本会比批量处理高出 1000 倍，"Reiner 在黑板上写下第一个公式，"这就是为什么你可以花钱买速度，也可以花时间省钱。"

为了解释这一点，Reiner 引入了两个核心分析工具：屋顶线模型和 Transformer 推理的两个时间组成部分——权重操作时间和上下文操作时间。

### 1.2 屋顶线模型：计算与内存的永恒博弈

屋顶线模型是分析计算机系统性能的经典方法，它考虑两个核心资源：计算能力（FLOPS，每秒浮点运算次数）和内存带宽（每秒能从内存读取多少字节）。任何程序的性能都不会超过这两个资源中的瓶颈。

对于 Transformer 推理来说，时间主要由两部分组成：

**计算时间**：执行权重矩阵乘法的时间，与批量大小成正比

**内存时间**：从内存读取权重和 KV 缓存的时间，由固定的权重读取时间和与批量大小成正比的 KV 缓存读取时间组成

```
计算时间 = (批量大小 × 活跃参数数量) / 硬件计算吞吐量
内存时间 = (总参数数量 / 内存带宽) + (批量大小 × 上下文长度 × 每token字节数 / 内存带宽)
总时间 = max(计算时间, 内存时间)
```

Reiner 特别解释了 KV 缓存的概念：在自回归推理中，模型每次生成一个新 token 时，都需要关注之前所有 token 的内部表示。为了避免重复计算，这些表示会被缓存起来，称为 KV 缓存。KV 缓存的大小与批量大小和上下文长度成正比，是长上下文推理的主要内存开销。

### 1.3 成本曲线的秘密：批量越大越便宜

如果我们把时间除以批量大小，得到每 token 的成本，就会看到一个非常有趣的曲线：

- 当批量很小时，权重读取时间占主导，每 token 成本极高，几乎与批量大小成反比
- 当批量增大到一定程度，权重读取时间被分摊，KV 缓存读取时间和计算时间开始占主导
- 当批量足够大时，计算时间成为瓶颈，每 token 成本趋于稳定，达到理论最小值

> "这就是为什么批量处理如此重要，"Reiner 指着曲线的最低点说，"在批量大小为 1 时，你需要为每个 token 支付读取整个模型权重的成本；而在批量大小为 2000 时，这个成本被分摊到了 2000 个 token 上，几乎可以忽略不计。"

这也解释了为什么"慢速模式"的降价空间有限：KV 缓存是每个用户独有的，无法像权重那样被批量分摊。即使你愿意等更长时间，也无法显著降低 KV 缓存的成本。

### 1.4 最优批量大小的推导：300× 稀疏度法则

那么多大的批量大小才能达到最优效率？Reiner 给出了一个惊人简单的公式：

```
最优批量大小 ≈ 300 × 稀疏度
```

其中，稀疏度是总参数数量与活跃参数数量的比值。例如，DeepSeek V3 有 7000 亿总参数和 370 亿活跃参数，稀疏度约为 19，那么最优批量大小约为 5700。

> "这个 300 是一个硬件常数，"Reiner 解释道，"它是 GPU 的计算吞吐量与内存带宽的比值，单位是每字节的 FLOPs。从 A100 到 H100 再到 B100，这个比值一直保持在 300 左右，非常稳定。"

这意味着，对于任何模型和任何硬件，最优批量大小只与稀疏度有关，与模型规模无关。这是一个非常强大的结论，它解释了为什么即使是最大的模型，最优批量大小也只有几千。

在实际部署中，服务商通常会选择比最优批量大 2-3 倍的批量，以留出一定的余量。这意味着，一个典型的前沿模型会以每 20 毫秒一个批次的速度运行，每个批次包含约 2000 个序列。

> "你可以把这想象成一列火车，每 20 分钟发一班，"Reiner 打了个比方，"不管有没有坐满，火车都会准时发车。如果你的请求刚好在火车发车后到达，你需要等下一班，这就是排队延迟的来源。"

## 二、MoE 模型的物理布局：一个机架就是一个专家层

### 2.1 专家并行：把不同专家放在不同 GPU 上

随着混合专家（MoE）模型的兴起，如何在 GPU 集群上高效部署 MoE 成为了一个关键问题。MoE 模型由多个专家组成，每个 token 只会被路由到少数几个专家进行处理。

Reiner 在黑板上画出了一个典型的 MoE 层结构：输入 token 经过路由器，被分配到不同的专家，每个专家是一个独立的 MLP，处理完后再将结果汇总。

> "部署 MoE 的最佳方式是专家并行，"Reiner 指出，"也就是把不同的专家放在不同的 GPU 上。"

例如，DeepSeek V3 有 256 个专家，如果部署在一个有 72 个 GPU 的 Blackwell 机架上，我们可以使用其中的 64 个 GPU，每个 GPU 放 4 个专家。这样，当 token 被路由到某个专家时，只需要与对应的 GPU 通信。

### 2.2 全对全通信：MoE 的甜蜜点与瓶颈

专家并行的通信模式是全对全（all-to-all）通信：每个 GPU 都可能向其他任何 GPU 发送 token，也可能从其他任何 GPU 接收 token。

> "这是一种非常特殊的通信模式，"Reiner 强调，"它要求所有 GPU 之间都有高速、平等的连接。"

幸运的是，现代 GPU 机架的设计正好满足了这一需求。在 Nvidia 的 Blackwell 机架中，所有 72 个 GPU 都通过 NVSwitch 连接在一起，任何两个 GPU 之间的通信只需要两跳，带宽相同。

> "一个 Blackwell 机架就是为 MoE 量身定制的，"Reiner 说，"它的全对全通信带宽正好匹配 MoE 的需求。"

然而，当我们试图把 MoE 层扩展到多个机架时，问题就出现了。机架之间的通信带宽通常比机架内部低 8 倍左右。如果一个 MoE 层分布在两个机架上，那么平均有一半的 token 需要跨机架通信，这会成为严重的瓶颈。

### 2.3 为什么一个机架是 MoE 的天然边界？

> "这就是为什么一个机架是 MoE 层的天然边界，"Reiner 得出结论，"你几乎不会看到一个 MoE 层分布在多个机架上。"

这一结论对 AI 模型的规模有着深远的影响。一个 MoE 层的总参数数量不能超过一个机架的内存容量。对于 Blackwell 机架来说，这大约是 20TB，对应约 10 万亿参数（假设使用 FP4 精度）。

这也解释了为什么 Google 的 Gemini 模型在早期能够领先：Google 的 TPU 集群很早就拥有了非常大的 scale-up 域（单个通信域内的芯片数量），能够支持更大的 MoE 层。

### 2.4 线缆密度：被物理世界限制的 AI 规模

那么，为什么我们不把更多的 GPU 放在一个机架里，或者建造更大的 scale-up 域呢？Reiner 给出了一个令人惊讶的答案：**物理空间和线缆密度**。

> "现代机架已经被推到了物理极限，"Reiner 解释道，"你需要在有限的空间里塞进尽可能多的 GPU、电源、冷却系统和线缆。而线缆的密度是最大的瓶颈之一。"

每个 GPU 需要大量的高速线缆连接到交换机。当你增加 GPU 数量时，线缆数量会呈平方级增长。这些线缆不仅占用空间，还有最小弯曲半径的要求，不能随意弯折。

> "从 Hopper 的 8 个 GPU 到 Blackwell 的 72 个 GPU，主要是产品形态的变化，从托盘式变成了机架式，"Reiner 说，"而即将到来的 Rubin 架构将 scale-up 域扩展到 500 多个 GPU，这需要在机架设计上取得重大突破，解决线缆密度、供电和冷却的问题。"

## 三、流水线并行：Ilya 为什么说"这不明智"？

### 3.1 流水线并行的基本原理：把层放在不同机架

既然 MoE 层不能跨机架，那么我们如何部署比一个机架内存还大的模型？传统的答案是流水线并行（Pipeline Parallelism）：把模型的不同层放在不同的机架上，通过高速网络连接。

Reiner 画出了一个典型的流水线并行示意图：输入数据首先在机架 1 上处理第 1-10 层，然后在机架 2 上处理第 11-20 层，以此类推。这种方式可以在有限的内存下处理非常大的模型。

### 3.2 训练 vs 推理：流水线的不同命运

流水线并行在训练中表现优异，因为训练时批量大、计算密度高，可以充分填充流水线，使得各阶段的 GPU 都能保持高利用率。

> "在训练中，梯度累积的批量可以非常大，足以填满整个流水线，"Reiner 解释道，"这就是为什么流水线并行一直是训练的主流方案。"

但在推理中，情况完全不同。推理时的批量通常只有几千甚至更小，无法充分填充流水线。这会导致 GPU 利用率低下，性能不佳。

### 3.3 致命陷阱：KV 缓存无法被流水线分摊

流水线的核心问题是：它只能分摊计算和权重存储，而无法分摊 KV 缓存。

在推理过程中，KV 缓存需要被所有处理同一序列的流水线阶段访问。当一个序列的第一个 token 进入流水线时，它会产生 KV 缓存；这些缓存需要被后续所有处理该序列的阶段使用。

> "在流水线并行中，每个阶段都需要存储自己处理过的序列的 KV 缓存，"Reiner 指出，"这些缓存无法被分摊，因为每个阶段都需要随时访问自己负责的部分。"

当 KV 缓存成为内存瓶颈时，增加更多的流水线阶段不仅无法提升性能，反而会增加额外的通信和同步开销。

### 3.4 规模的真相：带宽比容量更重要

Reiner 认为，AI 基础设施的设计应该更加重视通信带宽而非存储容量。

> "很多人关注 GPU 的 HBM 容量，但真正限制 AI 系统性能的是带宽，"Reiner 说，"带宽决定了你能多快地传输数据，而容量只是决定了你能存多少数据。"

他认为，未来 AI 硬件的竞争将在带宽维度展开，而非容量维度。这与当前行业的关注点有些不匹配——大多数人在讨论 GPU 时，首先提到的是显存大小，而非带宽。

## 四、RL 的颠覆：模型可能被过度训练 100 倍

### 4.1 Chinchilla 缩放定律的局限性

Chinchilla 缩放定律指出，对于给定的训练预算，应该使用与模型大小成正比的数据量进行训练，以达到最优的性能。这一结论在过去几年被广泛采用，指导了许多大模型的训练策略。

但 Reiner 指出，Chinchilla 定律只考虑了训练阶段，没有考虑推理成本和 RL（强化学习）成本。在实际的前沿模型训练中，这两者占据了大量预算。

### 4.2 总成本最小化：训练、RL、推理的三分天下

在真实的前沿模型部署中，总成本由三部分组成：

- **训练成本**：训练基础模型的成本
- **RL 成本**：使用强化学习微调模型的成本
- **推理成本**：部署模型进行推理的成本

> "当你把这三个成本放在一起考虑时，最优的训练数据量会大大超过 Chinchilla 最优，"Reiner 解释道，"因为更多的训练数据可以降低推理成本和 RL 成本，从而降低总成本。"

### 4.3 第一性原理推导：100 倍过度训练的由来

Reiner 进行了详细的第一性原理推导：

假设我们用总预算 B 来训练一个模型。传统 Chinchilla 策略会使用 0.5B 进行训练，0.5B 用于收集训练数据，得到的模型需要进行大量的 RL 和推理。

但如果我们增加训练数据量到 50B token（假设模型规模不变），训练成本会增加到 0.75B，但推理和 RL 成本会显著降低，因为模型更强大，需要的推理次数和 RL 迭代更少。

最终，总成本会降低约 40%，而模型性能会更高。

> "这就是为什么前沿模型实际上被过度训练了 100 倍，"Reiner 说，"这不是浪费，而是最小化总成本的理性选择。"

### 4.4 这对 AI 未来意味着什么？

这一发现对 AI 未来发展有重要启示：

1. **训练数据的重要性被低估**：在同等算力下，使用更多、更高质量的训练数据训练更小的模型，可能比使用更少数据训练更大的模型更经济。

2. **模型规模增长会放缓**：随着训练数据量的增加，最优模型规模会继续增长，但增长速度会放缓，因为数据收集的难度在增加。

3. **RL 和推理将成为主要成本**：随着模型能力的提升，RL 和推理成本将占据越来越大的比例，成为决定模型设计的关键因素。

## 五、从 API 价格反推：长上下文的真实成本

### 5.1 Gemini 定价泄露的秘密：200K 是成本拐点

从 API 定价可以反推出大模型的成本结构。Gemini 的定价显示，200K 是一个重要的拐点：超过 200K token 的上下文，价格会显著上升。

这背后的原因是什么？Reiner 指出，当上下文超过 200K 时，KV 缓存的内存消耗会成为主要成本，而计算时间相对较小。这意味着内存带宽成为瓶颈，而非计算吞吐量。

> "200K 是当前硬件条件下的成本拐点，"Reiner 说，"超过这个长度，每增加 1K token 的成本会显著上升，因为内存访问的代价开始超过计算的代价。"

### 5.2 预填充 vs 解码：为什么输出比输入贵 5 倍？

在使用 LLM API 时，我们通常会发现输出的价格比输入贵 5 倍左右。这背后有两个原因：

1. **预填充（Prefill）vs 解码（Decode）**：处理输入 token（预填充）时，GPU 可以高度并行处理，因此成本相对较低。生成输出 token（解码）时，由于是自回归的，必须一个一个生成，因此 GPU 利用率较低，成本较高。

2. **KV 缓存的读写**：在解码过程中，每次生成一个 token，都需要读写 KV 缓存。这个开销与上下文长度成正比，但计算量与上下文长度无关，因此长上下文的解码成本会显著高于短上下文。

### 5.3 上下文缓存的经济学：HBM、DDR 还是机械硬盘？

对于长上下文，缓存策略至关重要。不同层次的存储介质有着不同的成本和性能：

- **HBM（高带宽内存）**：速度最快，但成本最高，约 $1/GB
- **DDR（DDR 内存）**：速度中等，成本中等，约 $0.01/GB
- **SSD（固态硬盘）**：速度较慢，成本较低，约 $0.001/GB
- **HDD（机械硬盘）**：速度最慢，成本最低，约 $0.0001/GB

对于 KV 缓存，由于需要频繁随机访问，只有 HBM 和 DDR 是可行的选择。对于长上下文的缓存，SSD 可能是一个有趣的选择，因为它可以在成本上降低 100 倍，虽然速度会慢一些。

> "上下文缓存是一个巨大的机会，"Reiner 说，"如果你能有效地缓存长上下文的一半，你可以将成本降低一半，同时几乎不影响用户体验。"

### 5.4 百万级上下文的真正障碍：内存墙

要在合理的成本下支持百万级上下文，需要解决的核心问题是内存墙。

当前的 GPU（如 H100）的内存带宽约为 3.35 TB/s。如果每次生成 token 需要读取整个 KV 缓存（假设每个 token 约 1KB KV 缓存），那么 1M 上下文的带宽需求约为 1 GB/token × 1M token = 1 TB/token，远远超出了内存带宽的能力。

> "百万级上下文在技术上是可以实现的，"Reiner 说，"但在成本上不合理。你需要 1000 倍的内存带宽才能在合理的时间内处理 1M 上下文。"

他认为，更现实的目标是 200K-1M 区间，这个区间可以通过更好的缓存策略和算法优化来实现，成本相对可控。

## 六、趋同进化：神经网络与密码学的惊人相似

### 6.1 相同的核心目标：彻底混合信息

乍一看，神经网络和密码学似乎是两个完全不同的领域：一个是 AI 的核心技术，一个用于保护信息安全。但 Reiner 在深入研究后发现了一个令人惊讶的事实：**两者在底层架构上有着惊人的相似性**。

神经网络和密码学算法都有一个核心目标：**彻底混合输入信息**。

- 神经网络通过层层线性变换（如矩阵乘法）和非线性变换（如 ReLU、GeLU）来混合信息
- 密码学算法通过轮次的线性变换（如 XOR、置换）和非线性变换（如 S-box）来混合信息

### 6.2 相同的架构模式：线性+非线性的重复堆叠

更惊人的是，两者在架构上都采用了相同的模式：**线性变换和非线性变换的重复堆叠**。

神经网络中：每一层 = 线性变换（矩阵乘法） + 非线性激活函数

密码学算法中：每一轮 = 线性混合（XOR、置换） + 非线性 S-box

> "这是趋同进化的一个经典案例，"Reiner 说，"两个独立发展的领域，在解决同一类问题时，碰巧走到了同一个解法上。"

具体来说，Transformer 中的 attention 机制类似于密码学中的 MixColumn（列混合）和 S-box（非线性变换）：

- **Attention**（线性 QKV 投影 + softmax）类似于密码学中的 MixColumn，通过矩阵运算混合不同位置的信息
- **FFN**（前馈网络）中的 GeLU/GELU 类似于密码学中的 S-box，提供非线性变换，增加信息的复杂度

在 SHA-3 哈希函数中，每个轮由 θ、ρ、π、χ 和 ι 五个步骤组成，同样是线性和非线性变换的组合。

> "更有趣的是，它们都采用了分块混合的策略，"Reiner 补充道，"先在小范围内混合，然后在更大范围内混合，这样可以在保证混合效果的同时，提高计算效率和并行性。"

### 6.3 相反的优化目标：结构提取 vs 随机化

尽管架构相似，但神经网络和密码学算法的优化目标完全相反：

- **密码学算法**的目标是最大化输出的随机性和不可预测性，防止任何形式的逆向工程
- **神经网络**的目标是从输入中提取有用的结构和模式，让输出具有可解释性和预测性

这种相反的目标导致了一些关键的设计差异：

- 神经网络使用残差连接和 LayerNorm 来保持梯度的稳定性，便于训练
- 密码学算法避免使用残差连接，因为它们会削弱混合效果，容易受到差分密码分析攻击
- 神经网络使用浮点数运算，便于梯度下降
- 密码学算法使用整数运算，避免数值精度问题

### 6.4 交叉启发：从 Feistel 密码到可逆神经网络

尽管目标不同，但两个领域之间已经出现了交叉启发。最著名的例子是 Feistel 网络在神经网络中的应用。

Feistel 网络是密码学中一种经典的可逆结构，它可以将任何非可逆函数转换为可逆函数。2017 年，研究人员将 Feistel 网络引入神经网络，提出了可逆残差网络（RevNets）。

> "RevNets 的核心思想是让整个神经网络可逆，"Reiner 解释道，"这样在训练时，你不需要存储中间激活，只需要在反向传播时重新计算它们。这可以节省大量的内存。"

虽然 RevNets 在今天的大模型训练中并不常用，但它展示了跨领域借鉴的巨大潜力。

> "我相信未来还会有更多这样的交叉创新，"Reiner 说，"密码学领域几十年的研究成果，可能会为 AI 架构的创新提供新的思路。"

## 结语

这场两个多小时的讲座，让我们看到了 AI 背后那些不为人知的底层逻辑。从批量大小的经济学到 MoE 的物理布局，从流水线并行的陷阱到 RL 对训练策略的颠覆，从 API 定价泄露的技术秘密到神经网络与密码学的趋同进化，每一个结论都来自第一性原理的推导，每一个公式都揭示了 AI 行业的本质。

Reiner 的分析告诉我们，**AI 不是魔法，它是建立在物理世界之上的工程技术**。它的发展不仅受算法和数据的限制，更受 GPU 的内存带宽、机架的线缆密度、电力和冷却等物理因素的约束。理解这些约束，才能真正理解 AI 的现在和未来。

在这个 AI 快速发展的时代，我们很容易被各种炫目的应用和惊人的参数所迷惑，却忽略了那些决定 AI 本质的底层问题。而正是这些底层问题，才是真正的技术壁垒和商业机会所在。

最后，留给大家一个开放性的问题：如果内存墙是 AI 发展的主要瓶颈，那么未来的 AI 硬件和架构会朝着什么方向发展？是继续扩大 HBM 的容量和带宽，还是探索全新的计算范式，比如存内计算或者神经形态计算？这个问题的答案，将决定下一个十年 AI 的面貌。

## 📌 核心 Takeaways

1. **批量大小是 AI 推理成本和延迟的核心杠杆**，最优批量大小约为 300× 稀疏度，与模型规模无关

2. **MoE 模型受限于全对全通信**，一个机架是 MoE 层的天然部署边界，线缆密度是限制 scale-up 域大小的主要物理因素

3. **流水线并行无法分摊 KV 缓存成本**，在 KV 缓存主导内存开销的今天，其收益非常有限，这是 Ilya 认为"流水线并行不明智"的核心原因

4. **由于 RL 和推理成本的引入**，前沿模型可能被过度训练 100 倍以上，远超 Chinchilla 最优，这是最小化总成本的理性选择

5. **长上下文的主要瓶颈是内存带宽而非计算**，200K 是当前的成本拐点，百万级上下文短期内难以普及，经济合理区间在 200K-1M
